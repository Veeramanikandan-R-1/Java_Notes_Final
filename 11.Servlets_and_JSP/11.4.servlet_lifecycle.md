## Servlet Lifecycle

Servlet lifecycle is managed by the Servlet Container (e.g., Tomcat). It defines how a servlet is created, initialized, handles requests and gets destroyed.

### Lifecycle Methods

1. Loading and Instantiation
   - Container loads the servlet class.
   - Creates a servlet object.
2. `init()`
   - Called only once during the servlet's lifecycle.
   - Used for initialization tasks.
3. `service()`
   - Called for every incoming request.
   - Processes requests and dispatches them to `doGet()`, `doPost()`, etc. in `HttpServlet`.
4. `destroy()`
   - Called once before the servlet is removed.
   - Used to release resources.

### Example

```
@WebServlet("/hello")
public class HelloServlet extends HttpServlet {

    public void init() {
        System.out.println("Servlet Initialized");
    }

    protected void doGet(
        HttpServletRequest req,
        HttpServletResponse res
    ) throws IOException {

        res.getWriter().println("Hello World");
    }

    public void destroy() {
        System.out.println("Servlet Destroyed");
    }
}
```

### Important Interview Points

| Method                 | Frequency            | Purpose             |
| ---------------------- | -------------------- | ------------------- |
| Constructor            | Once per instance    | Object creation     |
| `init()`               | Once                 | Initialization      |
| `service()`            | Every request        | Request processing  |
| `doGet()` / `doPost()` | Depending on request | Handle HTTP methods |
| `destroy()`            | Once                 | Cleanup             |

Remember:

- Servlet lifecycle is managed by the container.
- `init()` executes once.
- `service()` executes for each request.
- `destroy()` executes once before servlet removal.
- Multiple requests can be handled concurrently by the same servlet instance, so avoid unsafe shared mutable instance variables.
