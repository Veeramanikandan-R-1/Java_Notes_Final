## **JDBC vs Spring JDBC**

| JDBC                                          | Spring JDBC                                                  |
| --------------------------------------------- | ------------------------------------------------------------ |
| Java's standard API to connect to databases.  | Spring Framework's abstraction over JDBC.                    |
| Requires manual connection management.        | Automatically manages connections.                           |
| Requires manual exception handling.           | Converts SQL exceptions into Spring's `DataAccessException`. |
| More boilerplate code.                        | Less boilerplate code.                                       |
| Manually handles `ResultSet` mapping.         | Provides utilities like `RowMapper`.                         |
| Uses `DriverManager` and `PreparedStatement`. | Uses `JdbcTemplate` internally.                              |

### **Simple Example**

**1. JDBC**

```
Connection con = DriverManager.getConnection(url, user, password);
PreparedStatement ps = con.prepareStatement("SELECT * FROM users");
ResultSet rs = ps.executeQuery();
```

**2. Spring JDBC**

```
@Autowired
private JdbcTemplate jdbcTemplate;

List<User> users = jdbcTemplate.query(
    "SELECT * FROM users",
    new BeanPropertyRowMapper<>(User.class)
);
```

**Key takeaway:**

- **JDBC:** More manual coding and resource management.
- **Spring JDBC:** Simplifies database operations using `JdbcTemplate`.

**Interview point:** Spring JDBC internally uses JDBC; it reduces boilerplate code but does not replace JDBC.
