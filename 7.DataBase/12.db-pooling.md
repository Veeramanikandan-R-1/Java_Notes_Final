## Database Connection Pooling

Database Connection Pooling is a technique where we maintain a pool (collection) of reusable database connections instead of creating a new connection for every database request.

### 1. Why do we need connection pooling?

Without connection pooling:

1. Application receives a request.
2. Creates a new database connection.
3. Executes the SQL query.
4. Closes the connection.
5. Repeats the same process for every request.

Creating connections repeatedly consumes time and resources.

With connection pooling:

1. Application starts and creates a pool of database connections.
2. Application requests a connection from the pool.
3. Executes the SQL query.
4. Returns the connection to the pool.
5. The same connection can be reused by another request.

### 3. Advantages

- Performance: Avoids repeatedly creating database connections.
- Resource management: Controls the number of active connections.
- Reusability: Reuses existing connections.
- Scalability: Handles multiple application requests efficiently.

### 4. Popular connection pooling libraries

| Library     | Description                       |
| ----------- | --------------------------------- |
| HikariCP    | Fast, lightweight connection pool |
| Apache DBCP | Apache Database Connection Pool   |
| C3P0        | JDBC connection pooling library   |

### 5. Connection pooling in Spring Boot

Spring Boot uses HikariCP by default when using JDBC or JPA starters, unless another pool is configured.

Example `application.properties`:

```
spring.datasource.url=jdbc:mysql://localhost:3306/product_db
spring.datasource.username=root
spring.datasource.password=password

# Connection Pool Configuration
spring.datasource.hikari.maximum-pool-size=10
spring.datasource.hikari.minimum-idle=5
spring.datasource.hikari.connection-timeout=30000
```

| Property           | Meaning                                              |
| ------------------ | ---------------------------------------------------- |
| maximum-pool-size  | Maximum number of connections                        |
| minimum-idle       | Minimum number of idle connections                   |
| connection-timeout | Maximum time to wait for a connection (milliseconds) |

### 6. Interview question

Q: What happens when all connections in the pool are occupied?

The application waits for a connection to become available. If the configured connection timeout expires, it throws a connection acquisition timeout exception.

In short: Connection pooling improves database performance by reusing connections instead of creating a new database connection for every request.
