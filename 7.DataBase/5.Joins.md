# Database Joins — Inner, Left, Right + Exercises

Since you already know React and are moving toward **Spring Boot**, SQL joins are very important. In real Spring Boot applications, you'll frequently use joins when fetching related data from MySQL.

---

## 1. What is a JOIN?

A **JOIN combines rows from two or more tables based on a related column.**

Example:

### `employees`

| id | name  | department_id |
| -: | ----- | ------------: |
|  1 | Arun  |            10 |
|  2 | Bala  |            20 |
|  3 | Kumar |            30 |
|  4 | Ravi  |          NULL |

### `departments`

| id | department_name |
| -: | --------------- |
| 10 | IT              |
| 20 | HR              |
| 40 | Finance         |

Relationship:

```text
employees.department_id
          ↓
departments.id
```

The common SQL pattern is:

```sql
SELECT columns
FROM table1
JOIN table2
ON table1.column = table2.column;
```

---

# 2. INNER JOIN

### Meaning

Returns **only matching rows from both tables**.

```sql
SELECT
    e.name,
    d.department_name
FROM employees e
INNER JOIN departments d
    ON e.department_id = d.id;
```

### Result

| name | department_name |
| ---- | --------------- |
| Arun | IT              |
| Bala | HR              |

Why?

```text
Arun  → 10 → IT     ✅
Bala  → 20 → HR     ✅
Kumar → 30 → ???    ❌
Ravi  → NULL         ❌
```

And:

```text
Finance → 40
```

has no employee, so it is also excluded.

### Remember

> **INNER JOIN = only matching records**

This is the most commonly used join.

---

# 3. LEFT JOIN

### Meaning

Returns:

> **All rows from the LEFT table + matching rows from the RIGHT table.**

```sql
SELECT
    e.name,
    d.department_name
FROM employees e
LEFT JOIN departments d
    ON e.department_id = d.id;
```

### Result

| name  | department_name |
| ----- | --------------- |
| Arun  | IT              |
| Bala  | HR              |
| Kumar | NULL            |
| Ravi  | NULL            |

Notice:

```text
employees = LEFT table
departments = RIGHT table
```

Every employee appears, even if there is no matching department.

### Remember

> **LEFT JOIN = keep everything from left table**

---

# 4. RIGHT JOIN

### Meaning

Returns:

> **All rows from the RIGHT table + matching rows from the LEFT table.**

```sql
SELECT
    e.name,
    d.department_name
FROM employees e
RIGHT JOIN departments d
    ON e.department_id = d.id;
```

### Result

| name | department_name |
| ---- | --------------- |
| Arun | IT              |
| Bala | HR              |
| NULL | Finance         |

Why?

Finance exists in `departments`, but no employee belongs to department `40`.

So:

```text
departments = RIGHT table
```

is completely preserved.

### Remember

> **RIGHT JOIN = keep everything from right table**

---

# 5. Easy Visual Memory

Think of:

```text
employees                 departments

   LEFT                       RIGHT
┌──────────┐               ┌──────────┐
│          │               │          │
│    A     │──── MATCH ────│    B     │
│          │               │          │
└──────────┘               └──────────┘
```

| JOIN       | Keeps                     |
| ---------- | ------------------------- |
| INNER JOIN | Matching rows only        |
| LEFT JOIN  | All LEFT + matching RIGHT |
| RIGHT JOIN | All RIGHT + matching LEFT |

# 6. LEFT JOIN vs INNER JOIN

This is very important for interviews.

Suppose:

```text
employees
1 Arun   10
2 Bala   20
3 Kumar  30
```

and:

```text
departments
10 IT
20 HR
```

### INNER JOIN

```sql
SELECT *
FROM employees e
INNER JOIN departments d
ON e.department_id = d.id;
```

Result:

```text
Arun   IT
Bala   HR
```

Kumar disappears.

### LEFT JOIN

```sql
SELECT *
FROM employees e
LEFT JOIN departments d
ON e.department_id = d.id;
```

Result:

```text
Arun   IT
Bala   HR
Kumar  NULL
```

# 7. Practical Database Setup

You can practice all of this directly in **MySQL Workbench**.

Create tables:

```sql
CREATE DATABASE join_practice;

USE join_practice;

CREATE TABLE employees (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    department_id INT
);

CREATE TABLE departments (
    id INT PRIMARY KEY,
    department_name VARCHAR(50)
);
```

Insert data:

```sql
INSERT INTO employees VALUES
(1, 'Arun', 10),
(2, 'Bala', 20),
(3, 'Kumar', 30),
(4, 'Ravi', NULL);

INSERT INTO departments VALUES
(10, 'IT'),
(20, 'HR'),
(40, 'Finance');
```

Now practice:

```sql
SELECT * FROM employees;

SELECT * FROM departments;
```

# 9. Answers

### Exercise 1

```sql
SELECT
    e.name,
    d.department_name
FROM employees e
INNER JOIN departments d
    ON e.department_id = d.id;
```

### Exercise 2

```sql
SELECT
    e.name,
    d.department_name
FROM employees e
LEFT JOIN departments d
    ON e.department_id = d.id;
```

### Exercise 3

```sql
SELECT
    e.name,
    d.department_name
FROM employees e
RIGHT JOIN departments d
    ON e.department_id = d.id;
```

### Exercise 4

```sql
SELECT
    e.name
FROM employees e
LEFT JOIN departments d
    ON e.department_id = d.id
WHERE d.id IS NULL;
```

### Exercise 5

```sql
SELECT
    d.department_name
FROM departments d
LEFT JOIN employees e
    ON e.department_id = d.id
WHERE e.id IS NULL;
```

### Exercise 6

```sql
SELECT
    d.department_name,
    COUNT(e.id) AS employee_count
FROM departments d
LEFT JOIN employees e
    ON e.department_id = d.id
GROUP BY d.id, d.department_name;
```

Result:

```text
IT        1
HR        1
Finance   0
```

## 10. Very Important Interview Point

These two are **not equivalent**:

### Query A

```sql
SELECT *
FROM employees e
LEFT JOIN departments d
ON e.department_id = d.id
WHERE d.department_name = 'IT';
```

The `WHERE` condition removes the `NULL` rows, effectively making this behave like an inner join for that condition.

### Query B

```sql
SELECT *
FROM employees e
LEFT JOIN departments d
ON e.department_id = d.id
AND d.department_name = 'IT';
```

Here the `LEFT JOIN` behavior is preserved, so **all employees remain**; non-IT matches become `NULL`.

This distinction is frequently asked in SQL interviews.

# 11. How JOINs fit into Spring Boot

Later, when you learn Spring Data JPA, the same relationship might look like:

```text
Employee
   |
   | department_id
   ↓
Department
```

And you may write JPQL such as:

```java
@Query("""
    SELECT e
    FROM Employee e
    JOIN e.department d
    WHERE d.departmentName = :name
""")
List<Employee> findByDepartment(String name);
```

So learning SQL JOINs now will make **JPA/Hibernate much easier**.

### What you should master from this topic

```text
JOIN
 ├── INNER JOIN       → matching only
 ├── LEFT JOIN        → all left
 ├── RIGHT JOIN       → all right
 ├── ON               → defines relationship
 ├── WHERE            → filters result
 ├── IS NULL          → find unmatched rows
 └── GROUP BY + JOIN  → aggregation
```

**Next SQL topic I recommend:** `GROUP BY + HAVING + Aggregate Functions (COUNT, SUM, AVG, MIN, MAX)` because they combine very naturally with JOINs and are heavily used in interviews.
