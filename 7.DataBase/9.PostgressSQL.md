## PostgreSQL — Setup and Usage + Database Project

Since your goal is **Java + Spring Boot**, learn PostgreSQL from the perspective of how a Spring Boot application will actually use it.

---

Q. we already have mysql then why postgress?

Yes — you mean **why PostgreSQL exists when MySQL already does the same basic job, and what PostgreSQL gives you that MySQL doesn't**.

Think of them as **two different RDBMS products solving the same core problem**, but with different design philosophies and strengths.

## MySQL vs PostgreSQL

| Feature            | MySQL                     | PostgreSQL                        |
| ------------------ | ------------------------- | --------------------------------- |
| Type               | RDBMS                     | Object-relational DBMS            |
| Basic CRUD         | ✅                         | ✅                                 |
| Joins              | ✅                         | ✅                                 |
| Transactions       | ✅                         | ✅                                 |
| ACID               | ✅                         | ✅                                 |
| Foreign keys       | ✅                         | ✅                                 |
| Indexes            | ✅                         | ✅                                 |
| JSON               | ✅                         | ✅                                 |
| Advanced SQL       | Good                      | **Very strong**                   |
| Complex queries    | Good                      | **Excellent**                     |
| Extensibility      | Moderate                  | **Excellent**                     |
| Custom data types  | Limited                   | **Strong support**                |
| JSON querying      | Good                      | **Excellent with JSONB**          |
| Arrays             | Limited                   | **Native array support**          |
| `RETURNING`        | Limited/version-dependent | **Excellent**                     |
| GIS                | Via extensions            | **PostGIS is extremely powerful** |
| Replication        | ✅                         | ✅                                 |
| Typical reputation | Simple, fast, widely used | Feature-rich, standards-oriented  |

# 1. PostgreSQL has more advanced SQL capabilities

Both can do:

```sql
SELECT *
FROM employees
WHERE salary > 50000;
```

But PostgreSQL provides many advanced SQL capabilities that are very useful for complex applications.

For example:

```sql
SELECT department_id, AVG(salary)
FROM employees
GROUP BY department_id
HAVING AVG(salary) > 50000;
```

Both databases can handle this, but PostgreSQL generally provides a broader set of advanced SQL features.

---

# 2. PostgreSQL has `JSONB`

This is one of its major advantages.

Suppose an employee has flexible metadata:

```json
{
  "skills": ["Java", "React"],
  "experience": 5,
  "remote": true
}
```

PostgreSQL can store this as:

```sql
metadata JSONB
```

And query inside it:

```sql
SELECT *
FROM employees
WHERE metadata->>'experience' = '5';
```

You can also index `JSONB`, making JSON queries much more practical at scale.

MySQL also supports JSON, but PostgreSQL's `JSONB` functionality is particularly powerful.

---

# 3. PostgreSQL supports arrays natively

For example:

```sql
CREATE TABLE employees (
    id BIGSERIAL PRIMARY KEY,
    name VARCHAR(100),
    skills TEXT[]
);
```

Insert:

```sql
INSERT INTO employees(name, skills)
VALUES (
    'John',
    ARRAY['Java', 'Spring Boot', 'React']
);
```

Query:

```sql
SELECT *
FROM employees
WHERE 'Java' = ANY(skills);
```

This kind of native data type support is a PostgreSQL strength.

---

# 4. PostgreSQL has very strong extensibility

This is a major architectural difference.

PostgreSQL allows you to extend the database with:

* Custom data types
* Custom functions
* Custom operators
* Extensions
* Custom indexes

For example:

### PostGIS

PostGIS adds powerful geospatial capabilities to PostgreSQL.

That makes PostgreSQL useful for applications involving:

```text
Maps
Locations
Distances
Geographic data
Delivery tracking
Ride-sharing
```

---

# 5. PostgreSQL has `RETURNING`

Very useful for backend development.

Suppose:

```sql
INSERT INTO employees(name, email)
VALUES ('John', 'john@gmail.com')
RETURNING id;
```

PostgreSQL can immediately return:

```text
id
---
101
```

Similarly:

```sql
UPDATE employees
SET salary = 70000
WHERE id = 101
RETURNING *;
```

This can be convenient when building APIs.

---

# 6. PostgreSQL is very strong for complex queries

For example, applications involving:

```text
Reporting
Analytics
Financial systems
Complex business logic
Large relational datasets
```

often benefit from PostgreSQL's extensive SQL functionality.

Features include:

* Window functions
* Common Table Expressions (CTEs)
* Recursive queries
* Advanced aggregation
* `LATERAL` queries
* Materialized views
* Powerful indexing options

Some of these exist in modern MySQL too, so it's not accurate to say PostgreSQL "can do them and MySQL can't." The difference is often **depth, breadth, implementation, and ecosystem**.

---

# 7. MySQL's advantages

MySQL isn't inferior. It has its own strengths.

### Simplicity

MySQL is often straightforward to learn and operate.

### Huge adoption

It's extremely common in:

```text
Web applications
PHP applications
WordPress
E-commerce
Traditional CRUD applications
```

### Performance

MySQL can perform extremely well for many read-heavy and conventional web workloads.

### Ecosystem

It has a huge community and extensive tooling.

---

# 8. Simple way to remember

Think:

```text
MySQL
   ↓
Simple + popular + excellent general-purpose web DB

PostgreSQL
   ↓
Feature-rich + advanced SQL + highly extensible
```

But **don't interpret this as "PostgreSQL is always better."**

The correct engineering answer is:

> **Choose the database based on the application's requirements, workload, ecosystem, operational needs, and team's experience.**

You don't need to learn both deeply right now.

```text

                    |

                    |

                    |
          ┌─────────┴─────────┐
          ↓                   ↓
```

Your Java/Spring code can work with either.

### 1. What is PostgreSQL?

PostgreSQL is a **relational database management system (RDBMS)**, similar to MySQL.

You will use it to:

* Store application data
* Create tables and relationships
* Run SQL queries
* Handle transactions
* Enforce constraints
* Connect your Spring Boot application to the database

Conceptually:

```text
React UI
   ↓
Spring Boot REST API
   ↓
PostgreSQL
   ↓
Tables / Data
```

# 5. Create a Table

Let's create an employee table.

```sql
CREATE TABLE employees (
    id BIGSERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(150) UNIQUE NOT NULL,
    salary NUMERIC(10,2),
    joining_date DATE
);
```

Important PostgreSQL types:

| Type            | Example           |
| --------------- | ----------------- |
| `INTEGER`       | `100`             |
| `BIGINT`        | large integer     |
| `VARCHAR(100)`  | `"John"`          |
| `TEXT`          | long text         |
| `BOOLEAN`       | `TRUE/FALSE`      |
| `DATE`          | `2026-09-24`      |
| `TIMESTAMP`     | date + time       |
| `NUMERIC(10,2)` | `25000.50`        |
| `JSONB`         | JSON data         |
| `UUID`          | unique identifier |

# 6. Insert Data

```sql
INSERT INTO employees
(name, email, salary, joining_date)
VALUES
('John', 'john@gmail.com', 50000.00, '2026-09-24'),
('David', 'david@gmail.com', 60000.00, '2026-09-20');
```

Notice that `id` isn't provided.

Because:

```sql
id BIGSERIAL PRIMARY KEY
```

PostgreSQL automatically generates it.

# 8. Update

```sql
UPDATE employees
SET salary = 55000
WHERE id = 1;
```

**Always be careful with `UPDATE` without `WHERE`.**

This:

```sql
UPDATE employees
SET salary = 55000;
```

updates **every employee**.

---

# 9. Delete

```sql
DELETE FROM employees
WHERE id = 2;
```

Again, this is dangerous:

```sql
DELETE FROM employees;
```

It deletes all rows.

# 10. PostgreSQL Database Project

For Spring Boot practice, don't just create random tables.

Build a small **Employee Management Database**.

### Database

```text
employee_db
```

### Tables

```text
departments
    ↓
employees
    ↓
projects
```

For example:

```sql
CREATE TABLE departments (
    id BIGSERIAL PRIMARY KEY,
    name VARCHAR(100) UNIQUE NOT NULL
);
```

```sql
CREATE TABLE employees (
    id BIGSERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(150) UNIQUE NOT NULL,
    salary NUMERIC(10,2),
    department_id BIGINT,
    
    CONSTRAINT fk_employee_department
        FOREIGN KEY (department_id)
        REFERENCES departments(id)
);
```

Insert departments:

```sql
INSERT INTO departments (name)
VALUES
('Engineering'),
('HR'),
('Finance');
```

Insert employees:

```sql
INSERT INTO employees
(name, email, salary, department_id)
VALUES
('John', 'john@gmail.com', 70000, 1),
('David', 'david@gmail.com', 60000, 1),
('Mary', 'mary@gmail.com', 50000, 2);
```

Now you have a real relationship:

```text
departments
     1
     |
     | 
     N
employees
```

Meaning:

**One department can have many employees.**

# 13. Important: PostgreSQL vs MySQL

Since you've already practiced MySQL, don't relearn SQL from zero.

The fundamentals are mostly the same:

```sql
CREATE DATABASE
CREATE TABLE
INSERT
SELECT
UPDATE
DELETE
JOIN
GROUP BY
ORDER BY
INDEX
FOREIGN KEY
TRANSACTION
```

Focus on **PostgreSQL-specific features** as you progress:

* `BIGSERIAL` / identity columns
* `UUID`
* `JSONB`
* PostgreSQL arrays
* `ILIKE`
* `RETURNING`
* PostgreSQL-specific indexing
* `EXPLAIN ANALYZE`
* Transactions
* PostgreSQL + JPA/Hibernate

### One particularly useful PostgreSQL feature

Instead of:

```sql
INSERT INTO employees (name, email)
VALUES ('John', 'john@gmail.com');
```

You can get the generated ID immediately:

```sql
INSERT INTO employees (name, email)
VALUES ('John', 'john@gmail.com')
RETURNING id;
```

Result:

```text
id
---
4
```

This becomes useful when working with APIs and Spring Data JPA.
