## ORM (Object-Relational Mapping) – Introduction

ORM is a programming technique that maps Java objects to relational database tables.

It allows developers to perform database operations using Java objects instead of writing SQL queries manually.

### 1. Why do we need ORM?

Without ORM (using JDBC):

- Write SQL queries manually.
- Manage connections and statements.
- Convert `ResultSet` rows into Java objects.
- Handle repetitive CRUD code.

With ORM:

- Map Java classes to database tables.
- Map Java objects to table records.
- Perform CRUD operations using Java methods.
- Reduce boilerplate JDBC code.

### 2. Example – JDBC vs ORM

Without ORM (JDBC):

```
String sql = "SELECT * FROM students";

PreparedStatement ps = con.prepareStatement(sql);

ResultSet rs = ps.executeQuery();

while (rs.next()) {
    Student student = new Student(
        rs.getInt("id"),
        rs.getString("name")
    );
}
```

With ORM (using Hibernate):

```
Student student = session.find(Student.class, 1);
```

Hibernate automatically generates and executes the required SQL query.

### 3. How ORM works

| Java      | Database    |
| --------- | ----------- |
| Class     | Table       |
| Object    | Row         |
| Field     | Column      |
| Object ID | Primary Key |

Example:

Java class:

```
class Student {
    int id;
    String name;
    String email;
}
```

Database table:

```
students
-----------------
id
name
email
```

| OpenJPA     | JPA implementation         |

### 5. ORM vs JPA vs Hibernate

- ORM: Concept of mapping Java objects to relational database tables.
- JPA: Java specification that defines ORM standards and APIs.
- Hibernate: Framework that implements JPA and provides ORM functionality.

Remember: JDBC requires us to handle SQL and object mapping manually. ORM simplifies database operations by mapping Java objects to database tables.

In Spring Boot, we commonly use Spring Data JPA + Hibernate to interact with databases without writing repetitive JDBC code.
