# Database Keys — SQL / MySQL

For Spring Boot, you need to understand **keys very clearly**, because they directly map to **JPA entity relationships** such as `@Id`, `@OneToMany`, `@ManyToOne`, etc.

---

## 1. What is a Key?

A **key** is a column or combination of columns used to:

* Uniquely identify a row
* Establish relationships between tables
* Prevent duplicate/invalid data

Example:

```text
employees
+----+--------+----------------+
| id | name   | email          |
+----+--------+----------------+
| 1  | Arun   | arun@gmail.com |
| 2  | Bala   | bala@gmail.com |
+----+--------+----------------+
```

`id` can uniquely identify each employee.

---

# 2. Primary Key ⭐

A **Primary Key (PK)** uniquely identifies every row.

```sql
CREATE TABLE employees (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    email VARCHAR(100)
);
```

Rules:

* Must be **unique**
* Cannot be `NULL`
* Only **one primary key constraint** per table
* Can contain one or multiple columns

Example:

```sql
INSERT INTO employees VALUES
(1, 'Arun', 'arun@gmail.com');

INSERT INTO employees VALUES
(1, 'Bala', 'bala@gmail.com');
```

❌ Second insert fails because `id = 1` already exists.

### Spring Boot/JPA equivalent

```java
@Entity
public class Employee {

    @Id
    private Long id;

    private String name;
}
```

`@Id` represents the primary key.

---

# 3. Foreign Key ⭐

A **Foreign Key (FK)** creates a relationship between two tables.

Example:

```text
departments
+----+---------+
| id | name    |
+----+---------+
| 10 | IT      |
| 20 | HR      |
+----+---------+

employees
+----+--------+---------------+
| id | name   | department_id |
+----+--------+---------------+
| 1  | Arun   | 10            |
| 2  | Bala   | 20            |
+----+--------+---------------+
```

Here:

```text
employees.department_id
        ↓
departments.id
```

Create it:

```sql
CREATE TABLE departments (
    id INT PRIMARY KEY,
    name VARCHAR(50)
);

CREATE TABLE employees (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    department_id INT,

    FOREIGN KEY (department_id)
        REFERENCES departments(id)
);
```

Now this is invalid:

```sql
INSERT INTO employees
VALUES (3, 'Kumar', 99);
```

❌ Because department `99` doesn't exist.

### Spring Boot/JPA equivalent

Later you'll commonly see:

```java
@ManyToOne
@JoinColumn(name = "department_id")
private Department department;
```

---

# 4. UNIQUE Key

A `UNIQUE` constraint ensures that values don't repeat.

```sql
CREATE TABLE users (
    id INT PRIMARY KEY,
    username VARCHAR(50) UNIQUE,
    email VARCHAR(100) UNIQUE
);
```

This is invalid:

```sql
INSERT INTO users
VALUES (1, 'arun', 'arun@gmail.com');

INSERT INTO users
VALUES (2, 'arun', 'bala@gmail.com');
```

❌ `username = 'arun'` already exists.

### Primary Key vs UNIQUE

| Primary Key                       | UNIQUE                                                    |
| --------------------------------- | --------------------------------------------------------- |
| Uniquely identifies row           | Prevents duplicate values                                 |
| Cannot be NULL                    | NULL behavior differs by DB; MySQL permits multiple NULLs |
| One PK constraint per table       | Multiple UNIQUE constraints possible                      |
| Usually the row's main identifier | Used for other unique attributes                          |

# 5. Composite Key

A **Composite Key** consists of **multiple columns together**.

Example:

```text
student_courses

student_id | course_id
-----------+----------
1          | 101
1          | 102
2          | 101
```

Neither column alone is necessarily unique.

But:

```text
(student_id, course_id)
```

together uniquely identify a row.

```sql
CREATE TABLE student_courses (
    student_id INT,
    course_id INT,

    PRIMARY KEY (student_id, course_id)
);
```

This is allowed:

```text
1, 101
1, 102
2, 101
```

But this is not:

```text
1, 101
1, 101  ← duplicate combination
```

---

# 6. Candidate Key

A **Candidate Key** is a column or set of columns that **could uniquely identify a row**.

Example:

```text
employees

id
email
phone
```

Suppose all three are unique.

Then:

```text
id       → candidate key
email    → candidate key
phone    → candidate key
```

One candidate key is selected as the **Primary Key**.

For example:

```text
Primary Key → id
Candidate Keys → email, phone
```

Think:

> **Candidate keys = possible choices for Primary Key**

---

# 7. Alternate Key

Once you select one candidate key as the Primary Key, the remaining candidate keys are called **Alternate Keys**.

Example:

```text
id       → Primary Key
email    → Alternate Key
phone    → Alternate Key
```

In actual SQL, you might enforce these using:

```sql
email VARCHAR(100) UNIQUE,
phone VARCHAR(20) UNIQUE
```

---

# 8. Super Key

A **Super Key** is any column/set of columns that can uniquely identify a row.

Suppose:

```text
id
email
```

are individually unique.

Then all of these can technically be super keys:

```text
{id}
{email}
{id, email}
{id, email, name}
```

But:

```text
{id, email}
```

contains unnecessary information.

A **Candidate Key is a minimal Super Key**.

### Easy hierarchy

```text
Super Key
    ↓
Candidate Key
    ↓
Primary Key
```

---

# 9. Natural Key vs Surrogate Key

This is very useful when designing databases.

### Natural Key

Uses real-world/business data.

Example:

```text
email
PAN number
employee code
ISBN
```

Example:

```sql
email VARCHAR(100) PRIMARY KEY
```

### Surrogate Key

Artificial ID created specifically for the database.

```sql
id BIGINT PRIMARY KEY AUTO_INCREMENT
```

Example:

```text
id | email
---+----------------
1  | arun@gmail.com
2  | bala@gmail.com
```

In many Spring Boot applications, you'll commonly see:

```java
@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Long id;
```

So:

```text
id = Surrogate Key
email = Natural Key
```

# 10. Complete Working Example

Run this in MySQL:

```sql
CREATE DATABASE key_practice;

USE key_practice;

CREATE TABLE departments (
    id INT PRIMARY KEY,
    name VARCHAR(50) UNIQUE
);

CREATE TABLE employees (
    id INT PRIMARY KEY AUTO_INCREMENT,
    employee_code VARCHAR(20) UNIQUE,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE,
    department_id INT,

    FOREIGN KEY (department_id)
        REFERENCES departments(id)
);
```

Insert:

```sql
INSERT INTO departments
VALUES
(10, 'IT'),
(20, 'HR');

INSERT INTO employees
(employee_code, name, email, department_id)
VALUES
('EMP001', 'Arun', 'arun@gmail.com', 10),
('EMP002', 'Bala', 'bala@gmail.com', 20);
```

Check:

```sql
SELECT * FROM employees;
```

Try:

```sql
INSERT INTO employees
(employee_code, name, email, department_id)
VALUES
('EMP001', 'Kumar', 'kumar@gmail.com', 10);
```

❌ Fails because `employee_code` is `UNIQUE`.

Try:

```sql
INSERT INTO employees
(employee_code, name, email, department_id)
VALUES
('EMP003', 'Kumar', 'kumar@gmail.com', 99);
```

❌ Fails because department `99` doesn't exist due to the **Foreign Key**.

# 11. Keys You Should Remember for Interviews

| Key               | Main Purpose                                 |
| ----------------- | -------------------------------------------- |
| **Primary Key**   | Uniquely identifies a row                    |
| **Foreign Key**   | Connects tables                              |
| **Unique Key**    | Prevents duplicate values                    |
| **Composite Key** | Multiple columns form one key                |
| **Candidate Key** | Possible choice for PK                       |
| **Alternate Key** | Candidate key not selected as PK             |
| **Super Key**     | Any combination that uniquely identifies row |
| **Natural Key**   | Real-world meaningful identifier             |
| **Surrogate Key** | Artificial/database-generated identifier     |

### Most important for your Spring Boot journey

Focus especially on:

```text
Primary Key ⭐⭐⭐
Foreign Key ⭐⭐⭐
Composite Key ⭐⭐
Unique Key ⭐⭐⭐
Natural vs Surrogate Key ⭐⭐
```

The next natural topic after **Keys + Joins** is **Relationships: One-to-One, One-to-Many, Many-to-One, Many-to-Many**, because that's where these SQL concepts connect directly to **JPA/Hibernate in Spring Boot**.
