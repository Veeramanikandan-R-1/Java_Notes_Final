# JPA, Hibernate, Spring Data JPA and Jakarta Persistence API

## 1. What is JPA?

JPA (Java Persistence API) is a Java specification that defines a standard way to map Java objects to relational database tables and perform database operations.

It defines ORM standards but does not provide the actual implementation.

## 2. Why do we need JPA?

- Provides a common standard for ORM.
- Allows developers to work with Java objects instead of writing SQL for every operation.
- Makes switching between JPA implementations easier.
- Reduces dependency on a specific ORM framework.

## 3. Difference between JPA, Hibernate and Spring Data JPA

| Technology      | Type                         | Responsibility                                    |
| --------------- | ---------------------------- | ------------------------------------------------- |
| JPA             | Specification                | Defines ORM standards and APIs                    |
| Hibernate       | ORM implementation           | Implements JPA and handles database operations    |
| Spring Data JPA | Spring framework abstraction | Simplifies database operations using repositories |

### How they work together

1. Spring Data JPA provides repository interfaces such as `JpaRepository`.
2. Spring Data JPA uses JPA APIs internally.
3. Hibernate implements the JPA APIs.
4. Hibernate generates SQL queries and communicates with the database.

Example:

```
public interface UserRepository extends JpaRepository<User, Long> {
}
```

```
userRepository.save(user);
userRepository.findById(1L);
userRepository.deleteById(1L);
```

Here:

- `JpaRepository` comes from Spring Data JPA.
- JPA defines the persistence standards.
- Hibernate performs the actual ORM operations.

## 4. What is Jakarta Persistence API?

Jakarta Persistence API is the newer name for JPA.

Initially, JPA was part of Java EE under the `javax.persistence` package.

After Java EE moved to the Eclipse Foundation and became Jakarta EE, the package namespace changed to `jakarta.persistence`.

### Difference between javax.persistence and jakarta.persistence

| Feature            | Java Persistence API       | Jakarta Persistence API      |
| ------------------ | -------------------------- | ---------------------------- |
| Original package   | `javax.persistence`        | `jakarta.persistence`        |
| Specification      | JPA                        | Jakarta Persistence          |
| Ownership          | Java EE                    | Jakarta EE                   |
| Current usage      | Older applications         | Modern applications          |
| Example annotation | `javax.persistence.Entity` | `jakarta.persistence.Entity` |

Important: Jakarta Persistence is not a different ORM technology. It is the continuation of JPA under Jakarta EE.

### Example

Older JPA:

```
import javax.persistence.Entity;
import javax.persistence.Id;
```

Modern Jakarta Persistence:

```
import jakarta.persistence.Entity;
import jakarta.persistence.Id;
```

For Spring Boot 3.x and 4.x, use `jakarta.persistence` imports.

## 5. Final takeaway (Interview)

Remember these four points:

- JPA: Specification that defines ORM standards.
- Jakarta Persistence: New name and namespace for JPA.
- Hibernate: Implementation of the JPA/Jakarta Persistence specification.
- Spring Data JPA: Simplifies database operations through repository interfaces.

Recommended learning order:

1. JPA fundamentals
2. Jakarta Persistence annotations
3. Hibernate architecture and working
4. Entity relationships
5. Spring Data JPA and repository methods

This is the standard combination to understand when developing Spring Boot applications with MySQL or PostgreSQL.
