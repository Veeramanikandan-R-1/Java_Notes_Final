In Hibernate, Lazy and Eager fetching determine when associated entities are loaded from the database.

## 1. Lazy Fetching (`FetchType.LAZY`)

- Associated data is loaded only when you access it.
- Avoids unnecessary database queries.
- Improves performance when related data is not required.

```
@OneToMany(fetch = FetchType.LAZY)
private List<Order> orders;
```

Example: Fetch a User without loading their Orders. Orders are loaded when `user.getOrders()` is accessed (provided the session is open).

## 2. Eager Fetching (`FetchType.EAGER`)

- Associated data is loaded immediately along with the parent entity.
- Useful when related data is always required.
- Can increase memory usage and database query overhead.

```
@OneToMany(fetch = FetchType.EAGER)
private List<Order> orders;
```

## 3. Difference

| Lazy                                     | Eager                                                  |
| ---------------------------------------- | ------------------------------------------------------ |
| Loads data on demand                     | Loads data immediately                                 |
| Avoids unnecessary loading               | May load unnecessary data                              |
| Generally better for large relationships | Useful for frequently required relationships           |
| Can cause LazyInitializationException    | Avoids lazy initialization issues for that association |

## 4. Interview example

Consider:

\- User → Orders (One-to-Many)

Lazy: Load User first. Load Orders only when requested.

Eager: Load User and its associated Orders immediately.

Interview tip: Prefer LAZY fetching for most associations and explicitly fetch related data when needed using `JOIN FETCH` or Entity Graphs. EAGER does not necessarily mean one SQL JOIN; Hibernate may use additional queries.

### Entity in Hibernate

An Entity is a Java class that represents a database table. Each object of that class represents one row in the table.

We use the `@Entity` annotation to tell Hibernate that a Java class should be mapped to a database table.

Example:

```
import jakarta.persistence.*;

@Entity
@Table(name = "students")
public class Student {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private int id;

    private String name;
    private int age;
}
```

Mapping:

| Java / Hibernate | Database         |
| ---------------- | ---------------- |
| `Student` class  | `students` table |
| `id` field       | `id` column      |
| `name` field     | `name` column    |
| `age` field      | `age` column     |
| Student object   | One table row    |

Key annotations:

- `@Entity` – Marks the class as an entity.
- `@Table` – Specifies the database table name.
- `@Id` – Defines the primary key.
- `@GeneratedValue` – Configures automatic primary key generation.

In short: Entity is the bridge between a Java object and a database table. Hibernate uses this mapping to perform CRUD operations.
