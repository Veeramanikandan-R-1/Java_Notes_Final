# **JWT (JSON Web Token) – Introduction**

**JWT** is a token-based authentication mechanism used to securely identify users and authorize access to protected APIs.

Instead of sending username and password with every request, the client sends a JWT token.

## **1. Why JWT?**

Consider a React + Spring Boot application.

Without JWT:

1. User sends username and password.
2. Server authenticates the user.
3. Managing authenticated sessions requires server-side session state.

With JWT:

1. User logs in with username and password.
2. Spring Boot validates credentials.
3. Server generates a JWT token.
4. React stores the token.
5. React sends the token with subsequent API requests.
6. Spring Boot validates the token and allows or denies access.

## **2. JWT structure**

A JWT consists of three parts separated by dots (`.`).

**Header**

### **.**

**Payload**

### **.**

**Signature**

- **Header:** Token type and signing algorithm (e.g., HS256).
- **Payload:** User information and claims (e.g., user ID, role, expiration).
- **Signature:** Verifies that the token has not been modified.

Example payload:

```
{
  "sub": "admin",
  "role": "ADMIN",
  "iat": 1795000000,
  "exp": 1795003600
}
```

Note: JWT payload is Base64URL encoded, not encrypted. Never store passwords or sensitive information inside it.

## **3. JWT authentication flow**

**React Application**

User enters username and password

**Spring Boot Login API**

Validates credentials using BCrypt

**JWT Generation**

Generates and returns access token

**React Application**

Sends token with API requests

**JWT Filter in Spring Security**

Validates token and authenticates user

Access granted to protected API

## **4. How React sends JWT?**

Usually through the Authorization header:

```
fetch("http://localhost:8080/api/products", {
    headers: {
        Authorization: `Bearer ${token}`
    }
});
```

`Bearer` indicates that the client is sending a bearer token.

## **5. Important JWT concepts**

| Concept            | Purpose                               |
| ------------------ | ------------------------------------- |
| Access Token       | Authenticates API requests            |
| Refresh Token      | Generates a new access token          |
| Secret Key         | Signs and verifies JWT                |
| Expiration (`exp`) | Defines token validity                |
| JWT Filter         | Validates token for incoming requests |
| Claims             | Stores user-related information       |
| Bearer Token       | Token authentication scheme           |

## **6. JWT vs Session Authentication**

| Session                                | JWT                                    |
| -------------------------------------- | -------------------------------------- |
| Server maintains session state         | Usually stateless                      |
| Session ID stored on client            | Token stored on client                 |
| Server validates session ID            | Server validates token                 |
| Session can be invalidated server-side | Revocation needs additional mechanisms |

**Important:** JWT does not automatically make an application secure. Use HTTPS, short-lived access tokens, secure token storage and proper signature validation.

## **7. What to implement in Spring Boot?**

Recommended learning sequence:

1. Add JWT dependency (JJWT).
2. Create JWT utility/service class.
3. Generate JWT after successful login.
4. Validate JWT token.
5. Create JWT authentication filter.
6. Configure Spring Security.
7. Protect REST APIs using JWT.
8. Integrate JWT with React.
