## **Spring Security – Introduction**

**Spring Security** is a Spring framework used to secure Java applications by handling **authentication and authorization**.

It protects REST APIs and web applications from unauthorized access.

### **1. Two important concepts**

| Concept        | Meaning              | Example                           |
| -------------- | -------------------- | --------------------------------- |
| Authentication | Who are you?         | Login using username and password |
| Authorization  | What can you access? | Only ADMIN can delete products    |

### **2. Key features**

- **Authentication:** Validates user identity.
- **Authorization:** Controls access based on roles and permissions.
- **Password Encoding:** Securely hashes passwords using BCrypt.
- **JWT Authentication:** Uses tokens to authenticate API requests.
- **CSRF Protection:** Protects against Cross-Site Request Forgery.
- **CORS:** Controls cross-origin browser requests.

### **3. How it works**

**Client (React)**

Sends login credentials / API request

**Spring Security Filters**

Checks authentication and authorization

**Spring Boot Controller**

Processes authorized requests

### **4. Important classes and concepts**

- `SecurityFilterChain` – Configures security rules.
- `UserDetails` – Represents user information.
- `UserDetailsService` – Loads user details.
- `PasswordEncoder` – Encodes passwords.
- `AuthenticationManager` – Manages authentication.

### **5. Example**

```
.requestMatchers("/api/admin/**").hasRole("ADMIN")
.requestMatchers("/api/user/**").hasAnyRole("USER", "ADMIN")
.anyRequest().authenticated()
```

**Interview definition:** Spring Security is a powerful framework that provides authentication, authorization, and protection against common security attacks in Spring applications.

**Recommended learning order:** Basic authentication → Password encoding → Role-based authorization → JWT authentication → Spring Security with React.

### `spring-boot-starter-security`**&#x20;– Package Introduction**

This is a **Spring Boot Starter dependency** that adds Spring Security functionality to your application.

```
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security</artifactId>
    <version>4.1.1</version>
</dependency>
```

**What does it provide?**

- Authentication – Verify user identity.
- Authorization – Control user access.
- Password security – Secure password handling.
- Security filters – Intercept and validate HTTP requests.
- Default security configuration – Automatically secures endpoints.

**Important notes:**

- `groupId`: Organization providing the dependency.
- `artifactId`: Dependency name.
- `version`: Spring Boot starter version.
- `scope`: Defaults to `compile`, so you can omit it.
- If you're using Spring Boot parent `4.1.1`, you can omit the dependency version because the parent manages it.

**In short:** Adding this dependency integrates Spring Security into your Spring Boot application.

You can configure your own username and password directly in `application.properties`.

### **application.properties**

```
spring.security.user.name=admin
spring.security.user.password=admin123
spring.security.user.roles=ADMIN
```

### **How it works**

- `spring.security.user.name` – Custom username.
- `spring.security.user.password` – Custom password.
- `spring.security.user.roles` – User roles.

### **Important**

1. No need to create `SecurityConfig.java` for basic default authentication.
2. Spring Boot automatically configures the user.
3. Password is configured as plain text in properties (not recommended for production).
4. Spring Security uses HTTP Basic or its default login form, depending on your configuration.

**Interview note:** `spring.security.user.*` properties configure a default in-memory user in Spring Boot.

---

Since you configured username and password in `application.properties`:

```
spring.security.user.name=admin
spring.security.user.password=admin123
spring.security.user.roles=ADMIN
```

You need to send these credentials from React using **HTTP Basic Authentication**.

### **1. Using fetch()**

```
const username = "admin";
const password = "admin123";

const response = await fetch(`${baseURL}/product`, {
    method: "GET",
    headers: {
        "Authorization": `Basic ${btoa(`${username}:${password}`)}`
    }
});

const data = await response.json();
console.log(data);
```

### **2. Using Axios**

```
import axios from "axios";

const response = await axios.get(`${baseURL}/product`, {
    auth: {
        username: "admin",
        password: "admin123"
    }
});

console.log(response.data);
```

### **3. How Basic Authentication works**

React sends this HTTP header:

```
Authorization: Basic YWRtaW46YWRtaW4xMjM=
```

Spring Security decodes the credentials and validates them.

### **Important**

- `401 Unauthorized` – Missing or invalid credentials.
- `403 Forbidden` – Authenticated, but insufficient permissions.
- Use HTTPS in production.
- Don't hardcode production credentials in React. Browser code is visible to users.

**For your e-commerce application:** Learn JWT authentication next. It is a better approach for a React + Spring Boot application than sending the username and password with every API request.
