## **CSRF in Spring Boot**

**CSRF (Cross-Site Request Forgery)** is a security attack where an attacker tricks an authenticated user's browser into sending an unwanted request to another website.

For example:

1. You log in to an e-commerce website.
2. Your browser stores your authentication session.
3. You visit a malicious website.
4. That website tries to submit an unwanted POST request to your e-commerce website.
5. Your browser may automatically send the session cookie.

CSRF protection prevents such unauthorized cross-site requests.

## **1. How CSRF protection works**

Spring Security generates a CSRF token and expects the client to send it with requests that modify data.

**React application**

Requests CSRF token

**Spring Security**

Generates and provides token

**React sends POST / PUT / DELETE**

Includes CSRF token

**Spring Security validates token**

Valid token → request proceeds

## **2. Generate and return CSRF token**

Create a controller endpoint:

**CsrfController.java**

```
package com.practice.ecommerce_server.controller;

import java.util.Map;

import org.springframework.security.web.csrf.CsrfToken;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class CsrfController {

    @GetMapping("/api/csrf")
    public Map<String, String> getCsrfToken(CsrfToken csrfToken) {

        return Map.of(
            "token", csrfToken.getToken(),
            "headerName", csrfToken.getHeaderName()
        );
    }
}
```

Spring Security generates the token when it is accessed and returns it through this endpoint.

## **3. Configure Spring Security**

**SecurityConfig.java**

```
@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http)
            throws Exception {

        http
            .csrf(csrf -> csrf
                .csrfTokenRepository(
                    new HttpSessionCsrfTokenRepository()
                )
            )
            .authorizeHttpRequests(auth -> auth
                .anyRequest().authenticated()
            )
            .httpBasic(basic -> {});

        return http.build();
    }
}
```

Import:

```
import org.springframework.security.web.csrf.HttpSessionCsrfTokenRepository;
```

Here:

- `HttpSessionCsrfTokenRepository` stores the CSRF token in the HTTP session.
- Spring Security validates the token for POST, PUT, PATCH and DELETE requests.
- GET requests generally don't require a CSRF token.

## **4. Get CSRF token in React**

First, request the token:

```
const csrfResponse = await fetch(`${baseURL}/api/csrf`, {
    headers: {
        Authorization: "Basic " + btoa("user:User@123")
    },
    credentials: "include"
});

const csrfData = await csrfResponse.json();

console.log(csrfData);
```

Example response:

```
{
    "token": "generated-csrf-token",
    "headerName": "X-CSRF-TOKEN"
}
```

## **5. Send token with POST request**

Update your existing fetch request:

```
fetch(`${baseURL}/product`, {
    method: "POST",
    body: data,
    credentials: "include",
    headers: {
        Authorization: "Basic " + btoa("user:User@123"),
        [csrfData.headerName]: csrfData.token
    }
});
```

Do not manually set the multipart `Content-Type`.

## **6. Important: React and Spring Boot CORS**

If React and Spring Boot run on different origins, configure CORS to allow credentials and your React origin. Do not use `*` as the allowed origin when credentials are enabled.

Also, Basic Authentication credentials manually attached by React are not normally sent automatically by a malicious cross-site HTML form. If your API uses only manually supplied Basic Auth headers and no cookie-based authentication, disabling CSRF can be appropriate.

**Remember these concepts:**

| Concept                          | Purpose                                    |
| -------------------------------- | ------------------------------------------ |
| CSRF Token                       | Protects against forged requests           |
| `CsrfToken`                      | Represents the generated token             |
| `HttpSessionCsrfTokenRepository` | Stores token in session                    |
| `X-CSRF-TOKEN`                   | Header used to send the token              |
| `403 Forbidden`                  | Common response when CSRF validation fails |

**For your learning:** Test the flow in this order: GET `/api/csrf` → POST `/product` with the returned token → POST without the token and observe the rejection.

---

We make changes in `SecurityConfig.java` because **Spring Security controls CSRF protection through its security filter chain**. The configuration tells Spring Security how to generate, store, expose, and validate CSRF tokens.

### **Why are these changes needed?**

For example, when React sends a POST request:

1. Spring Security checks whether CSRF protection is enabled.
2. It generates or retrieves a CSRF token.
3. React sends that token in the request header.
4. Spring Security compares the received token with the expected token.
5. If the token is missing or invalid, Spring Security rejects the request with `403 Forbidden`.

### **What does each configuration do?**

```
http.csrf(csrf -> csrf
    .csrfTokenRepository(
        new HttpSessionCsrfTokenRepository()
    )
);
```

- `csrf()` – enables CSRF protection.
- `HttpSessionCsrfTokenRepository()` – stores the CSRF token in the HTTP session so it can be validated on subsequent requests.

### **Do we always need to modify SecurityConfig?**

**No.**

| Scenario                                                                | Configuration                               |
| ----------------------------------------------------------------------- | ------------------------------------------- |
| Default Spring Security CSRF                                            | Usually no additional configuration         |
| Custom token storage                                                    | Configure `CsrfTokenRepository`             |
| React frontend integration                                              | Configure token handling and CORS as needed |
| Stateless REST API using Basic auth without cookie-based authentication | CSRF may be disabled if appropriate         |

**Key point:** `SecurityConfig` configures the security mechanism; the controller exposes the token to React; React sends it back with state-changing requests. These are three different responsibilities.
