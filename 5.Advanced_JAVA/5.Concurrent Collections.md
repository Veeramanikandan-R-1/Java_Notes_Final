# Advanced Java — Concurrent Collections

## Subtopic: `BlockingQueue`

Since you already know React and are learning Java for **Spring Boot/full-stack**, the key thing to understand is **producer-consumer communication between threads**.

---

## 1. What is a `BlockingQueue`?

`BlockingQueue` is a **thread-safe queue** where:

* A **producer** puts data into the queue.
* A **consumer** takes data from the queue.
* If the queue is **full**, producer can wait.
* If the queue is **empty**, consumer can wait.

```text
Producer Thread
      │
      │ put()
      ▼
┌─────────────────┐
│  BlockingQueue  │
│ [A] [B] [C]     │
└─────────────────┘
      │
      │ take()
      ▼
Consumer Thread
```

This is especially useful when multiple threads need to exchange data safely.

---

# 2. Why not use normal `Queue`?

A normal `Queue` like:

```java
Queue<String> queue = new LinkedList<>();
```

is **not thread-safe**.

With multiple threads:

```text
Producer 1 ──┐
Producer 2 ──┼──> Queue
Consumer 1 ──┘
```

you can get race conditions.

`BlockingQueue` handles the necessary thread synchronization for you.

---

# 3. Important Implementations

The main implementations you should know:

| Implementation          | Behavior                                   |
| ----------------------- | ------------------------------------------ |
| `ArrayBlockingQueue`    | Fixed capacity                             |
| `LinkedBlockingQueue`   | Usually used as a bounded/unbounded queue  |
| `PriorityBlockingQueue` | Elements processed according to priority   |
| `DelayQueue`            | Element available only after delay         |
| `SynchronousQueue`      | No storage; direct handoff between threads |

For interviews, focus first on:

**`ArrayBlockingQueue` and `LinkedBlockingQueue`.**

BlockingQueue<String> queue =

 ↑

# 5. Four Important Operations

This is **very important for interviews**.

| Operation | If queue is full/empty |
| --------- | ---------------------- |
| `add()`   | Throws exception       |
| `offer()` | Returns `false`        |
| `put()`   | Waits/block            |
| `take()`  | Waits/block            |

### Example

```java
queue.put("A");
```

If the queue is full:

```text
Producer
   │
   ▼
put("D")
   │
   ├── queue full
   │
   ▼
WAIT
```

When space becomes available, the producer continues.

---

# 6. `put()` vs `offer()`

### `put()`

Blocks until space is available.

```java
queue.put("A");
```

### `offer()`

Doesn't wait indefinitely.

```java
boolean result = queue.offer("A");

System.out.println(result);
```

If queue is full:

```text
false
```

You can also specify a timeout:

```java
queue.offer("A", 2, TimeUnit.SECONDS);
```

Meaning:

> Wait up to 2 seconds for space.

---

# 7. `take()` vs `poll()`

### `take()`

Blocks until an element is available.

```java
String value = queue.take();
```

If empty:

```text
Consumer
   │
 take()
   │
   ▼
 WAIT
   │
Producer adds item
   │
   ▼
Consumer continues
```

### `poll()`

Returns immediately.

```java
String value = queue.poll();
```

If empty:

```text
null
```

Timeout version:

```java
queue.poll(2, TimeUnit.SECONDS);
```

# 8. Producer-Consumer Example ⭐

This is the most important example.

### Full working code

```java
import java.util.concurrent.ArrayBlockingQueue;
import java.util.concurrent.BlockingQueue;

public class Main {

    public static void main(String[] args) {

        BlockingQueue<String> queue =
                new ArrayBlockingQueue<>(3);

        // Producer
        Thread producer = new Thread(() -> {

            try {
                for (int i = 1; i <= 5; i++) {

                    String item = "Item-" + i;

                    queue.put(item);

                    System.out.println(
                            "Produced: " + item
                    );

                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        });

        // Consumer
        Thread consumer = new Thread(() -> {

            try {
                for (int i = 1; i <= 5; i++) {

                    String item = queue.take();

                    System.out.println(
                            "Consumed: " + item
                    );
                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        });

        producer.start();
        consumer.start();
    }
}
```

Possible output:

```text
Produced: Item-1
Consumed: Item-1
Produced: Item-2
Produced: Item-3
Consumed: Item-2
Produced: Item-4
Consumed: Item-3
Produced: Item-5
Consumed: Item-4
Consumed: Item-5
```

The exact order/timing can vary because threads execute concurrently.

# 9. What happens when Queue is Full?

Suppose:

```java
BlockingQueue<String> queue =
        new ArrayBlockingQueue<>(2);
```

Producer:

```java
queue.put("A");
queue.put("B");
queue.put("C");
```

After A and B:

```text
Queue:
[A] [B]
```

Queue is full.

When producer executes:

```java
queue.put("C");
```

it **blocks**.

Then consumer executes:

```java
queue.take();
```

Now:

```text
Before:

[A] [B]

Consumer takes A

After:

[B]
```

Space is available, so producer can continue and insert C.

This is the main advantage of `BlockingQueue`.

# 10. `ArrayBlockingQueue`

Fixed-size queue:

```java
BlockingQueue<Integer> queue =
        new ArrayBlockingQueue<>(100);
```

Capacity cannot grow beyond `100`.

Good when you want **controlled memory usage/backpressure**.

---

# 11. `LinkedBlockingQueue`

```java
BlockingQueue<Integer> queue =
        new LinkedBlockingQueue<>(100);
```

Can also be bounded.

If capacity isn't specified:

```java
BlockingQueue<Integer> queue =
        new LinkedBlockingQueue<>();
```

it has a very large theoretical capacity (`Integer.MAX_VALUE`), so don't assume this means unlimited memory.

---

# 12. `PriorityBlockingQueue`

Elements are processed based on priority rather than insertion order.

```java
import java.util.concurrent.PriorityBlockingQueue;

public class Main {

    public static void main(String[] args) throws Exception {

        PriorityBlockingQueue<Integer> queue =
                new PriorityBlockingQueue<>();

        queue.put(30);
        queue.put(10);
        queue.put(20);

        System.out.println(queue.take());
        System.out.println(queue.take());
        System.out.println(queue.take());
    }
}
```

Output:

```text
10
20
30
```

It is useful when tasks have different priorities.

**Important:** `PriorityBlockingQueue` is not bounded by default.

---

# 13. Why `BlockingQueue` is Better Than Manual `wait()` / `notify()`

Without `BlockingQueue`, you might write:

```text
synchronized
wait()
notify()
```

manually.

This can become complicated and error-prone.

With `BlockingQueue`:

```java
queue.put(item);
queue.take();
```

The queue handles the coordination.

So:

```text
Manual approach:
synchronized + wait() + notify()

Modern approach:
BlockingQueue
```

# 14. Spring Boot Connection

This concept appears in backend systems such as:

```text
HTTP Requests
     ↓
Producer
     ↓
BlockingQueue
     ↓
Worker Threads
     ↓
Database / External API
```

For example:

```text
Order API
   ↓
Queue
   ↓
Order Worker 1
Order Worker 2
Order Worker 3
   ↓
Process Orders
```

This allows you to **control how many tasks are processed concurrently** and provides a form of **backpressure** when the queue is bounded.

In Spring Boot, you'll encounter similar concepts through:

* `ThreadPoolTaskExecutor`
* `ExecutorService`
* `@Async`
* message brokers such as Kafka/RabbitMQ

# 15. Important Interview Question

### Is `BlockingQueue` thread-safe?

**Yes.**

It is specifically designed for concurrent access from multiple threads.

### Does `BlockingQueue` guarantee FIFO?

It depends on the implementation.

For example:

```text
ArrayBlockingQueue → FIFO
LinkedBlockingQueue → FIFO
PriorityBlockingQueue → priority ordering
```

So don't say simply:

> "All BlockingQueues are FIFO."

# 16. Quick Revision ⭐

Remember this table:

| Method     | Success | Failure   |
| ---------- | ------- | --------- |
| `add(e)`   | Adds    | Exception |
| `offer(e)` | `true`  | `false`   |
| `put(e)`   | Adds    | **Waits** |
| `remove()` | Removes | Exception |
| `poll()`   | Removes | `null`    |
| `take()`   | Removes | **Waits** |

### The four you should remember first:

```java
put()    → add, wait if full
take()   → remove, wait if empty

offer()  → add, don't wait
poll()   → remove, don't wait
```

### Mental model

```text
             BlockingQueue
            /             \
       Producer          Consumer
          │                  │
       put()               take()
          │                  │
          └──── Queue ───────┘
             │
       Full → producer waits
       Empty → consumer waits
```
