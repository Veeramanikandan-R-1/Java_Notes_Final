# Template Method Pattern

**Template Method** is a **behavioral design pattern**.

### 1. What problem does it solve?

When multiple classes follow the **same overall algorithm**, but some individual steps differ, put the common algorithm in a parent class and let child classes customize specific steps.

Think:

```text
Overall process = fixed
Individual steps = customizable
```

For example, preparing different beverages:

```text
1. Boil water        ← common
2. Prepare beverage  ← different
3. Pour into cup     ← common
4. Add ingredients   ← different
```

---

## 2. Key concept

The parent class defines the **template method**:

```java
final void prepare() {
    step1();
    step2();
    step3();
    step4();
}
```

Child classes override the variable steps.

### Important

The template method is usually marked **`final`** so subclasses cannot change the overall algorithm/order.

---

## 3. Full working example

```java
abstract class Beverage {

    // Template Method
    public final void prepare() {
        boilWater();
        prepareBeverage();
        pourIntoCup();
        addIngredients();
    }

    // Common steps
    private void boilWater() {
        System.out.println("Boiling water");
    }

    private void pourIntoCup() {
        System.out.println("Pouring into cup");
    }

    // Variable steps
    protected abstract void prepareBeverage();

    protected abstract void addIngredients();
}

class Tea extends Beverage {

    @Override
    protected void prepareBeverage() {
        System.out.println("Steeping tea");
    }

    @Override
    protected void addIngredients() {
        System.out.println("Adding lemon");
    }
}

class Coffee extends Beverage {

    @Override
    protected void prepareBeverage() {
        System.out.println("Brewing coffee");
    }

    @Override
    protected void addIngredients() {
        System.out.println("Adding milk and sugar");
    }
}

public class Main {

    public static void main(String[] args) {

        Beverage tea = new Tea();
        tea.prepare();

        System.out.println();

        Beverage coffee = new Coffee();
        coffee.prepare();
    }
}
```

### Output

```text
Boiling water
Steeping tea
Pouring into cup
Adding lemon

Boiling water
Brewing coffee
Pouring into cup
Adding milk and sugar
```

---

## 4. What is happening?

```java
tea.prepare();
```

calls the **parent's final method**:

```java
prepare()
```

The sequence is always:

```text
boilWater()
    ↓
prepareBeverage()
    ↓
pourIntoCup()
    ↓
addIngredients()
```

But because of **runtime polymorphism**:

```java
prepareBeverage()
addIngredients()
```

execute the `Tea` implementation.

For coffee, they execute the `Coffee` implementation.

So:

```text
Parent
 └── defines algorithm/order
       ↓
Child
 └── provides specific implementations
```

# 5. Hook Method

A Template Method can also contain an **optional hook**.

A hook provides a default implementation that subclasses *may* override.

```java
abstract class Beverage {

    public final void prepare() {
        boilWater();
        prepareBeverage();

        if (customerWantsMilk()) {
            addMilk();
        }

        pourIntoCup();
    }

    protected abstract void prepareBeverage();

    protected void addMilk() {
        System.out.println("Adding milk");
    }

    // Hook
    protected boolean customerWantsMilk() {
        return true;
    }

    private void boilWater() {
        System.out.println("Boiling water");
    }

    private void pourIntoCup() {
        System.out.println("Pouring into cup");
    }
}
```

A subclass can override:

```java
@Override
protected boolean customerWantsMilk() {
    return false;
}
```

### Abstract method vs Hook

|                | Abstract method        | Hook                   |
| -------------- | ---------------------- | ---------------------- |
| Implementation | Must provide           | Already has default    |
| Override       | Required               | Optional               |
| Purpose        | Required customization | Optional customization |

# 6. Template Method vs Strategy

This is an important interview comparison.

### Template Method

Uses **inheritance**:

```text
Parent
  ↓
Child
```

The overall algorithm is controlled by the parent.

### Strategy

Uses **composition**:

```text
Context
  ↓
Strategy interface
  ↓
Different implementations
```

Strategy allows behavior to be changed more dynamically at runtime.

---

# 7. Real-world Java/Spring relevance

You will see this pattern in Java frameworks.

For example, Spring's framework classes often provide a common workflow while allowing subclasses/callbacks to customize particular operations.

A famous Java example is:

```java
AbstractList
```

where the framework provides common list behavior while subclasses provide specific operations.

You don't necessarily need to manually implement Template Method frequently in Spring Boot, but **understanding it helps you understand framework architecture**.

---

## Interview answer

> **Template Method is a behavioral design pattern where a parent class defines the skeleton of an algorithm and subclasses implement or customize specific steps without changing the overall algorithm. The template method is commonly made `final` to preserve the algorithm's order.**

### Remember this

```text
Template Method
       ↓
Inheritance
       ↓
Parent fixes algorithm
       ↓
Child customizes steps
       ↓
Often uses abstract methods + hooks
```
