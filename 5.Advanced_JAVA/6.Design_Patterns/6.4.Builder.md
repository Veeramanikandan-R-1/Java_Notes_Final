# Design Pattern: Builder

**Builder Pattern** is a **Creational Design Pattern**.

It is useful when an object has **many fields/parameters**, especially when many of them are **optional**.

---

## 1. What problem does Builder solve?

Suppose you have a `User` with many properties:

```java
User user = new User(
    "Veera",
    "veera@gmail.com",
    28,
    "Chennai",
    "Java",
    true
);
```

Problems:

* Hard to understand which argument is which.
* Easy to pass values in the wrong order.
* Constructor becomes very large.
* Optional fields become difficult to handle.

You could create multiple constructors:

```java
User(...)
User(..., ...)
User(..., ..., ...)
```

This is called **telescoping constructors** and becomes messy.

Builder solves this by allowing:

```java
User user = new User.Builder()
        .name("Veera")
        .email("veera@gmail.com")
        .age(28)
        .city("Chennai")
        .skill("Java")
        .active(true)
        .build();
```

Much easier to read.

---

# 2. Basic Builder Structure

```text
User
 └── Builder
      ├── name()
      ├── email()
      ├── age()
      ├── city()
      └── build()
```

The `Builder` collects the values and finally creates the `User`.

---

# 3. Complete Working Example

```java
class User {

    private final String name;
    private final String email;
    private final int age;
    private final String city;
    private final boolean active;

    private User(Builder builder) {
        this.name = builder.name;
        this.email = builder.email;
        this.age = builder.age;
        this.city = builder.city;
        this.active = builder.active;
    }

    public void display() {
        System.out.println("Name: " + name);
        System.out.println("Email: " + email);
        System.out.println("Age: " + age);
        System.out.println("City: " + city);
        System.out.println("Active: " + active);
    }

    // Builder
    public static class Builder {

        private String name;
        private String email;
        private int age;
        private String city;
        private boolean active;

        public Builder name(String name) {
            this.name = name;
            return this;
        }

        public Builder email(String email) {
            this.email = email;
            return this;
        }

        public Builder age(int age) {
            this.age = age;
            return this;
        }

        public Builder city(String city) {
            this.city = city;
            return this;
        }

        public Builder active(boolean active) {
            this.active = active;
            return this;
        }

        public User build() {
            return new User(this);
        }
    }
}

public class Main {

    public static void main(String[] args) {

        User user = new User.Builder()
                .name("Veera")
                .email("veera@gmail.com")
                .age(28)
                .city("Chennai")
                .active(true)
                .build();

        user.display();
    }
}
```

### Output

```text
Name: Veera
Email: veera@gmail.com
Age: 28
City: Chennai
Active: true
```

# 4. How does `return this` work?

This is the key part of Builder.

```java
public Builder name(String name) {
    this.name = name;
    return this;
}
```

`this` means **current Builder object**.

Therefore:

```java
new User.Builder()
    .name("Veera")
    .email("veera@gmail.com")
    .age(28)
```

works because:

```text
Builder
  ↓
name()   → returns Builder
  ↓
email()  → returns Builder
  ↓
age()    → returns Builder
```

This is called **method chaining / fluent API**.

---

# 5. What does `build()` do?

This is where the actual `User` object is created:

```java
public User build() {
    return new User(this);
}
```

So:

```text
new User.Builder()
       ↓
set values
       ↓
build()
       ↓
new User(...)
```

The client doesn't directly call the complex constructor.

---

# 6. Why are fields `final`?

In our example:

```java
private final String name;
private final String email;
```

Once the `User` object is created, those values cannot be changed.

This makes the object **immutable**.

Builder is frequently used to construct immutable objects.

Notice:

```java
User user = new User.Builder()
        .name("Veera")
        .age(28)
        .build();
```

After construction, there is no:

```java
user.setName(...)
```

So the `User` object's state remains unchanged.

---

# 7. Optional Parameters ⭐

This is where Builder is especially useful.

You can create:

```java
User user = new User.Builder()
        .name("Veera")
        .email("veera@gmail.com")
        .build();
```

No need to provide:

```text
age
city
active
```

They get their default values:

```text
age    → 0
city   → null
active → false
```

You can also provide only what you need:

```java
User user = new User.Builder()
        .name("Veera")
        .city("Chennai")
        .build();
```

# 8. Builder vs Factory

Since you just learned Factory:

### Factory

Answers:

> **Which object should I create?**

```java
Vehicle vehicle =
        VehicleFactory.createVehicle("car");
```

### Builder

Answers:

> **How should I construct/configure this object?**

```java
User user = new User.Builder()
        .name("Veera")
        .age(28)
        .city("Chennai")
        .build();
```

Remember:

```text
Factory → WHAT object to create
Builder → HOW to construct the object
```

They can also be used together.

# 9. Spring Boot Connection ⭐⭐⭐

Builder is very common in Java/Spring projects.

You'll often see:

```java
User user = User.builder()
        .name("Veera")
        .email("veera@gmail.com")
        .age(28)
        .build();
```

This syntax is commonly generated using **Lombok's `@Builder`**.

Example:

```java
import lombok.Builder;
import lombok.Getter;

@Getter
@Builder
public class User {

    private String name;
    private String email;
    private int age;
}
```

Then:

```java
User user = User.builder()
        .name("Veera")
        .email("veera@gmail.com")
        .age(28)
        .build();
```

You'll encounter this frequently in **Spring Boot DTOs, request/response objects and domain models**.

# Interview Answer

> **Builder Pattern is a creational design pattern used to construct complex objects step by step. It is particularly useful when an object has many optional parameters and helps avoid telescoping constructors.**

### Remember this

```text
Builder
   ↓
Complex object
   ↓
Build step-by-step
   ↓
Method chaining
   ↓
build()
   ↓
Final object
```

**Factory → chooses/creates the type.**
**Builder → configures and constructs the object.**
