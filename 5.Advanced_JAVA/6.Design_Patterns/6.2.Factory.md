## Design Pattern: Factory

**Factory Pattern** is a **Creational Design Pattern**.

### 1. What problem does Factory solve?

Suppose your application needs to create different types of objects:

```java
Car
Bike
Truck
```

Without Factory, your business code directly creates objects:

```java
Vehicle vehicle = new Car();
```

If object creation becomes complex or changes frequently, your business logic becomes tightly coupled to concrete classes.

**Factory moves object-creation logic into one place.**

Think of it like:

```text
Client
  ↓
VehicleFactory
  ↓
 ┌──────┬──────┬───────┐
 Car    Bike   Truck
```

---

# 2. Basic Example

### Step 1: Create interface

```java
interface Vehicle {
    void drive();
}
```

### Step 2: Create implementations

```java
class Car implements Vehicle {

    @Override
    public void drive() {
        System.out.println("Driving a car");
    }
}

class Bike implements Vehicle {

    @Override
    public void drive() {
        System.out.println("Riding a bike");
    }
}
```

### Step 3: Create Factory

```java
class VehicleFactory {

    public static Vehicle createVehicle(String type) {

        if (type.equalsIgnoreCase("car")) {
            return new Car();
        }

        if (type.equalsIgnoreCase("bike")) {
            return new Bike();
        }

        throw new IllegalArgumentException("Unknown vehicle type");
    }
}
```

### Step 4: Client

```java
public class Main {

    public static void main(String[] args) {

        Vehicle vehicle1 = VehicleFactory.createVehicle("car");
        vehicle1.drive();

        Vehicle vehicle2 = VehicleFactory.createVehicle("bike");
        vehicle2.drive();
    }
}
```

### Output

```text
Driving a car
Riding a bike
```

---

# 3. What exactly did Factory change?

### Without Factory

```java
Vehicle vehicle = new Car();
```

Client knows:

```text
Car
```

and directly creates it.

### With Factory

```java
Vehicle vehicle = VehicleFactory.createVehicle("car");
```

Client only knows:

```text
VehicleFactory
Vehicle
```

The Factory knows:

```text
Car
Bike
```

So **object creation is separated from object usage.**

---

# 4. Important Concept

Factory doesn't mean:

> "Never use `new`."

It means:

> **Centralize/encapsulate object creation when the creation logic or choice of implementation belongs in a separate component.**

For example:

```java
VehicleFactory.createVehicle("car");
```

internally still does:

```java
return new Car();
```

That's perfectly fine.

---

# 5. Why is this useful in Spring Boot?

This concept becomes especially important in Spring because Spring's **IoC container acts as an object creation and management mechanism**.

Instead of your code frequently doing:

```java
Service service = new Service();
```

Spring can create and manage the object:

```java
@Service
class OrderService {
}
```

and inject it:

```java
@Autowired
private OrderService orderService;
```

So understanding Factory helps you understand **IoC / Dependency Injection** later.

---

# 6. Factory vs Simple Factory vs Factory Method

These names are often confused.

### Simple Factory

One factory decides which object to create:

```text
VehicleFactory
     ↓
 Car / Bike / Truck
```

The example above is a **Simple Factory**.

### Factory Method

Creation is delegated to subclasses.

```text
VehicleCreator
      ↓
 ┌───────────────┐
CarCreator   BikeCreator
    ↓             ↓
   Car           Bike
```

Factory Method is a formal GoF design pattern.

### Abstract Factory

Creates **families of related objects**.

Example:

```text
WindowsFactory
 ├── WindowsButton
 └── WindowsCheckbox

MacFactory
 ├── MacButton
 └── MacCheckbox
```

## Interview Answer ⭐

If interviewer asks **"What is Factory Pattern?"**, you can say:

> **Factory is a creational design pattern that encapsulates object creation and allows the client to obtain an appropriate implementation without directly instantiating the concrete class. This reduces coupling between the client and concrete implementations.**

### Remember this

```text
Factory Pattern
       ↓
Encapsulate object creation
       ↓
Reduce coupling
       ↓
Client depends on interface
       ↓
Factory decides concrete implementation
```

For your **React → Java/Spring Boot** transition, the next useful topic after this is **Factory Method**, because that's where the difference between a Simple Factory and the actual GoF Factory Method becomes clear.
