# Design Patterns – Singleton

Since you're moving from **React → Java + Spring Boot**, Singleton is important because you'll encounter the concept directly in **Spring beans**.

## 1. What is Singleton?

**Singleton Pattern** ensures that a class has **only one object (instance)** throughout the application and provides a way to access that instance.

### Real-world example

Think of a **configuration manager**:

```text
Application
    |
    +----> ConfigurationManager
    |
    +----> ConfigurationManager
    |
    +----> ConfigurationManager

All references → SAME object
```

Instead of creating:

```java
new ConfigurationManager();
new ConfigurationManager();
new ConfigurationManager();
```

we ensure only **one instance** exists.

---

# 2. Basic Singleton Implementation

```java
class Singleton {

    // 1. Create the single instance
    private static Singleton instance;

    // 2. Private constructor
    private Singleton() {
    }

    // 3. Global access method
    public static Singleton getInstance() {

        if (instance == null) {
            instance = new Singleton();
        }

        return instance;
    }
}

public class Main {

    public static void main(String[] args) {

        Singleton obj1 = Singleton.getInstance();
        Singleton obj2 = Singleton.getInstance();

        System.out.println(obj1 == obj2);
    }
}
```

Output:

```text
true
```

Both variables point to the **same object**.

---

# 3. Why Private Constructor?

This is the most important part.

```java
private Singleton() {
}
```

Because of this, nobody can do:

```java
Singleton obj = new Singleton(); // ❌ Compile error
```

The only way to get the object is:

```java
Singleton.getInstance();
```

---

# 4. How Singleton Works

There are three important parts:

### ① Private static instance

```java
private static Singleton instance;
```

Stores the single object.

### ② Private constructor

```java
private Singleton() {}
```

Prevents external object creation.

### ③ Static `getInstance()`

```java
public static Singleton getInstance() {

    if (instance == null) {
        instance = new Singleton();
    }

    return instance;
}
```

Creates the object **only when required**.

This is called **lazy initialization**.

---

# 5. Problem with the Above Implementation

The basic implementation is **not thread-safe**.

Imagine two threads execute this simultaneously:

```text
Thread 1                  Thread 2

instance == null          instance == null
        ↓                         ↓
new Singleton()            new Singleton()
```

Now **two objects can be created**, violating Singleton.

This matters in backend applications because Java applications commonly use multiple threads.

---

# 6. Thread-Safe Singleton

One simple solution is `synchronized`:

```java
class Singleton {

    private static Singleton instance;

    private Singleton() {
    }

    public static synchronized Singleton getInstance() {

        if (instance == null) {
            instance = new Singleton();
        }

        return instance;
    }
}

public class Main {

    public static void main(String[] args) {

        Singleton obj1 = Singleton.getInstance();
        Singleton obj2 = Singleton.getInstance();

        System.out.println(obj1 == obj2); // true
    }
}
```

However, synchronizing the entire method can introduce unnecessary synchronization overhead.

---

# 7. Recommended Java Approach: `enum`

Java provides a very robust Singleton implementation using `enum`.

```java
enum Singleton {

    INSTANCE;

    public void showMessage() {
        System.out.println("Hello from Singleton");
    }
}

public class Main {

    public static void main(String[] args) {

        Singleton obj1 = Singleton.INSTANCE;
        Singleton obj2 = Singleton.INSTANCE;

        obj1.showMessage();

        System.out.println(obj1 == obj2);
    }
}
```

Output:

```text
Hello from Singleton
true
```

`enum` provides strong protection against several common issues such as serialization-related creation of another instance.

# 8. Singleton and Spring Boot ⭐

This is **very important for your Spring Boot learning**.

Spring beans are **singleton-scoped by default**.

For example:

```java
@Service
public class UserService {
}
```

When Spring manages this bean, the default scope is:

```text
Singleton
```

So when different components request `UserService`, Spring normally gives them the **same bean instance within that Spring ApplicationContext**.

Conceptually:

```text
Spring Container
       |
       ↓
   UserService
       ↑
       |
 ┌─────┴─────┐
 ↓           ↓
Controller   OtherService
```

Both receive the same Spring-managed instance.

### Important distinction

Don't say:

> "Every Spring bean is a Java Singleton."

More accurately:

> **Spring's default bean scope is singleton, meaning one bean instance per Spring IoC container/ApplicationContext.**

This is a **container-managed singleton**, not necessarily the classic GoF Singleton implementation.

# Interview Questions

### Q1. What is Singleton?

> A design pattern that ensures a class has only one instance and provides a global access point to that instance.

### Q2. Why make the constructor private?

> To prevent other classes from creating objects using `new`.

### Q3. What is lazy initialization?

> Creating the Singleton instance only when `getInstance()` is called for the first time.

### Q4. Is the basic Singleton thread-safe?

> No. Multiple threads can simultaneously observe `instance == null` and create multiple instances.

### Q5. How does Spring implement Singleton?

> Spring uses singleton as the default bean scope and manages the single bean instance inside the Spring IoC container.
