# Advanced Java — Concurrency

## 1. Synchronization

### What problem does synchronization solve?

When **multiple threads access and modify the same shared data at the same time**, you can get incorrect results due to a **race condition**.

Example:

```text
Thread 1 → counter++
Thread 2 → counter++
```

You might expect:

```text
counter = 2
```

But both threads can read the same old value and overwrite each other's update.

### What is synchronization?

**Synchronization ensures that only one thread at a time can execute a critical section for a shared resource.**

Think of it like:

```text
Thread 1 → 🔒 shared resource → update → 🔓
Thread 2 → waits ------------------------→ 🔒 → update → 🔓
```

---

## 2. `synchronized` method

A simple example:

```java
class Counter {

    private int count = 0;

    public synchronized void increment() {
        count++;
    }

    public int getCount() {
        return count;
    }
}

public class Main {

    public static void main(String[] args) throws InterruptedException {

        Counter counter = new Counter();

        Thread t1 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.increment();
            }
        });

        Thread t2 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.increment();
            }
        });

        t1.start();
        t2.start();

        t1.join();
        t2.join();

        System.out.println(counter.getCount());
    }
}
```

Output:

```text
2000
```

### Why `synchronized`?

Without:

```java
public synchronized void increment()
```

both threads can modify `count` simultaneously, potentially producing a value less than `2000`.

With `synchronized`, only one thread can execute `increment()` at a time.

# 3. Synchronized block

You don't always need to synchronize the entire method.

You can synchronize only the **critical section**:

```java
synchronized (this) {
    count++;
}
```

Example:

```java
class Counter {

    private int count = 0;

    public void increment() {

        // Other non-critical work

        synchronized (this) {
            count++;
        }
    }

    public int getCount() {
        return count;
    }
}
```

### Difference

```java
public synchronized void increment()
```

locks the entire method.

```java
synchronized (this) {
    count++;
}
```

locks only the required section.

**Interview point:** Smaller synchronized blocks can reduce unnecessary lock contention.

# 4. What is Producer-Consumer?

The **Producer-Consumer pattern** is one of the most important concurrency patterns.

There are two types of threads:

### Producer

Produces data/tasks and puts them into a shared queue.

```text
Producer
   ↓
[ Queue ]
   ↓
Consumer
```

### Consumer

Takes data/tasks from the queue and processes them.

Example:

```text
Producer → [Task 1]
           [Task 2]
           [Task 3] → Consumer
```

The problem is:

* What if the queue is **full**?
* What if the queue is **empty**?

We need threads to **wait safely** instead of continuously checking.

---

# 5. Modern Java approach: `BlockingQueue`

For real Java applications, `BlockingQueue` is usually preferred over manually implementing `wait()`/`notify()`.

It automatically handles:

* Thread safety
* Waiting when queue is empty
* Waiting when queue is full

Important methods:

```java
put()
```

Waits if queue is full.

```java
take()
```

Waits if queue is empty.

---

## Full Producer-Consumer Example

```java
import java.util.concurrent.ArrayBlockingQueue;
import java.util.concurrent.BlockingQueue;

public class Main {

    public static void main(String[] args) throws InterruptedException {

        BlockingQueue<Integer> queue = new ArrayBlockingQueue<>(3);

        Thread producer = new Thread(() -> {

            try {
                for (int i = 1; i <= 5; i++) {

                    System.out.println("Producing: " + i);

                    queue.put(i);

                    System.out.println("Produced: " + i);
                }

            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        });

        Thread consumer = new Thread(() -> {

            try {
                for (int i = 1; i <= 5; i++) {

                    int value = queue.take();

                    System.out.println("Consumed: " + value);

                    Thread.sleep(1000);
                }

            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        });

        producer.start();
        consumer.start();

        producer.join();
        consumer.join();

        System.out.println("Finished");
    }
}
```

### Flow

```text
Producer
   |
   | put(1)
   | put(2)
   | put(3)
   ↓
+-----------+
|   Queue   |  capacity = 3
+-----------+
   ↓
   | take()
Consumer
```

If the queue becomes full:

```java
queue.put(value);
```

**waits** until space becomes available.

If the queue is empty:

```java
queue.take();
```

**waits** until an item becomes available.

This is why `BlockingQueue` is extremely useful.

# 6. `wait()` / `notify()` — traditional approach

Before `BlockingQueue`, Producer-Consumer was commonly implemented using:

```java
wait();
notify();
```

Basic idea:

```text
Producer
   ↓
if queue full → wait()

Consumer
   ↓
if queue empty → wait()
```

When something changes:

```java
notify();
```

wakes a waiting thread.

Important rules:

* `wait()`, `notify()`, `notifyAll()` must be called while holding the object's monitor, typically inside `synchronized`.
* Prefer `while`, not `if`, when checking the condition.
* `wait()` releases the object's monitor while waiting.
* `Thread.sleep()` **does not release a lock**.

For modern application code, prefer `BlockingQueue` when it fits the problem.

---

# 7. `synchronized` vs `BlockingQueue`

| Concept         | Purpose                                          |
| --------------- | ------------------------------------------------ |
| `synchronized`  | Protect shared data/resource                     |
| `BlockingQueue` | Safely communicate between producer and consumer |
| `wait()`        | Make current thread wait                         |
| `notify()`      | Wake a waiting thread                            |
| `notifyAll()`   | Wake all waiting threads                         |
| `put()`         | Add to BlockingQueue, waits if full              |
| `take()`        | Remove from BlockingQueue, waits if empty        |

## Important interview understanding

### Synchronization

> **"Only one thread should access this critical section at a time."**

### Producer-Consumer

> **"One or more threads produce work, another thread consumes that work through a thread-safe queue."**

### Most important modern pattern

```text
Producer
   ↓
BlockingQueue
   ↓
Consumer
```

This pattern appears frequently in **Spring Boot backend systems**, such as background jobs, task processing, message handling, and worker-based processing.
