# Advanced Java — Executor Framework

## Subtopic: Thread Pools & Examples

Since you're moving from React to Spring Boot, **Thread Pools are very important**. In real Java backend applications, you generally **don't create a new `Thread` for every task**. Instead, you use an `ExecutorService` with a pool of reusable threads.

---

## 1. What is a Thread Pool?

A **thread pool** is a collection of reusable worker threads.

Instead of:

```text
Task 1 → create Thread → execute → destroy
Task 2 → create Thread → execute → destroy
Task 3 → create Thread → execute → destroy
```

we use:

```text
             Thread Pool
          ┌───────────────┐
Task 1 →  │ Worker Thread │
Task 2 →  │ Worker Thread │
Task 3 →  │ Worker Thread │
Task 4 →  │ Worker Thread │
          └───────────────┘
```

Threads are **created once and reused**.

### Why?

Creating threads repeatedly has overhead.

Thread pools provide:

* Thread reuse
* Better performance
* Control over number of concurrent threads
* Task queueing
* Easier concurrency management

---

# 2. `ExecutorService`

Java provides the Executor Framework through:

```java
java.util.concurrent
```

The most commonly used API is:

```java
ExecutorService
```

Example:

```java
ExecutorService executor =
        Executors.newFixedThreadPool(3);
```

This creates a pool containing **3 worker threads**.

---

# 3. Basic Thread Pool Example

```java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class Main {

    public static void main(String[] args) {

        ExecutorService executor =
                Executors.newFixedThreadPool(3);

        for (int i = 1; i <= 5; i++) {

            int taskNumber = i;

            executor.submit(() -> {

                System.out.println(
                    "Task " + taskNumber +
                    " running on " +
                    Thread.currentThread().getName()
                );
            });
        }

        executor.shutdown();
    }
}
```

Possible output:

```text
Task 1 running on pool-1-thread-1
Task 2 running on pool-1-thread-2
Task 3 running on pool-1-thread-3
Task 4 running on pool-1-thread-1
Task 5 running on pool-1-thread-2
```

Notice:

```text
3 threads
5 tasks
```

The threads are **reused**.

```text
Task 1 ──→ Thread 1
Task 2 ──→ Thread 2
Task 3 ──→ Thread 3
Task 4 ──→ Thread 1  ← reused
Task 5 ──→ Thread 2  ← reused
```

The exact assignment/order is not guaranteed.

---

# 4. `submit()` vs `execute()`

You will see both.

### `execute()`

```java
executor.execute(() -> {
    System.out.println("Hello");
});
```

Used when you don't need a result.

### `submit()`

```java
executor.submit(() -> {
    System.out.println("Hello");
});
```

Returns a `Future`.

So:

```text
execute()
   ↓
fire-and-forget task

submit()
   ↓
task + Future
```

# 5. Fixed Thread Pool

Most basic type:

```java
Executors.newFixedThreadPool(3)
```

Means:

> Maintain up to 3 worker threads.

Example:

```java
import java.util.concurrent.*;

public class Main {

    public static void main(String[] args) {

        ExecutorService executor =
                Executors.newFixedThreadPool(2);

        for (int i = 1; i <= 5; i++) {

            int task = i;

            executor.submit(() -> {

                System.out.println(
                    "Starting Task " + task
                );

                try {
                    Thread.sleep(1000);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }

                System.out.println(
                    "Finished Task " + task
                );
            });
        }

        executor.shutdown();
    }
}
```

Because there are only **2 threads**, approximately:

```text
Time 0s:
Thread-1 → Task 1
Thread-2 → Task 2

Time 1s:
Thread-1 → Task 3
Thread-2 → Task 4

Time 2s:
Thread-1 → Task 5
```

So 5 tasks don't mean 5 threads.

---

# 6. `shutdown()` — Very Important

After submitting tasks:

```java
executor.shutdown();
```

means:

> Stop accepting new tasks, but finish already submitted tasks.

Example:

```java
executor.submit(task1);
executor.submit(task2);

executor.shutdown();
```

`task1` and `task2` will still execute.

After shutdown:

```java
executor.submit(task3); // RejectedExecutionException
```

because the executor no longer accepts new tasks.

---

# 7. `shutdownNow()`

```java
executor.shutdownNow();
```

Attempts to stop currently running tasks and returns tasks that were waiting in the queue.

Important:

**It does not guarantee that running tasks instantly stop.**

A thread typically responds to interruption.

For example:

```java
try {
    Thread.sleep(5000);
} catch (InterruptedException e) {
    Thread.currentThread().interrupt();
}
```

# 8. Realistic Example — Processing API Requests

Imagine your Spring Boot application receives an order.

You need to perform several background operations:

```text
Order created
    │
    ├── Send email
    ├── Generate invoice
    ├── Update analytics
    └── Send notification
```

A thread pool can process these tasks.

```java
import java.util.concurrent.*;

public class Main {

    public static void main(String[] args) {

        ExecutorService executor =
                Executors.newFixedThreadPool(3);

        executor.submit(() -> sendEmail());

        executor.submit(() -> generateInvoice());

        executor.submit(() -> updateAnalytics());

        executor.submit(() -> sendNotification());

        executor.shutdown();
    }

    static void sendEmail() {
        System.out.println(
            "Sending email: " +
            Thread.currentThread().getName()
        );
    }

    static void generateInvoice() {
        System.out.println(
            "Generating invoice: " +
            Thread.currentThread().getName()
        );
    }

    static void updateAnalytics() {
        System.out.println(
            "Updating analytics: " +
            Thread.currentThread().getName()
        );
    }

    static void sendNotification() {
        System.out.println(
            "Sending notification: " +
            Thread.currentThread().getName()
        );
    }
}
```

This is conceptually similar to what you may encounter in backend systems.

# 9. `newCachedThreadPool()`

```java
ExecutorService executor =
        Executors.newCachedThreadPool();
```

It creates/reuses threads as needed and can create many threads when demand increases.

Good for:

* Many short-lived asynchronous tasks
* Variable workload

But be careful: it can create a large number of threads under heavy load.

For most application code, don't blindly choose it.

---

# 10. `newSingleThreadExecutor()`

```java
ExecutorService executor =
        Executors.newSingleThreadExecutor();
```

Only **one worker thread**.

```text
Task 1
  ↓
Task 2
  ↓
Task 3
  ↓
Task 4
```

Tasks execute sequentially.

Useful when you want:

> Multiple tasks, but only one at a time.

# 11. Thread Pool Types — Remember

| Executor                    | Threads | Typical use                 |
| --------------------------- | ------: | --------------------------- |
| `newFixedThreadPool(n)`     |   Fixed | Controlled concurrency      |
| `newSingleThreadExecutor()` |       1 | Sequential background tasks |
| `newCachedThreadPool()`     | Dynamic | Short-lived variable tasks  |
| `newScheduledThreadPool(n)` |   Fixed | Delayed/periodic tasks      |

# 12. Scheduled Thread Pool

Useful for delayed or periodic tasks.

```java
import java.util.concurrent.*;

public class Main {

    public static void main(String[] args) {

        ScheduledExecutorService executor =
                Executors.newScheduledThreadPool(2);

        executor.schedule(
            () -> System.out.println("Executed after 2 seconds"),
            2,
            TimeUnit.SECONDS
        );

        executor.scheduleAtFixedRate(
            () -> System.out.println("Running periodically"),
            1,
            3,
            TimeUnit.SECONDS
        );
    }
}
```

Methods to know:

```text
schedule()
        → execute once after delay

scheduleAtFixedRate()
        → execute periodically

scheduleWithFixedDelay()
        → wait fixed delay after previous execution
```

For this example, because the periodic task keeps running, you'd normally keep a reference and eventually call `shutdown()` when the application no longer needs it.

# 13. Very Important: `Future`

`submit()` can return a `Future`.

```java
import java.util.concurrent.*;

public class Main {

    public static void main(String[] args)
            throws Exception {

        ExecutorService executor =
                Executors.newFixedThreadPool(2);

        Future<Integer> future = executor.submit(() -> {

            Thread.sleep(1000);

            return 10 + 20;
        });

        System.out.println("Doing other work...");

        Integer result = future.get();

        System.out.println("Result = " + result);

        executor.shutdown();
    }
}
```

Output:

```text
Doing other work...
Result = 30
```

`Future` represents the **result of an asynchronous computation**.

Important methods:

```java
future.get();
future.isDone();
future.cancel(true);
```

### Important

```java
future.get();
```

is **blocking**.

The calling thread waits until the result is available.

# 14. Thread Pool Mental Model

This is the most important concept:

```text
                ExecutorService
                      │
              ┌───────┴───────┐
              ↓               ↓
         Worker Thread    Worker Thread
              │               │
              └───────┬───────┘
                      ↓
                 Task Queue
                ┌───────────┐
                │ Task 3    │
                │ Task 4    │
                │ Task 5    │
                └───────────┘
```

If you have:

```java
Executors.newFixedThreadPool(3)
```

and submit:

```text
10 tasks
```

you don't necessarily get 10 threads.

You have up to **3 worker threads** processing the queued tasks.

---

# 15. Why Thread Pools Matter in Spring Boot

In backend applications, you may have:

```text
1000 incoming requests
        ↓
Application
        ↓
Database calls
External APIs
File processing
Emails
Background tasks
```

Creating unlimited threads is dangerous.

Thread pools allow you to control concurrency:

```text
1000 tasks
    ↓
Thread Pool
    ↓
20 workers
    ↓
tasks processed in controlled batches
```

In Spring Boot, you'll commonly encounter:

* `@Async`
* `TaskExecutor`
* `ThreadPoolTaskExecutor`
* `CompletableFuture`
* scheduled tasks
* application server request threads

So understanding Java's `ExecutorService` is foundational.

# Interview Revision

### Why use Thread Pool?

> To reuse threads, reduce thread-creation overhead, control concurrency, and manage asynchronous tasks efficiently.

### `execute()` vs `submit()`?

```text
execute() → no result/Future
submit()  → returns Future
```

### `shutdown()`?

> Stops accepting new tasks but allows submitted tasks to complete.

### `shutdownNow()`?

> Attempts to stop running tasks via interruption and returns queued tasks.

### Fixed pool?

```java
Executors.newFixedThreadPool(5);
```

> Maximum of 5 worker threads.

### `Future.get()`?

> Retrieves the asynchronous result and blocks if it isn't ready.

### Most important mental model

```text
Task
 ↓
ExecutorService
 ↓
Thread Pool
 ↓
Worker Thread
 ↓
Execute Task
 ↓
Thread becomes available again
 ↓
Next Task
```
