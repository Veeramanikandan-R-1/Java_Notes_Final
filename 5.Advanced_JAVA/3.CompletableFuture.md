## Advanced Java — `CompletableFuture`

### Subtopic: Async Processing

Since you already know Java basics and are moving toward **Spring Boot**, focus on understanding **why async processing is useful**, how `CompletableFuture` works, and how to combine async tasks.

---

## 1. What is Async Processing?

Normally, Java executes code **sequentially**:

```text
Task A → wait → Task B → wait → Task C
```

With asynchronous processing:

```text
Task A ───────────────→ result
Task B ─────────→ result
Task C ───────→ result
```

Tasks can execute independently without blocking the current thread.

### Real-world Spring Boot example

Suppose an API needs:

```text
Get User
Get Orders
Get Recommendations
```

Sequential:

```text
User:            1 sec
Orders:          2 sec
Recommendations: 1 sec
----------------------
Total:           4 sec
```

If they are independent, async execution can reduce this to approximately:

```text
Maximum task time ≈ 2 sec
```

---

# 2. What is `CompletableFuture`?

`CompletableFuture<T>` represents a **future result of an asynchronous operation**.

Think of it as:

> "I don't have the result now, but I will give you the result later."

```java
CompletableFuture<String> future =
        CompletableFuture.supplyAsync(() -> "Hello");

System.out.println(future.join());
```

Output:

```text
Hello
```

### Important methods

| Method            | Purpose                         |
| ----------------- | ------------------------------- |
| `runAsync()`      | Async task with no return value |
| `supplyAsync()`   | Async task that returns a value |
| `thenApply()`     | Transform result                |
| `thenAccept()`    | Consume result                  |
| `thenRun()`       | Run something after completion  |
| `thenCombine()`   | Combine two independent futures |
| `allOf()`         | Wait for multiple futures       |
| `exceptionally()` | Handle exception                |
| `join()`          | Get result, unchecked exception |
| `get()`           | Get result, checked exception   |

---

# 3. `runAsync()` — No Return Value

Use when the task performs an action but doesn't return anything.

### Full working example

```java
import java.util.concurrent.CompletableFuture;

public class Main {

    public static void main(String[] args) {

        CompletableFuture<Void> future =
                CompletableFuture.runAsync(() -> {
                    System.out.println("Running async task...");
                });

        future.join();

        System.out.println("Main completed");
    }
}
```

Possible output:

```text
Running async task...
Main completed
```

`runAsync()` → `CompletableFuture<Void>`

---

# 4. `supplyAsync()` — Returns a Result

Use when the asynchronous task needs to return a value.

### Full working example

```java
import java.util.concurrent.CompletableFuture;

public class Main {

    public static void main(String[] args) {

        CompletableFuture<String> future =
                CompletableFuture.supplyAsync(() -> {

                    return "User data";

                });

        String result = future.join();

        System.out.println(result);
    }
}
```

Output:

```text
User data
```

### Remember

```java
runAsync()    → no result
supplyAsync() → returns result
```

---

# 5. `thenApply()` — Process the Result

This is similar to Java Stream's `map()`.

```text
Async Task
    ↓
Result
    ↓
thenApply()
    ↓
New Result
```

### Example

```java
import java.util.concurrent.CompletableFuture;

public class Main {

    public static void main(String[] args) {

        CompletableFuture<String> future =
                CompletableFuture
                        .supplyAsync(() -> "veeramanikandan")
                        .thenApply(name -> name.toUpperCase());

        System.out.println(future.join());
    }
}
```

Output:

```text
VEERAMANIKANDAN
```

Here:

```java
supplyAsync()
```

produces:

```text
veeramanikandan
```

Then:

```java
thenApply()
```

transforms it into:

```text
VEERAMANIKANDAN
```

---

# 6. `thenAccept()` — Consume the Result

Use when you want to **use the result but don't need to return another result**.

```java
import java.util.concurrent.CompletableFuture;

public class Main {

    public static void main(String[] args) {

        CompletableFuture
                .supplyAsync(() -> "User loaded")
                .thenAccept(result ->
                        System.out.println(result)
                )
                .join();
    }
}
```

Output:

```text
User loaded
```

Difference:

```text
thenApply()  → returns another CompletableFuture<T>
thenAccept() → returns CompletableFuture<Void>
```

---

# 7. `thenRun()` — Run After Completion

If you don't care about the previous result:

```java
import java.util.concurrent.CompletableFuture;

public class Main {

    public static void main(String[] args) {

        CompletableFuture
                .supplyAsync(() -> "Data loaded")
                .thenRun(() ->
                        System.out.println("Task completed")
                )
                .join();
    }
}
```

Output:

```text
Task completed
```

The result `"Data loaded"` is not passed to `thenRun()`.

---

# 8. Most Important — Combining Async Tasks

Suppose:

```text
Get User       → 1 second
Get Orders     → 2 seconds
```

These are independent.

We can run both asynchronously.

### Full working example

```java
import java.util.concurrent.CompletableFuture;

public class Main {

    static String getUser() {
        sleep(1000);
        return "User: John";
    }

    static String getOrders() {
        sleep(2000);
        return "Orders: 5";
    }

    static void sleep(long milliseconds) {
        try {
            Thread.sleep(milliseconds);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }

    public static void main(String[] args) {

        CompletableFuture<String> userFuture =
                CompletableFuture.supplyAsync(Main::getUser);

        CompletableFuture<String> orderFuture =
                CompletableFuture.supplyAsync(Main::getOrders);

        CompletableFuture<String> result =
                userFuture.thenCombine(
                        orderFuture,
                        (user, orders) -> user + ", " + orders
                );

        System.out.println(result.join());
    }
}
```

Output:

```text
User: John, Orders: 5
```

### Execution

Instead of:

```text
getUser()
    ↓
getOrders()
    ↓
Total ≈ 3 seconds
```

they can execute concurrently:

```text
getUser()   ───── 1 sec ────┐
                            ├── combine
getOrders() ───── 2 sec ────┘

Total ≈ 2 seconds
```

This pattern is **very important in backend development**.

# 9. `allOf()` — Wait for Multiple Tasks

Suppose you have:

```text
Task 1
Task 2
Task 3
Task 4
```

You want to wait until **all complete**.

```java
import java.util.concurrent.CompletableFuture;

public class Main {

    public static void main(String[] args) {

        CompletableFuture<String> f1 =
                CompletableFuture.supplyAsync(() -> "User");

        CompletableFuture<String> f2 =
                CompletableFuture.supplyAsync(() -> "Orders");

        CompletableFuture<String> f3 =
                CompletableFuture.supplyAsync(() -> "Products");

        CompletableFuture<Void> all =
                CompletableFuture.allOf(f1, f2, f3);

        all.join();

        System.out.println(f1.join());
        System.out.println(f2.join());
        System.out.println(f3.join());
    }
}
```

Output:

```text
User
Orders
Products
```

### Important

`allOf()` returns:

```java
CompletableFuture<Void>
```

It tells you:

> "All tasks are completed."

It doesn't automatically give you a `List` of results.

# 10. Exception Handling

Async tasks can fail.

Use `exceptionally()`:

```java
import java.util.concurrent.CompletableFuture;

public class Main {

    public static void main(String[] args) {

        CompletableFuture<String> future =
                CompletableFuture
                        .supplyAsync(() -> {

                            throw new RuntimeException("Database error");

                        })
                        .exceptionally(error -> {
                            System.out.println("Error: " + error.getMessage());
                            return "Fallback data";
                        });

        System.out.println(future.join());
    }
}
```

Output:

```text
Error: java.lang.RuntimeException: Database error
Fallback data
```

This is particularly useful for **fallback handling in Spring Boot services**.

---

# 11. `join()` vs `get()`

Both wait for the result.

### `get()`

```java
future.get();
```

Throws checked exceptions:

```text
InterruptedException
ExecutionException
```

### `join()`

```java
future.join();
```

Throws unchecked:

```text
CompletionException
```

For modern `CompletableFuture` code, you'll frequently see:

```java
future.join();
```

---

# 12. Which Thread Executes the Async Task?

By default:

```java
CompletableFuture.supplyAsync(...)
```

uses Java's:

```text
ForkJoinPool.commonPool()
```

Example:

```java
CompletableFuture.supplyAsync(() -> {
    System.out.println(Thread.currentThread().getName());
    return "Done";
}).join();
```

You may see something like:

```text
ForkJoinPool.commonPool-worker-1
```

The main thread doesn't necessarily execute the async task.

---

# 13. Custom Thread Pool

In real backend applications, you often don't want every task using the common pool.

You can provide an `Executor`.

```java
import java.util.concurrent.*;

public class Main {

    public static void main(String[] args) {

        ExecutorService executor =
                Executors.newFixedThreadPool(3);

        CompletableFuture<String> future =
                CompletableFuture.supplyAsync(() -> {

                    System.out.println(
                            Thread.currentThread().getName()
                    );

                    return "Data loaded";

                }, executor);

        System.out.println(future.join());

        executor.shutdown();
    }
}
```

Now the task uses your custom thread pool.

In **Spring Boot**, this concept maps to configuring a managed `Executor`/`ThreadPoolTaskExecutor`.

---

# 14. Important: Async ≠ Parallel Always

This distinction is important.

**Async** means:

> The caller doesn't have to wait synchronously for the task to finish.

**Parallel/concurrent execution** means:

> Multiple tasks can execute at the same time.

`CompletableFuture` can help achieve concurrent execution, but simply using `CompletableFuture` does not automatically make every operation parallel.

---

# 15. Spring Boot Connection

A common Spring Boot service might look conceptually like:

```java
@Async
public CompletableFuture<User> getUser() {
    // database/API call
}
```

Then:

```java
CompletableFuture<User> user = getUser();
CompletableFuture<Order> orders = getOrders();
```

The controller/service can combine the results.

Spring's `@Async` is built around asynchronous execution, while `CompletableFuture` provides the API for composing and handling those asynchronous results.

# Quick Revision

```text
CompletableFuture
        │
        ├── runAsync()       → no return value
        │
        ├── supplyAsync()    → returns value
        │
        ├── thenApply()      → transform result
        │
        ├── thenAccept()     → consume result
        │
        ├── thenRun()        → run after completion
        │
        ├── thenCombine()    → combine 2 futures
        │
        ├── allOf()          → wait for multiple futures
        │
        ├── exceptionally()  → handle failure
        │
        ├── join()           → get result
        │
        └── get()            → get result
```

### Most important for Spring Boot interviews

Remember these **5 patterns** first:

```java
CompletableFuture.supplyAsync(...)
```

```java
future.thenApply(...)
```

```java
future.thenAccept(...)
```

```java
future1.thenCombine(future2, ...)
```

```java
CompletableFuture.allOf(...)
```

**Mental model:**

```text
supplyAsync()
      ↓
 CompletableFuture<T>
      ↓
 thenApply() / thenAccept()
      ↓
 combine / allOf
      ↓
 join()
```

This is the foundation you need before moving into **`CompletableFuture` chaining, `thenCompose()`, exception handling, custom executors, and Spring Boot `@Async`**.
