# Time and Space Complexity in DSA

## 1. What is complexity?

Complexity helps us measure how efficient an algorithm is as the input size \\(n\\) increases.

- Time complexity: How the number of operations grows with input size.
- Space complexity: How the memory usage grows with input size.

We use Big O notation — \\(O(...)\\) to describe the upper-bound growth rate, commonly used to analyze worst-case performance.

## 2. Common time complexities

| Complexity       | Name         | Example                          |
| ---------------- | ------------ | -------------------------------- |
| \\(O(1)\\)       | Constant     | Access an array element by index |
| \\(O(\log n)\\)  | Logarithmic  | Binary search                    |
| \\(O(n)\\)       | Linear       | Traverse an array                |
| \\(O(n\log n)\\) | Linearithmic | Merge sort                       |
| \\(O(n^2)\\)     | Quadratic    | Two nested loops over an array   |
| \\(O(2^n)\\)     | Exponential  | Basic recursive Fibonacci        |
| \\(O(n!)\\)      | Factorial    | Generate all permutations        |

As input size grows, lower complexity is generally more efficient, though actual performance also depends on constants and implementation.

## 3. Understand complexity with Java code

### Example A: \\(O(1)\\) — Constant time

```
public class Main {
    public static void main(String[] args) {
        int[] arr = {10, 20, 30, 40, 50};
        System.out.println(arr[2]); // 30
    }
}
```

Accessing an array element by index takes constant time, regardless of array size.

### Example B: \\(O(n)\\) — Linear time

```
public class Main {
    public static void main(String[] args) {
        int[] arr = {10, 20, 30, 40, 50};

        for (int value : arr) {
            System.out.println(value);
        }
    }
}
```

The loop processes every element once. If there are \\(n\\) elements, it runs \\(n\\) times.

### Example C: \\(O(n^2)\\) — Quadratic time

```
public class Main {
    public static void main(String[] args) {
        int[] arr = {10, 20, 30};

        for (int i = 0; i < arr.length; i++) {
            for (int j = 0; j < arr.length; j++) {
                System.out.println(arr[i] + ", " + arr[j]);
            }
        }
    }
}
```

The outer loop runs \\(n\\) times, and the inner loop runs \\(n\\) times for each outer iteration.

Total operations: \\(n \times n = n^2\\).

## 4. How to calculate time complexity

Use these rules when analyzing code:

- A single basic operation: \\(O(1)\\).
- A loop running \\(n\\) times: \\(O(n)\\).
- Nested loops, each running \\(n\\) times: \\(O(n^2)\\).
- Consecutive loops: add their complexities, then keep the dominant term.
- A loop that repeatedly halves or doubles its controlling value: often \\(O(\log n)\\).

Example of consecutive loops:

```
for (int i = 0; i < n; i++) {
    System.out.println(i);
}

for (int i = 0; i < n; i++) {
    System.out.println(i);
}
```

Total: \\(O(n+n)=O(2n)=O(n)\\).

Important: Ignore constant multipliers and lower-order terms. For example, \\(O(n^2+3n+10)\\) simplifies to \\(O(n^2)\\).&#x20;

## 5. Space complexity

Space complexity measures how memory usage grows with input size. In DSA, pay special attention to auxiliary space — extra memory used by the algorithm beyond the input itself.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://jhu-dsa.github.io\&sz=32)

JHU DSA+1



### Example A: \\(O(1)\\) auxiliary space

```
static int sum(int[] arr) {
    int total = 0;

    for (int value : arr) {
        total += value;
    }

    return total;
}
```

Only one extra variable, `total`, is used regardless of array size.

- Time: \\(O(n)\\)
- Auxiliary space: \\(O(1)\\)

### Example B: \\(O(n)\\) auxiliary space

```
static int[] copyArray(int[] arr) {
    int[] copy = new int[arr.length];

    for (int i = 0; i < arr.length; i++) {
        copy[i] = arr[i];
    }

    return copy;
}
```

A new array of size \\(n\\) is created.

- Time: \\(O(n)\\)
- Auxiliary space: \\(O(n)\\)

## 6. Best, average and worst cases

Consider linear search for a target element.

| Case    | Situation                        | Time complexity |
| ------- | -------------------------------- | --------------- |
| Best    | Target is the first element      | \\(O(1)\\)      |
| Average | Target is somewhere in the array | \\(O(n)\\)      |
| Worst   | Target is last or absent         | \\(O(n)\\)      |

In interviews, state the case you are analyzing. Big O is an upper-bound notation; it is commonly used to express worst-case complexity, but it can also describe other cases.&#x20;

## 7. Quick interview revision

| Question                                   | Answer                                                |
| ------------------------------------------ | ----------------------------------------------------- |
| Why do we analyze complexity?              | To compare algorithm efficiency as input grows.       |
| Does \\(O(1)\\) mean one second?           | No, it means constant growth.                         |
| Two consecutive \\(O(n)\\) loops?          | \\(O(n)\\)                                            |
| Two nested \\(O(n)\\) loops?               | \\(O(n^2)\\)                                          |
| One loop plus a new array of size \\(n\\)? | Often \\(O(n)\\) time and \\(O(n)\\) auxiliary space. |
| Recursive calls consume memory?            | Yes, active call stack frames use memory.             |

Algorithm is a step-by-step set of instructions to solve a problem or perform a task.

Example: Find the largest number in an array

1. Assume the first element is the largest.
2. Compare it with every remaining element.
3. If a larger element is found, update the largest value.
4. Return the largest value.

Java example:

```
int[] arr = {10, 30, 20};
int max = arr[0];

for (int i = 1; i < arr.length; i++) {
    if (arr[i] > max) {
        max = arr[i];
    }
}

System.out.println(max); // 30
```

Key points:

- An algorithm defines the steps to solve a problem.
- Time complexity measures how its execution grows with input size.
- Space complexity measures how its memory usage grows.

Remember: Algorithm = Steps to solve a problem.

## Big O Complexity Chart

Big O describes how an algorithm's time or space requirements grow as input size \\(n\\) increases.

| Big O            | Name         | Example                   | Performance            |
| ---------------- | ------------ | ------------------------- | ---------------------- |
| \\(O(1)\\)       | Constant     | Array index access        | Excellent              |
| \\(O(\log n)\\)  | Logarithmic  | Binary search             | Very good              |
| \\(O(n)\\)       | Linear       | Linear search             | Good                   |
| \\(O(n\log n)\\) | Linearithmic | Merge sort                | Moderate               |
| \\(O(n^2)\\)     | Quadratic    | Two nested loops          | Slow for large \\(n\\) |
| \\(O(n^3)\\)     | Cubic        | Three nested loops        | Slower                 |
| \\(O(2^n)\\)     | Exponential  | Basic recursive Fibonacci | Very slow              |
| \\(O(n!)\\)      | Factorial    | Generate all permutations | Extremely slow         |

### Complexity growth comparison

| Input size \\(n\\) | \\(O(1)\\) | \\(O(\log_2 n)\\) | \\(O(n)\\) | \\(O(n\log_2 n)\\) | \\(O(n^2)\\) |
| ------------------ | ---------- | ----------------- | ---------- | ------------------ | ------------ |
| 10                 | 1          | 3.3               | 10         | 33                 | 100          |
| 100                | 1          | 6.6               | 100        | 664                | 10,000       |
| 1,000              | 1          | 10                | 1,000      | 9,966              | 1,000,000    |
| 10,000             | 1          | 13.3              | 10,000     | 132,877            | 100,000,000  |

Values show approximate growth rates, not actual execution times. Logarithms use base 2.

### Remember this order

From generally most efficient to least efficient:

\\[ O(1) < O(\log n) < O(n) < O(n\log n) < O(n^2) < O(n^3) < O(2^n) < O(n!) \\]

DSA interview tip: Focus first on recognizing \\(O(1)\\), \\(O(\log n)\\), \\(O(n)\\), \\(O(n\log n)\\), and \\(O(n^2)\\). These appear frequently in array, searching, sorting, and interview problems.
