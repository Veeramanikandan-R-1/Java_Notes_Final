## Binary Search in a Sorted Array

Definition: Binary search finds a target element by repeatedly dividing the search range into half. The array must be sorted.

### Java code

```
public class Main {
    public static void main(String[] args) {
        int[] arr = {10, 20, 30, 40, 50, 60, 70};
        int target = 50;

        int low = 0;
        int high = arr.length - 1;
        int result = -1;

        while (low <= high) {
            int mid = low + (high - low) / 2;

            if (arr[mid] == target) {
                result = mid;
                break;
            } else if (arr[mid] < target) {
                low = mid + 1;
            } else {
                high = mid - 1;
            }
        }

        System.out.println(result == -1
                ? "Not found"
                : "Found at index: " + result);
    }
}
```

Output: `Found at index: 4`

### How it works

Array: `{10, 20, 30, 40, 50, 60, 70}`, target: `50`

1. First iteration
   - `low = 0`, `high = 6`
   - `mid = 3`, so `arr[mid] = 40`.
   - Since `40 < 50`, ignore the left half and set `low = mid + 1 = 4`.
2. Second iteration
   - `low = 4`, `high = 6`
   - `mid = 5`, so `arr[mid] = 60`.
   - Since `60 > 50`, ignore the right half and set `high = mid - 1 = 4`.
3. Third iteration
   - `low = 4`, `high = 4`
   - `mid = 4`, so `arr[mid] = 50`.
   - Target found at index `4`.

### Important variables

- `low`: Starting index of the current search range.
- `high`: Ending index of the current search range.
- `mid`: Middle index of the current search range.
- `low <= high`: Continue while the search range is valid.

### Time and space complexity

- Best case: \\(O(1)\\) — target is at the middle initially.
- Average and worst case: \\(O(\log n)\\).
- Space complexity: \\(O(1)\\) — iterative implementation uses constant extra memory.

Remember: Linear search checks elements one by one; binary search eliminates half the remaining search range at each step.

---

Both formulas calculate the middle index, but `low + (high - low) / 2` is safer because it avoids integer overflow.

### 1. Normal formula

```
int mid = (low + high) / 2;
```

If `low + high` exceeds Java's maximum `int` value (`2,147,483,647`), integer overflow can occur, producing an incorrect result.

### 2. Safer formula

```
int mid = low + (high - low) / 2;
```

Here, we calculate the distance between `high` and `low`, divide it by two, and add it to `low`.

For example, if `low = 4` and `high = 10`:

- `(high - low) / 2 = (10 - 4) / 2 = 3`
- `mid = 4 + 3 = 7`

Both formulas give `7` in this case.

### Interview takeaway

- `(low + high) / 2` — simpler, but can overflow.
- `low + (high - low) / 2` — preferred because it avoids overflow for valid non-negative array indices.

Remember: Use the second formula in binary search as a good coding practice.

Note:

## Integer Overflow Example in Java

Java `int` maximum value is 2,147,483,647.

When an integer calculation exceeds this limit, it wraps around to a negative value instead of throwing an exception.

### Example

```
public class Main {
    public static void main(String[] args) {
        int low = 2_000_000_000;
        int high = 2_100_000_000;

        int mid1 = (low + high) / 2;
        int mid2 = low + (high - low) / 2;

        System.out.println("Normal formula: " + mid1);
        System.out.println("Safe formula: " + mid2);
    }
}
```

Output:

```
Normal formula: -97...
Safe formula: 2050000000
```

The exact first output is `-97483648`.

### Why does this happen?

Normal formula:

```
int mid = (low + high) / 2;
```

- `low + high = 4,100,000,000`
- This exceeds the maximum `int` value.
- Integer overflow produces `-194967296`.
- Dividing by `2` gives `-97483648`, an incorrect middle index.

Safe formula:

```
int mid = low + (high - low) / 2;
```

- `high - low = 100,000,000`
- `100,000,000 / 2 = 50,000,000`
- `2,000,000,000 + 50,000,000 = 2,050,000,000`

The result is correct.

Remember: Use `low + (high - low) / 2` in binary search to avoid overflow when calculating the midpoint.

## Binary Search Using Recursion (Java)

Definition: Recursive binary search finds a target in a sorted array by checking the middle element and calling the same method on either the left or right half.

### 1. Full working Java code

```
class Main {

    public static int binarySearch(int[] arr, int target,
                                   int low, int high) {

        // Base case: target not found
        if (low > high) {
            return -1;
        }

        int mid = low + (high - low) / 2;

        if (arr[mid] == target) {
            return mid;
        } else if (arr[mid] < target) {
            return binarySearch(arr, target, mid + 1, high);
        } else {
            return binarySearch(arr, target, low, mid - 1);
        }
    }

    public static void main(String[] args) {
        int[] arr = {10, 20, 30, 40, 50, 60, 70};
        int target = 50;

        int result = binarySearch(arr, target, 0, arr.length - 1);

        System.out.println(result == -1
                ? "Not found"
                : "Found at index: " + result);
    }
}
```

Output:

```
Found at index: 4
```

### 2. How it works

For `arr = {10, 20, 30, 40, 50, 60, 70}` and `target = 50`:

1. `low = 0`, `high = 6`; middle element is `40`. Since `40 < 50`, recursively search the right half.
2. `low = 4`, `high = 6`; middle element is `60`. Since `60 > 50`, recursively search the left half.
3. `low = 4`, `high = 4`; middle element is `50`. Return index `4`.

### 3. Important concepts

- Base case: `low > high` means the target does not exist in the remaining range; return `-1`.
- Recursive case: Call `binarySearch()` again with a smaller search range.
- Return value: Each recursive call passes its result back to the previous call.

### 4. Complexity

| Complexity              | Value                                       |
| ----------------------- | ------------------------------------------- |
| Best-case time          | \\(O(1)\\)                                  |
| Average/worst-case time | \\(O(\log n)\\)                             |
| Auxiliary space         | \\(O(\log n)\\) due to recursive call stack |

Interview tip: Iterative binary search uses \\(O(1)\\) auxiliary space, while recursive binary search uses \\(O(\log n)\\) because each recursive call occupies stack memory.
