In Spring Core (without Spring Boot), we can perform Field Injection and Constructor Injection using XML configuration with the `applicationContext.xml` file.

Let's use a simple `Student` and `StudentService` example.

## 1. Project structure

```
spring-core-practice/
├── pom.xml
└── src/main/
    ├── java/com/example/
    │   ├── Student.java
    │   ├── StudentService.java
    │   └── Main.java
    └── resources/
        └── applicationContext.xml
```

## 2. Student.java

```
package com.example;

public class Student {

    public void display() {
        System.out.println("Student details displayed");
    }
}
```

## 3. StudentService.java

We will demonstrate both injection types in this class.

A. Constructor Injection

```
package com.example;

public class StudentService {

    private Student student;

    // Constructor injection
    public StudentService(Student student) {
        this.student = student;
    }

    public void getStudentDetails() {
        student.display();
    }
}
```

B. Field Injection

For field injection, we need a no-argument constructor and a setter is not required.

```
package com.example;

public class StudentService {

    private Student student;

    public void getStudentDetails() {
        student.display();
    }
}
```

We will inject the `student` field directly using XML.

## 4. applicationContext.xml

Constructor Injection

```
<?xml version="1.0" encoding="UTF-8"?>

<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:schemaLocation="
       http://www.springframework.org/schema/beans
       https://www.springframework.org/schema/beans/spring-beans.xsd">

    <!-- Student Bean -->
    <bean id="student" class="com.example.Student"/>

    <!-- Constructor Injection -->
    <bean id="studentService"
          class="com.example.StudentService">

        <constructor-arg ref="student"/>

    </bean>

</beans>
```

How it works:

- `student` bean creates the Student object.
- `constructor-arg` passes the Student bean to the StudentService constructor.
- Spring automatically injects the dependency.

Field Injection

For field injection, replace the `studentService` bean configuration with:

```
<bean id="studentService"
      class="com.example.StudentService">

    <property name="student" ref="student"/>

</bean>
```

Important: XML's `<property>` element performs setter-based injection by default, not direct field injection.

To inject directly into a private field without a setter, use Spring's `MethodInvokingFactoryBean` or another supported field-injection mechanism. For practical XML configuration, setter injection is the standard approach.

Here is the recommended setter-based version:

```
public class StudentService {

    private Student student;

    public void setStudent(Student student) {
        this.student = student;
    }

    public void getStudentDetails() {
        student.display();
    }
}
```

## 5. Main.java

```
package com.example;

import org.springframework.context.ApplicationContext;
import org.springframework.context.support.ClassPathXmlApplicationContext;

public class Main {

    public static void main(String[] args) {

        ApplicationContext context =
            new ClassPathXmlApplicationContext("applicationContext.xml");

        StudentService service =
            context.getBean("studentService", StudentService.class);

        service.getStudentDetails();

        ((ClassPathXmlApplicationContext) context).close();
    }
}
```

## 6. Output

```
Student details displayed
```

## 7. Constructor vs Field vs Setter Injection

| Feature                 | Constructor       | Field                   | Setter                    |
| ----------------------- | ----------------- | ----------------------- | ------------------------- |
| XML configuration       | `constructor-arg` | Special field injection | `property`                |
| Requires constructor    | Yes               | No                      | No                        |
| Requires setter         | No                | No                      | Yes                       |
| Supports `final` fields | Yes               | No                      | No                        |
| Recommended             | Yes               | Generally avoid         | For optional dependencies |

Important interview point:

Spring XML's `<property>` means setter injection. It does not mean direct field injection.

My recommendation: Practise constructor injection first. It makes dependencies explicit, supports immutable fields and is the preferred approach in modern Spring applications.

### Autowiring in Spring XML Configuration

Autowiring means Spring automatically identifies and injects the required dependency without explicitly configuring every dependency using `constructor-arg` or `property`.

Spring XML supports different autowiring modes.

## 1. Types of Autowiring

| Mode          | Description                                             |
| ------------- | ------------------------------------------------------- |
| `no`          | Default. No automatic injection.                        |
| `byName`      | Matches dependency using the property name and Bean ID. |
| `byType`      | Matches dependency using the Java class type.           |
| `constructor` | Matches dependencies using constructor parameter types. |

## 2. Example

Student.java

```
package com.example;

public class Student {
    public void display() {
        System.out.println("Student details displayed");
    }
}
```

StudentService.java

```
package com.example;

public class StudentService {

    private Student student;

    public void setStudent(Student student) {
        this.student = student;
    }

    public void getDetails() {
        student.display();
    }
}
```

## 3. Autowiring using XML

A. byName

```
<bean id="student" class="com.example.Student"/>

<bean id="studentService"
      class="com.example.StudentService"
      autowire="byName"/>
```

Spring looks for a Bean named `student` because the property name is `student`.

B. byType

```
<bean id="student" class="com.example.Student"/>

<bean id="studentService"
      class="com.example.StudentService"
      autowire="byType"/>
```

Spring identifies the dependency using the `Student` type.

If multiple Student Beans exist, Spring cannot resolve the ambiguity automatically.

C. constructor

```
public class StudentService {

    private Student student;

    public StudentService(Student student) {
        this.student = student;
    }
}
```

XML:

```
<bean id="student" class="com.example.Student"/>

<bean id="studentService"
      class="com.example.StudentService"
      autowire="constructor"/>
```

Spring resolves the constructor dependency using its type.

## 4. Explicit Injection vs Autowiring

| Explicit Injection                   | Autowiring                     |
| ------------------------------------ | ------------------------------ |
| Manually specify dependencies        | Spring identifies dependencies |
| Uses `constructor-arg` or `property` | Uses `autowire` attribute      |
| More configuration                   | Less configuration             |

In short:

- `constructor-arg` → Manually inject through constructor.
- `property` → Manually inject through setter.
- `autowire="byName"` → Match by Bean name.
- `autowire="byType"` → Match by Java type.
- `autowire="constructor"` → Match constructor parameters.

Interview point: XML autowiring and annotation-based `@Autowired` are two different ways of performing dependency injection in Spring.
