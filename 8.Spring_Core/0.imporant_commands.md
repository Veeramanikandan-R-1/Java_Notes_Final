## 1. When to use Maven commands

Think of the Maven build lifecycle as:

Clean → Compile → Test → Package → Install → Run

| Command             | When to use                                          | What it does                                      |
| ------------------- | ---------------------------------------------------- | ------------------------------------------------- |
| `mvn clean`         | Before a fresh build                                 | Deletes the `target/` directory                   |
| `mvn compile`       | After changing Java code                             | Compiles main source files                        |
| `mvn clean compile` | When you want a fresh compilation                    | Deletes old build files and compiles again        |
| `mvn test`          | After writing tests                                  | Compiles and executes unit tests                  |
| `mvn package`       | When you need a deployable artifact                  | Creates JAR/WAR inside `target/`                  |
| `mvn install`       | When another local Maven project needs your artifact | Installs the JAR into your local Maven repository |
| `mvn clean install` | For a fresh complete build                           | Cleans, compiles, tests, packages and installs    |
| `mvn verify`        | Before releasing or sharing a build                  | Runs checks through the verify phase              |

### Your three commands

1\. `mvn clean compile`

Use when:

- You modify Java code.
- You want to remove old compiled files and compile everything again.

2\. `mvn clean install`

Use when:

- You want a complete build.
- You want to run tests and package the application.
- You want to install the artifact into your local Maven repository (`~/.m2/repository`).

3\. Run the application

```
mvn exec:java -Dexec.mainClass="com.example.Main" -Dexec.classpathScope=compile
```

Use when:

- You want to execute your Java main class using Maven.
- You have configured the `exec-maven-plugin` in `pom.xml`.

This command does not automatically perform a fresh compile. Run `mvn compile` first after source changes.

## 2. Other important Maven commands

### Project and dependency commands

| Command                               | Purpose                                       |
| ------------------------------------- | --------------------------------------------- |
| `mvn validate`                        | Validates project structure and configuration |
| `mvn dependency:tree`                 | Displays dependency hierarchy                 |
| `mvn dependency:resolve`              | Downloads/resolves dependencies               |
| `mvn help:effective-pom`              | Displays the final effective POM              |
| `mvn help:describe -Dplugin=compiler` | Displays plugin information                   |

### Testing commands

| Command                       | Purpose                                 |
| ----------------------------- | --------------------------------------- |
| `mvn test`                    | Runs all unit tests                     |
| `mvn test -Dtest=StudentTest` | Runs a specific test class              |
| `mvn test -DskipTests`        | Skips test execution but compiles tests |
| `mvn package -DskipTests`     | Packages without executing tests        |
| `mvn install -DskipTests`     | Installs without executing tests        |

### Build and execution commands

| Command             | Purpose                                           |
| ------------------- | ------------------------------------------------- |
| `mvn clean package` | Freshly creates JAR/WAR                           |
| `mvn clean verify`  | Performs a fresh build and verification           |
| `mvn exec:java`     | Executes Java main class (with plugin configured) |
| `mvn -q compile`    | Compiles with minimal Maven output                |
| `mvn -X compile`    | Runs with detailed debug logs                     |

### Dependency and configuration commands

| Command                         | Purpose                                            |
| ------------------------------- | -------------------------------------------------- |
| `mvn -U clean install`          | Forces checking for updated snapshots and releases |
| `mvn -o clean install`          | Runs in offline mode                               |
| `mvn -f custom-pom.xml install` | Uses a specific POM file                           |
| `mvn -version`                  | Displays Maven version and Java version            |

## 3. Understand Maven build lifecycle

Maven has three main built-in lifecycles:

1\. Clean lifecycle

Removes old build output

`pre-clean → clean → post-clean`

2\. Default lifecycle

Build and deployment

1. validate
2. compile
3. test
4. package
5. verify
6. install
7. deploy

3\. Site lifecycle

Project documentation

`pre-site → site → post-site → site-deploy`

Important: Running a later phase automatically executes the earlier phases in that lifecycle.

For example:

```
mvn install
```

Automatically executes validate, compile, test, package, verify and install.

For your Spring Core, Hibernate and JDBC practice:

| ------------------------------ | --------------------------------------------------- |
| Compile code                   | `mvn compile`                                       |
| Run tests                      | `mvn test`                                          |
