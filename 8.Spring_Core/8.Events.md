## Spring Application Events

Since you're learning Spring Boot for a **React + Spring Boot full-stack role**, think of Spring Events as an **in-process event mechanism**.

Instead of one service directly calling another service, it can **publish an event**, and other components can **listen** to it.

### 1. Basic idea

```text
UserService
    |
    | publish event
    ↓
UserCreatedEvent
    |
    ├── EmailListener
    ├── AuditListener
    └── NotificationListener
```

This gives **loose coupling**.

---

# 2. Main Spring Event concepts

| Concept                     | Purpose                      |
| --------------------------- | ---------------------------- |
| `ApplicationEventPublisher` | Publishes an event           |
| Event class                 | Carries event data           |
| `@EventListener`            | Receives/listens to an event |
| `ApplicationEvent`          | Older/base event approach    |

Modern Spring applications generally use a **plain Java class as the event**.

---

# 3. Complete working example

### Project structure

```text
com.example.demo
├── DemoApplication.java
├── event
│   └── UserCreatedEvent.java
├── service
│   └── UserService.java
└── listener
    └── UserEventListener.java
```

---

## Step 1 — Create Event

```java
package com.example.demo.event;

public class UserCreatedEvent {

    private final Long userId;
    private final String username;

    public UserCreatedEvent(Long userId, String username) {
        this.userId = userId;
        this.username = username;
    }

    public Long getUserId() {
        return userId;
    }

    public String getUsername() {
        return username;
    }
}
```

The event represents:

> "A user has been created."

---

# 4. Publish the event

```java
package com.example.demo.service;

import com.example.demo.event.UserCreatedEvent;
import org.springframework.context.ApplicationEventPublisher;
import org.springframework.stereotype.Service;

@Service
public class UserService {

    private final ApplicationEventPublisher eventPublisher;

    public UserService(ApplicationEventPublisher eventPublisher) {
        this.eventPublisher = eventPublisher;
    }

    public void createUser() {

        System.out.println("Creating user...");

        Long userId = 101L;
        String username = "John";

        // Publish event
        eventPublisher.publishEvent(
                new UserCreatedEvent(userId, username)
        );

        System.out.println("User creation completed.");
    }
}
```

### Important

Spring automatically provides:

```java
ApplicationEventPublisher
```

You simply inject it.

---

# 5. Listen to the event

```java
package com.example.demo.listener;

import com.example.demo.event.UserCreatedEvent;
import org.springframework.context.event.EventListener;
import org.springframework.stereotype.Component;

@Component
public class UserEventListener {

    @EventListener
    public void handleUserCreated(UserCreatedEvent event) {

        System.out.println(
                "Sending welcome email to: "
                + event.getUsername()
        );
    }
}
```

Spring sees:

```java
@EventListener
```

and registers this method as an event listener.

---

# 6. Main application

```java
package com.example.demo;

import com.example.demo.service.UserService;
import org.springframework.boot.CommandLineRunner;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.context.annotation.Bean;

@SpringBootApplication
public class DemoApplication {

    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }

    @Bean
    CommandLineRunner run(UserService userService) {
        return args -> userService.createUser();
    }
}
```

### Output

```text
Creating user...
Sending welcome email to: John
User creation completed.
```

# 7. Multiple listeners

This is where Events become really useful.

You can have another listener:

```java
package com.example.demo.listener;

import com.example.demo.event.UserCreatedEvent;
import org.springframework.context.event.EventListener;
import org.springframework.stereotype.Component;

@Component
public class AuditListener {

    @EventListener
    public void handleUserCreated(UserCreatedEvent event) {

        System.out.println(
                "Audit: User created with ID "
                + event.getUserId()
        );
    }
}
```

Now:

```text
UserService
    |
    | publishEvent()
    ↓
UserCreatedEvent
    |
    ├── UserEventListener
    |       └── Send email
    |
    └── AuditListener
            └── Save audit
```

The `UserService` doesn't need to know about either listener.

That's the main benefit.

# 8. Real-world example

Imagine an order system:

```java
orderService.createOrder();
```

After order creation:

```text
OrderCreatedEvent
       |
       ├── EmailListener
       |      → Send order confirmation
       |
       ├── InventoryListener
       |      → Reduce inventory
       |
       └── AuditListener
              → Store audit record
```

Without events:

```java
createOrder();
sendEmail();
updateInventory();
saveAudit();
```

The order service becomes tightly coupled to everything.

With events:

```java
createOrder();

eventPublisher.publishEvent(
    new OrderCreatedEvent(orderId)
);
```

Other components react independently.

# 9. Synchronous behavior — Important

By default, Spring application events are **synchronous**.

Meaning:

```text
publishEvent()
      ↓
Listener executes
      ↓
publishEvent() returns
```

For example:

```java
System.out.println("Before");

eventPublisher.publishEvent(event);

System.out.println("After");
```

The listener normally executes between:

```text
Before
   ↓
Listener
   ↓
After
```

So Spring Events are **not automatically Kafka/RabbitMQ-style asynchronous messaging**.

---

# 10. Event vs REST vs Kafka

You should understand this distinction for interviews.

| Technology               | Communication                    |
| ------------------------ | -------------------------------- |
| Spring Application Event | Inside same application/JVM      |
| REST API                 | Between applications/services    |
| Kafka                    | Distributed event/message system |
| RabbitMQ                 | Distributed messaging            |

So:

```text
Application Events
      ↓
Same Spring application
```

while:

```text
Kafka
  ↓
Service A → Kafka → Service B
```

---

# 11. Interview definition

> **Spring Application Events provide a way for components within the same Spring application to communicate through events, reducing direct coupling between the publisher and listeners.**

Remember these four things:

```text
ApplicationEventPublisher
        ↓
publishEvent()
        ↓
@EventListener
        ↓
Event object
```

### Most important takeaway

If `UserService` needs to tell **multiple independent components** that something happened, don't necessarily call all of them directly.

Publish:

```java
eventPublisher.publishEvent(new UserCreatedEvent(...));
```

and let interested components listen with:

```java
@EventListener
```

That is the core of **Spring Application Events**.
