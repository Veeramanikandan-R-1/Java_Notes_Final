## Spring AOP — Aspect Implementation

Since you already know Java and have 5 years of React experience, think of **AOP (Aspect-Oriented Programming)** as a way to keep **cross-cutting concerns** separate from your business logic.

### 1. Why do we need AOP?

Suppose many service methods need:

* Logging
* Execution-time measurement
* Security checks
* Transaction handling
* Auditing

Without AOP:

```java
public void createUser() {
    System.out.println("Method started");
    
    // business logic
    
    System.out.println("Method completed");
}
```

You would repeat this logging code in many methods.

With AOP:

```java
public void createUser() {
    // only business logic
}
```

The logging can be handled separately by an **Aspect**.

---

# 2. Important AOP terminology

| Term           | Meaning                                      |
| -------------- | -------------------------------------------- |
| **Aspect**     | Class containing cross-cutting logic         |
| **Advice**     | What action should be performed              |
| **Join Point** | Point where advice can execute               |
| **Pointcut**   | Rule that selects which methods to intercept |
| **Target**     | Actual business object                       |
| **Proxy**      | Object Spring creates around the target      |
| **Weaving**    | Applying aspect logic to target              |

In Spring AOP, the most important things initially are:

**Aspect + Advice + Pointcut**

## 4. Service class

```java
package com.example.demo.service;

import org.springframework.stereotype.Service;

@Service
public class UserService {

    public void createUser() {
        System.out.println("Creating user...");
    }

    public void deleteUser() {
        System.out.println("Deleting user...");
    }
}
```

Notice that there is **no logging code** here.

---

# 5. Create Aspect

```java
package com.example.demo.aspect;

import org.aspectj.lang.annotation.Aspect;
import org.aspectj.lang.annotation.Before;
import org.springframework.stereotype.Component;

@Aspect
@Component
public class LoggingAspect {

    @Before("execution(* com.example.demo.service.*.*(..))")
    public void logBefore() {
        System.out.println("Logging: Method is about to execute");
    }
}
```

### What is happening?

```java
@Aspect
```

Tells Spring:

> This class contains AOP logic.

```java
@Component
```

Makes the aspect a Spring bean.

```java
@Before
```

Means:

> Execute this advice **before** the matched method.

And:

```java
execution(* com.example.demo.service.*.*(..))
```

is the **pointcut expression**.

It means:

```text
execution(
    return-type
    package
    class
    method(parameters)
)
```

Here:

```text
*                              → any return type
com.example.demo.service       → this package
*                              → any class
*                              → any method
(..)                           → any arguments
```

So it matches:

```java
UserService.createUser()
UserService.deleteUser()
```

# 6. Main class

```java
package com.example.demo;

import com.example.demo.service.UserService;
import org.springframework.boot.CommandLineRunner;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.context.annotation.Bean;

@SpringBootApplication
public class DemoApplication {

    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }

    @Bean
    CommandLineRunner run(UserService userService) {
        return args -> {
            userService.createUser();
            userService.deleteUser();
        };
    }
}
```

### Output

```text
Logging: Method is about to execute
Creating user...

Logging: Method is about to execute
Deleting user...
```

You called:

```java
userService.createUser();
```

but Spring actually calls a **proxy** around `UserService`.

Conceptually:

```text
Your code
   ↓
Spring Proxy
   ↓
@Before advice
   ↓
UserService.createUser()
```

That's the core idea of Spring AOP.

# 7. Common Advice types

You should know these:

### `@Before`

Runs before method.

```java
@Before("execution(* com.example.demo.service.*.*(..))")
public void before() {
    System.out.println("Before");
}
```

### `@After`

Runs after method, regardless of success/failure.

```java
@After("execution(* com.example.demo.service.*.*(..))")
public void after() {
    System.out.println("After");
}
```

### `@AfterReturning`

Runs only when method successfully returns.

```java
@AfterReturning("execution(* com.example.demo.service.*.*(..))")
public void afterReturning() {
    System.out.println("Success");
}
```

### `@AfterThrowing`

Runs when method throws an exception.

```java
@AfterThrowing("execution(* com.example.demo.service.*.*(..))")
public void afterThrowing() {
    System.out.println("Exception occurred");
}
```

### `@Around` ⭐

Most powerful. Runs **before and after** the method and can control whether the method executes.

```java
@Around("execution(* com.example.demo.service.*.*(..))")
public Object around(ProceedingJoinPoint joinPoint) throws Throwable {

    System.out.println("Before method");

    Object result = joinPoint.proceed();

    System.out.println("After method");

    return result;
}
```

Flow:

```text
Around Advice
     ↓
Before
     ↓
joinPoint.proceed()
     ↓
Actual method
     ↓
After
     ↓
Return result
```

# 8. Practical logging example

A very common real-world use is measuring execution time:

```java
@Aspect
@Component
public class LoggingAspect {

    @Around("execution(* com.example.demo.service.*.*(..))")
    public Object logExecutionTime(ProceedingJoinPoint joinPoint)
            throws Throwable {

        long start = System.currentTimeMillis();

        Object result = joinPoint.proceed();

        long end = System.currentTimeMillis();

        System.out.println(
            joinPoint.getSignature().getName()
            + " took "
            + (end - start)
            + " ms"
        );

        return result;
    }
}
```

Output:

```text
createUser took 15 ms
deleteUser took 3 ms
```

This is much cleaner than putting timing code inside every service method.

## 9. Key point to remember

Think of Spring AOP like this:

```text
Business Logic
     ↓
   Service
     ↑
   Proxy
     ↑
   Aspect
```

**AOP = Add common behavior around business methods without modifying those methods.**

For interviews, remember:

> **Aspect** = what cross-cutting logic to apply
> **Advice** = when/how to apply it
> **Pointcut** = where to apply it
> **Proxy** = how Spring applies it at runtime

Next important topic after this is **Pointcut expressions (`execution`, `within`, `@annotation`)**, because that is where most Spring AOP usage becomes practical.
