## Spring Core — Bean Scopes

A **bean scope** defines **how many objects (instances) Spring creates for a bean and how long those objects are used**.

The two important scopes to learn first are:

| Scope         | Objects created                       | Default? |
| ------------- | ------------------------------------- | -------- |
| **Singleton** | One instance per Spring IoC container | ✅ Yes    |
| **Prototype** | New instance every time requested     | ❌ No     |

---

# 1. Singleton Scope

### Concept

With `singleton` scope, Spring creates **only one object** for a bean inside a Spring container.

```text
Spring Container
      │
      ▼
  UserService
      │
   ┌──┴──┐
   │ ONE │
   │ OBJ │
   └─────┘
```

If multiple classes request `UserService`, they get the **same object**.

### Example

```java
package com.springapp.demo;

import org.springframework.stereotype.Component;

@Component
public class UserService {

    public void printMessage() {
        System.out.println("Hello from UserService");
    }
}
```

Spring automatically uses singleton scope because it is the default.

Now:

```java
package com.springapp.demo;

import org.springframework.context.ApplicationContext;
import org.springframework.context.annotation.AnnotationConfigApplicationContext;

public class DemoApplication {

    public static void main(String[] args) {

        ApplicationContext context =
                new AnnotationConfigApplicationContext(AppConfig.class);

        UserService userService1 = context.getBean(UserService.class);
        UserService userService2 = context.getBean(UserService.class);

        System.out.println(userService1 == userService2);
    }
}
```

Output:

```text
true
```

Both variables point to the **same object**.

### Explicitly declaring Singleton

You can also write:

```java
@Component
@Scope("singleton")
public class UserService {
}
```

But this is unnecessary because singleton is already the default.

# 2. Prototype Scope

With `prototype`, Spring creates a **new object every time you request the bean**.

```text
context.getBean()
       │
       ├── UserService object #1
       │
context.getBean()
       │
       ├── UserService object #2
       │
context.getBean()
       │
       └── UserService object #3
```

### Example

```java
package com.springapp.demo;

import org.springframework.context.annotation.Scope;
import org.springframework.stereotype.Component;

@Component
@Scope("prototype")
public class UserService {

    public UserService() {
        System.out.println("UserService object created");
    }
}
```

Then:

```java
package com.springapp.demo;

import org.springframework.context.ApplicationContext;
import org.springframework.context.annotation.AnnotationConfigApplicationContext;

public class DemoApplication {

    public static void main(String[] args) {

        ApplicationContext context =
                new AnnotationConfigApplicationContext(AppConfig.class);

        UserService userService1 = context.getBean(UserService.class);
        UserService userService2 = context.getBean(UserService.class);

        System.out.println(userService1 == userService2);
    }
}
```

Output:

```text
UserService object created
UserService object created
false
```

Two different objects were created.

---

# Singleton vs Prototype

Think of it like this:

### Singleton

```java
UserService a = context.getBean(UserService.class);
UserService b = context.getBean(UserService.class);

a == b; // true
```

### Prototype

```java
UserService a = context.getBean(UserService.class);
UserService b = context.getBean(UserService.class);

a == b; // false
```

---

## Important Spring Interview Point ⭐

**Singleton does NOT mean one object for the entire Java application.**

It means:

> **One bean instance per Spring IoC container.**

For example, if you have:

```text
Application
   │
   ├── Spring Container 1 → UserService instance A
   │
   └── Spring Container 2 → UserService instance B
```

There can be multiple instances if there are multiple Spring containers.

---

## When to use?

### Singleton — most common

Use for **stateless services, repositories, controllers, configuration**, etc.

```text
UserController
      ↓
UserService       ← Singleton
      ↓
UserRepository    ← Singleton
      ↓
Database
```

This is the normal Spring application design.

### Prototype

Use when you specifically need a **fresh object with independent state** each time.

For example:

```text
Request/Object creation
        ↓
New object
        ↓
Work with its own state
        ↓
Discard
```

---

## One very important point

Prototype doesn't mean Spring manages the object's entire lifecycle like Singleton.

For a prototype bean:

* Spring creates it.
* Spring injects its dependencies.
* After returning it, **Spring generally does not manage its destruction lifecycle**.

### Remember this

```text
Singleton
    → One instance
    → Spring manages lifecycle

Prototype
    → New instance per getBean()
    → Spring creates/configures it
    → Caller is generally responsible for its eventual cleanup
```

**Interview answer:**

> Spring bean scope determines the lifecycle and number of instances of a bean. Singleton is the default and gives one instance per Spring container, while Prototype creates a new instance every time the bean is requested from the container.
