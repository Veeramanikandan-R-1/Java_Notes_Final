# Spring Core — Configuration

Spring configuration tells Spring **which objects (beans) it should create and manage**.

The 3 important concepts here are:

* `@Configuration`
* `@Bean`
* `@ConfigurationProperties`

---

# 1. `@Configuration`

`@Configuration` tells Spring:

> **"This class contains Spring bean definitions/configuration."**

Example:

```java
package com.springapp.demo;

import org.springframework.context.annotation.Configuration;

@Configuration
public class AppConfig {

}
```

Spring detects `AppConfig` and processes the bean definitions inside it.

---

# 2. `@Bean`

`@Bean` tells Spring:

> **"Create and manage the object returned by this method as a Spring bean."**

### Why do we need `@Bean`?

For your own classes, you can usually use:

```java
@Service
@Repository
@Component
```

But what if the class is from a **third-party library** and you cannot add `@Component` to it?

That's where `@Bean` is useful.

---

## Complete Example

### `AppConfig.java`

```java
package com.springapp.demo;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class AppConfig {

    @Bean
    public EmailService emailService() {
        return new EmailService();
    }
}
```

### `EmailService.java`

```java
package com.springapp.demo;

public class EmailService {

    public void sendEmail() {
        System.out.println("Email sent");
    }
}
```

### `DemoApplication.java`

```java
package com.springapp.demo;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class DemoApplication {

    public static void main(String[] args) {

        var context = SpringApplication.run(DemoApplication.class, args);

        EmailService emailService =
                context.getBean(EmailService.class);

        emailService.sendEmail();
    }
}
```

Output:

```text
Email sent
```

### What happened?

Spring sees:

```java
@Bean
public EmailService emailService()
```

and effectively creates:

```java
EmailService emailService = new EmailService();
```

and stores it inside the Spring container.

Then you can retrieve it:

```java
context.getBean(EmailService.class);
```

# 3. `@Bean` with Dependency Injection

This is where `@Bean` becomes very useful.

Suppose:

```java
package com.springapp.demo;

public class EmailService {

    private final EmailClient emailClient;

    public EmailService(EmailClient emailClient) {
        this.emailClient = emailClient;
    }

    public void send() {
        emailClient.connect();
        System.out.println("Email sent");
    }
}
```

And:

```java
package com.springapp.demo;

public class EmailClient {

    public void connect() {
        System.out.println("Connected to email server");
    }
}
```

Configuration:

```java
package com.springapp.demo;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class AppConfig {

    @Bean
    public EmailClient emailClient() {
        return new EmailClient();
    }

    @Bean
    public EmailService emailService(EmailClient emailClient) {
        return new EmailService(emailClient);
    }
}
```

Notice this:

```java
@Bean
public EmailService emailService(EmailClient emailClient)
```

Spring automatically injects the `EmailClient` bean.

```text
EmailClient Bean
      ↓
EmailService Bean
      ↓
Constructor Injection
```

# 4. `@ConfigurationProperties`

This is used to **bind configuration values from `application.properties` / `application.yml` into a Java object**.

Instead of hardcoding configuration:

```java
String host = "localhost";
int port = 8080;
```

put it in:

```text
application.properties
```

```properties
app.name=My Application
app.host=localhost
app.port=8080
```

Then create:

```java
package com.springapp.demo;

import org.springframework.boot.context.properties.ConfigurationProperties;

@ConfigurationProperties(prefix = "app")
public class AppProperties {

    private String name;
    private String host;
    private int port;

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public String getHost() {
        return host;
    }

    public void setHost(String host) {
        this.host = host;
    }

    public int getPort() {
        return port;
    }

    public void setPort(int port) {
        this.port = port;
    }
}
```

Now Spring needs to register this configuration-properties class.

The simplest Spring Boot approach is:

```java
package com.springapp.demo;

import org.springframework.boot.context.properties.EnableConfigurationProperties;
import org.springframework.context.annotation.Configuration;

@Configuration
@EnableConfigurationProperties(AppProperties.class)
public class AppConfig {

}
```

Now you can inject it:

```java
package com.springapp.demo;

import org.springframework.stereotype.Service;

@Service
public class AppService {

    private final AppProperties properties;

    public AppService(AppProperties properties) {
        this.properties = properties;
    }

    public void printConfig() {
        System.out.println(properties.getName());
        System.out.println(properties.getHost());
        System.out.println(properties.getPort());
    }
}
```

Output:

```text
My Application
localhost
8080
```

---

# How `@ConfigurationProperties` works

```text
application.properties

app.name=My Application
app.host=localhost
app.port=8080
          │
          ▼
@ConfigurationProperties(prefix = "app")
          │
          ▼
      AppProperties
          │
          ▼
     Inject into Service
```

The prefix:

```java
@ConfigurationProperties(prefix = "app")
```

means:

```properties
app.name
app.host
app.port
```

will be mapped to:

```java
name
host
port
```

# `@Value` vs `@ConfigurationProperties`

You'll encounter both.

### `@Value`

Good for a small number of values:

```java
@Value("${app.name}")
private String name;
```

### `@ConfigurationProperties`

Better when you have a **group of related configuration values**:

```properties
app.name=My Application
app.host=localhost
app.port=8080
app.timeout=5000
```

```java
@ConfigurationProperties(prefix = "app")
public class AppProperties {
    private String name;
    private String host;
    private int port;
    private int timeout;
}
```

For real Spring Boot applications, `@ConfigurationProperties` is generally cleaner for grouped configuration.

# Important Interview Summary

| Annotation                 | Purpose                                                    |
| -------------------------- | ---------------------------------------------------------- |
| `@Configuration`           | Marks a class as Spring configuration                      |
| `@Bean`                    | Registers the object returned by a method as a Spring bean |
| `@ConfigurationProperties` | Maps application configuration into a Java object          |

### Remember this flow

```text
@Configuration
      ↓
Defines configuration

@Bean
      ↓
Creates/registers custom bean

@ConfigurationProperties
      ↓
application.properties
      ↓
Java configuration object
```

### One important distinction

```java
@Component
```

means:

> **Spring discovers and creates this class as a bean.**

Whereas:

```java
@Bean
```

means:

> **I explicitly tell Spring which object to create and register.**

This distinction is very important when you start working with real Spring Boot projects.
