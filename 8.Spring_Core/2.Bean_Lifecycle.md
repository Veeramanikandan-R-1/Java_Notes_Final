Since you already know React, think of the **Spring Context** roughly as a centralized container that creates, stores, wires, and manages your application's objects (beans).

---

### Why do we need a Spring Bean?

A **Bean = Java object managed by Spring**.

Instead of manually doing:

```java
UserService service = new UserService();
```

Spring creates and manages it:

```java
@Service
class UserService {}
```

Spring handles:

* **Object creation**
* **Dependency Injection**
* **Lifecycle**
* **Object reuse** (Singleton by default)

So simply:

> **We use Beans so Spring can manage our application's objects and their dependencies for us.**

---

## 1. What is Spring Context?

`ApplicationContext` is the **Spring IoC container**.

Its main responsibilities are:

* Create Spring beans
* Manage their lifecycle
* Perform Dependency Injection
* Store/retrieve beans
* Execute lifecycle callbacks
* Manage configuration

```text
Application
     |
     v
ApplicationContext
     |
     +---- UserService
     +---- UserRepository
     +---- EmailService
     +---- ...
```

### React analogy

In React, you may have a context:

```jsx
<UserContext.Provider value={user}>
```

Components consume that shared value.

Spring's `ApplicationContext` is much more powerful: it manages **objects and their dependencies/lifecycle**, not just shared values.

# 2. Creating a Spring Context

For learning Spring Core, we can use:

```java
AnnotationConfigApplicationContext
```

Example:

### `AppConfig.java`

```java
import org.springframework.context.annotation.ComponentScan;
import org.springframework.context.annotation.Configuration;

@Configuration
@ComponentScan("com.example")
public class AppConfig {
}
```

### `UserService.java`

```java
package com.example;

import org.springframework.stereotype.Component;

@Component
public class UserService {

    public void sayHello() {
        System.out.println("Hello from UserService");
    }
}
```

### `Main.java`

```java
package com.example;

import org.springframework.context.ApplicationContext;
import org.springframework.context.annotation.AnnotationConfigApplicationContext;

public class Main {

    public static void main(String[] args) {

        ApplicationContext context =
                new AnnotationConfigApplicationContext(AppConfig.class);

        UserService userService = context.getBean(UserService.class);

        userService.sayHello();
    }
}
```

### What happens?

When this executes:

```java
new AnnotationConfigApplicationContext(AppConfig.class);
```

Spring:

```text
Read AppConfig
     ↓
Scan @Component
     ↓
Find UserService
     ↓
Create UserService object
     ↓
Store it inside ApplicationContext
     ↓
Manage its lifecycle
```

Then:

```java
context.getBean(UserService.class);
```

gets the **Spring-managed object**.

# 3. Bean Lifecycle

A Spring bean generally goes through these stages:

```text
Spring Context starts
       ↓
Create bean
       ↓
Dependency Injection
       ↓
Aware callbacks
       ↓
@PostConstruct
       ↓
Bean ready
       ↓
Application uses bean
       ↓
Context closes
       ↓
@PreDestroy
       ↓
Bean destroyed
```

The important lifecycle callbacks for normal Spring applications are:

```text
Constructor
    ↓
Dependency Injection
    ↓
@PostConstruct
    ↓
Bean is ready
    ↓
@PreDestroy
```

---

# 4. Lifecycle Example

```java
package com.example;

import jakarta.annotation.PostConstruct;
import jakarta.annotation.PreDestroy;
import org.springframework.stereotype.Component;

@Component
public class UserService {

    public UserService() {
        System.out.println("1. Constructor");
    }

    @PostConstruct
    public void init() {
        System.out.println("2. @PostConstruct");
    }

    public void execute() {
        System.out.println("3. Bean is being used");
    }

    @PreDestroy
    public void cleanup() {
        System.out.println("4. @PreDestroy");
    }
}
```

### Main

```java
package com.example;

import org.springframework.context.annotation.AnnotationConfigApplicationContext;

public class Main {

    public static void main(String[] args) {

        AnnotationConfigApplicationContext context =
                new AnnotationConfigApplicationContext(AppConfig.class);

        UserService service = context.getBean(UserService.class);

        service.execute();

        context.close();
    }
}
```

Output:

```text
1. Constructor
2. @PostConstruct
3. Bean is being used
4. @PreDestroy
```

# 5. Why `@PostConstruct`?

Use it when initialization requires the bean's dependencies to already be injected.

For example:

```java
@Component
public class UserService {

    private final UserRepository repository;

    public UserService(UserRepository repository) {
        this.repository = repository;
    }

    @PostConstruct
    public void init() {
        System.out.println("Repository is ready");
    }
}
```

At `@PostConstruct`, `repository` has already been injected.

Typical uses:

* Initialize resources
* Validate configuration
* Load initial data
* Perform startup initialization

---

# 6. Why `@PreDestroy`?

Used for cleanup before the bean is destroyed.

```java
@PreDestroy
public void cleanup() {
    System.out.println("Closing resources...");
}
```

Typical uses:

* Close resources
* Stop background tasks
* Cleanup connections
* Release memory/resources

**Important:** `@PreDestroy` is normally triggered when the Spring `ApplicationContext` is properly closed.

---

# 7. Spring Context vs Bean

Don't confuse these:

### Bean

An object managed by Spring.

```java
@Component
public class UserService {
}
```

### ApplicationContext

The container managing those beans.

```java
ApplicationContext context =
    new AnnotationConfigApplicationContext(AppConfig.class);
```

Conceptually:

```text
ApplicationContext
       |
       +-- UserService bean
       +-- UserRepository bean
       +-- EmailService bean
       +-- OrderService bean
```

---

# 8. Important Interview Point

Don't manually create Spring-managed beans using:

```java
UserService service = new UserService();
```

If you do that, Spring doesn't manage that object.

Instead:

```java
UserService service = context.getBean(UserService.class);
```

Or, in a real Spring Boot application, preferably let Spring inject it:

```java
@Service
public class OrderService {

    private final UserService userService;

    public OrderService(UserService userService) {
        this.userService = userService;
    }
}
```

This is the main benefit of **IoC + Dependency Injection**.

## What you should remember

```text
ApplicationContext = Spring's IoC container

Bean lifecycle:

Constructor
    ↓
Dependency Injection
    ↓
@PostConstruct
    ↓
Ready to use
    ↓
@PreDestroy
```

For Spring Boot development, the most important lifecycle annotations to know initially are:

| Annotation       | Purpose                                   |
| ---------------- | ----------------------------------------- |
| `@PostConstruct` | Initialization after dependency injection |
| `@PreDestroy`    | Cleanup before bean destruction           |

**Next natural topic:** Bean scopes (`singleton`, `prototype`, `request`, `session`) because lifecycle and scope are closely connected.
