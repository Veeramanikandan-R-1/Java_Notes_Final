### `@Primary` Annotation in Spring

`@Primary` is used to specify the default Bean when multiple Beans of the same type are available for dependency injection.

It tells Spring which Bean should be preferred when resolving dependency conflicts.

### Example

Suppose we have two implementations of the same interface.

```
public interface PaymentService {
    void pay();
}
```

Implementation 1:

```
@Service
@Primary
public class UpiPayment implements PaymentService {
    public void pay() {
        System.out.println("UPI Payment");
    }
}
```

Implementation 2:

```
@Service
public class CardPayment implements PaymentService {
    public void pay() {
        System.out.println("Card Payment");
    }
}
```

Injection:

```
@Service
public class OrderService {

    @Autowired
    private PaymentService paymentService;

    public void makePayment() {
        paymentService.pay();
    }
}
```

Output:

```
UPI Payment
```

### Why do we need `@Primary`?

Without `@Primary`, Spring finds multiple Beans of type `PaymentService` and doesn't know which one to inject, resulting in `NoUniqueBeanDefinitionException` (unless another resolution rule applies).

### `@Primary` vs `@Qualifier`

| `@Primary`                              | `@Qualifier`                    |
| --------------------------------------- | ------------------------------- |
| Defines the default Bean                | Explicitly selects a Bean       |
| Applied to Bean definition              | Applied at injection point      |
| Used when no specific Bean is requested | Overrides the default selection |

In short: `@Primary` tells Spring which Bean to choose by default when multiple implementations of the same type exist.

### `@Qualifier` Annotation in Spring

`@Qualifier` is used to explicitly specify which Bean should be injected when multiple Beans of the same type are available.

### Example

1\. Interface

```
public interface PaymentService {
    void pay();
}
```

2\. Implementations

```
@Service("upiPayment")
public class UpiPayment implements PaymentService {
    public void pay() {
        System.out.println("UPI Payment");
    }
}
```

```
@Service("cardPayment")
public class CardPayment implements PaymentService {
    public void pay() {
        System.out.println("Card Payment");
    }
}
```

3\. Inject using `@Qualifier`

```
@Service
public class OrderService {

    private final PaymentService paymentService;

    public OrderService(
        @Qualifier("cardPayment") PaymentService paymentService) {
        this.paymentService = paymentService;
    }

    public void makePayment() {
        paymentService.pay();
    }
}
```

Output:

```
Card Payment
```

### Key points

- `@Qualifier` resolves ambiguity when multiple Beans of the same type exist.
- It selects a specific Bean using its name.
- It can be used with constructor, setter, and field injection.
- It takes precedence over `@Primary` when explicitly selecting a Bean.

In short:

- `@Primary` → Which Bean should be selected by default?
- `@Qualifier` → Which specific Bean do I want?

---

Note:

In Spring, when you use `@Service` without explicitly specifying a Bean name, Spring creates the default Bean name using the class name with its first letter converted to lowercase.

### Example

```
@Service
public class UpiPayment implements PaymentService {
}
```

Spring registers this Bean with the name:

```
upiPayment
```

Therefore, you use:

```
@Qualifier("upiPayment")
```

### What if we specify a custom name?

```
@Service("myUpiService")
public class UpiPayment implements PaymentService {
}
```

Now inject it using:

```
@Qualifier("myUpiService")
```

### Key points

| Class name    | Default Bean name |
| ------------- | ----------------- |
| `UpiPayment`  | `upiPayment`      |
| `CardPayment` | `cardPayment`     |
| `UserService` | `userService`     |

In short: Spring follows the default bean-naming convention (lowercase first letter). `@Qualifier` must match the registered Bean name, not necessarily the Java class name.
