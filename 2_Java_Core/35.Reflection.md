# Java Reflection

**Reflection** allows Java code to **inspect and interact with classes, methods, fields, and constructors at runtime**.

Normally, you write:

```java
User user = new User();
user.getName();
```

With Reflection, you can discover things like:

```text
What is this class?
What fields does it have?
What methods does it have?
What are their types?
Can I invoke this method dynamically?
Can I read/change this field dynamically?
```

This is important to understand because frameworks like **Spring/Spring Boot, Hibernate, Jackson, JUnit** use reflection heavily.

The exact reason we need Reflection is:

When the program/framework does not know the class, method, or field it needs to work with until runtime.

Without Reflection, Java code usually knows these things at compile time.

Simple comparison

Suppose you know the class beforehand:

User user = new User();
user.getName();

No Reflection needed. This is normal Java.

But imagine a framework receives this at runtime:

"com.example.User"

It doesn't know beforehand which class the application wants.

Reflection allows it to do:

Class<?> clazz = Class.forName("com.example.User");
Object obj = clazz.getDeclaredConstructor().newInstance();

Now the framework can work with the class dynamically.

# 2. `Class` ⭐⭐⭐

`Class` represents the metadata/information about a Java class at runtime.

There are 3 common ways to get a `Class` object.

### Method 1 — `.class`

```java
Class<?> clazz = User.class;
```

### Method 2 — `getClass()`

```java
User user = new User();

Class<?> clazz = user.getClass();
```

### Method 3 — `Class.forName()`

```java
Class<?> clazz = Class.forName("User");
```

The third approach is useful when the class name is available dynamically.

---

# 3. `Method` ⭐⭐⭐

`Method` represents a method of a class.

Let's use a complete example.

```java
import java.lang.reflect.Method;

class User {

    public void greet(String name) {
        System.out.println("Hello " + name);
    }

    public int add(int a, int b) {
        return a + b;
    }
}

public class Main {

    public static void main(String[] args) throws Exception {

        User user = new User();

        Class<?> clazz = user.getClass();

        // Get method
        Method method = clazz.getMethod("greet", String.class);

        // Invoke method dynamically
        method.invoke(user, "John");

        // Another method
        Method addMethod = clazz.getMethod(
                "add",
                int.class,
                int.class
        );

        Object result = addMethod.invoke(user, 10, 20);

        System.out.println(result);
    }
}
```

Output:

```text
Hello John
30
```

### What's happening?

Normally:

```java
user.greet("John");
```

Reflection:

```java
Method method = clazz.getMethod("greet", String.class);

method.invoke(user, "John");
```

So:

```text
Class
 ↓
find Method
 ↓
invoke Method
```

---

# 4. `getMethod()` vs `getDeclaredMethod()` ⭐⭐

This is important.

### `getMethod()`

Finds **public methods**, including inherited methods.

```java
Method method = clazz.getMethod("greet", String.class);
```

### `getDeclaredMethod()`

Finds methods **declared directly in that class**, including private/protected methods.

```java
Method method =
        clazz.getDeclaredMethod("secret");
```

For example:

```java
class User {

    private void secret() {
        System.out.println("Secret");
    }
}
```

You cannot access it directly:

```java
user.secret(); // ❌
```

But reflection can access it:

```java
Method method = User.class.getDeclaredMethod("secret");

method.setAccessible(true);

method.invoke(user);
```

Output:

```text
Secret
```

> Modern Java strongly restricts reflective access across module boundaries, so `setAccessible(true)` should not be treated as a general-purpose way to bypass access control.

# 5. `Field` ⭐⭐⭐

`Field` represents a class variable/field.

Complete example:

```java
import java.lang.reflect.Field;

class User {

    private String name = "John";
    public int age = 25;
}

public class Main {

    public static void main(String[] args) throws Exception {

        User user = new User();

        Class<?> clazz = user.getClass();

        // Get private field
        Field nameField = clazz.getDeclaredField("name");

        nameField.setAccessible(true);

        // Read field
        System.out.println(nameField.get(user));

        // Change field
        nameField.set(user, "Bob");

        System.out.println(nameField.get(user));

        // Public field
        Field ageField = clazz.getField("age");

        System.out.println(ageField.get(user));
    }
}
```

Output:

```text
John
Bob
25
```

The normal approach:

```java
user.name
```

Reflection:

```java
Field field = clazz.getDeclaredField("name");

field.setAccessible(true);

field.get(user);
```

---

# 6. `getField()` vs `getDeclaredField()`

Same concept as methods.

### `getField()`

Only **public fields**, including inherited public fields.

```java
Field field = clazz.getField("age");
```

### `getDeclaredField()`

Fields declared directly in the class, including private fields.

```java
Field field = clazz.getDeclaredField("name");
```

---

# 7. Getting All Methods and Fields

Reflection is particularly useful when you want to **inspect a class dynamically**.

```java
import java.lang.reflect.Field;
import java.lang.reflect.Method;

class User {

    private String name;
    private int age;

    public void login() {
    }

    public void logout() {
    }
}

public class Main {

    public static void main(String[] args) {

        Class<?> clazz = User.class;

        System.out.println("Class: " + clazz.getName());

        System.out.println("\nFields:");

        for (Field field : clazz.getDeclaredFields()) {
            System.out.println(
                    field.getName() + " : " + field.getType()
            );
        }

        System.out.println("\nMethods:");

        for (Method method : clazz.getDeclaredMethods()) {
            System.out.println(method.getName());
        }
    }
}
```

Output will be similar to:

```text
Class: User

Fields:
name : class java.lang.String
age : int

Methods:
login
logout
```

# 8. Reflection Flow — Remember This ⭐⭐⭐

Think of Reflection like this:

```text
             User.class
                 ↓
               Class
                 ↓
       ┌─────────┼─────────┐
       ↓         ↓         ↓
     Field     Method   Constructor
       ↓         ↓         ↓
     get/set   invoke    newInstance
```

# 9. Why Spring Boot Uses Reflection ⭐⭐⭐⭐⭐

This is the most important reason for learning Reflection.

Suppose you write:

```java
@Service
class UserService {
}
```

You don't manually do:

```java
UserService service = new UserService();
```

Spring scans your classes, discovers annotations such as:

```java
@Service
@Autowired
@RestController
```

and uses reflection and other runtime mechanisms to inspect classes and create/configure objects.

Similarly, frameworks can inspect:

```java
class User {

    private String name;

    public void save() {
    }
}
```

and dynamically discover:

```text
User
 ↓
Fields → name
Methods → save()
Annotations → ...
```

This is one of the foundations behind Java frameworks.

# Interview Points

Remember these:

| API                   | Purpose                    |
| --------------------- | -------------------------- |
| `Class`               | Represents class metadata  |
| `Method`              | Represents a method        |
| `Field`               | Represents a field         |
| `Constructor`         | Represents a constructor   |
| `getMethod()`         | Public methods             |
| `getDeclaredMethod()` | Methods declared in class  |
| `getField()`          | Public fields              |
| `getDeclaredField()`  | Fields declared in class   |
| `invoke()`            | Execute method dynamically |
| `get()`               | Read field                 |
| `set()`               | Modify field               |

### One-line definition

> **Reflection is the ability to inspect and manipulate Java classes, methods, fields, and constructors at runtime.**

For your **Spring Boot goal**, you don't need to become an expert in Reflection implementation. You should be comfortable with **`Class`, `Method`, `Field`, `getDeclared...`, `invoke()`, and why Spring uses reflection**.
