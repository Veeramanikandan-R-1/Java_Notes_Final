## JVM — Class Loader & Memory

Since you already know Java basics, think of the JVM as the **runtime environment that loads your `.class` files and manages their memory while your application runs.**

### 1. Class Loader

When you run:

```java
public class Main {
    public static void main(String[] args) {
        User user = new User();
        System.out.println(user);
    }
}
```

You compile:

```text
Main.java → Main.class
User.java → User.class
```

When the JVM starts, it needs to **load these `.class` files into memory**.

That's the job of the **Class Loader**.

```text
.class files
     ↓
Class Loader
     ↓
JVM Memory
     ↓
Execution
```

### Class Loader hierarchy

Modern Java has mainly:

```text
Bootstrap ClassLoader
        ↓
Platform ClassLoader
        ↓
Application ClassLoader
```

#### Bootstrap ClassLoader

Loads core Java classes such as:

```java
String
Object
ArrayList
```

For example:

```java
String name = "John";
```

`String` is loaded by the Bootstrap ClassLoader.

#### Platform ClassLoader

Loads Java platform classes/modules that aren't part of the core bootstrap classes.

#### Application ClassLoader

Loads **your application's classes** and classes from the classpath.

```java
User user = new User();
```

`User.class` is typically loaded by the Application ClassLoader.

### Important concept: Parent Delegation

When a ClassLoader needs a class, it generally asks its **parent first**.

```text
Application ClassLoader
        ↓ asks
Platform ClassLoader
        ↓ asks
Bootstrap ClassLoader
```

Why?

To prevent your application from replacing core Java classes with its own versions.

# 2. JVM Memory

Once classes and objects are loaded, JVM manages different memory areas.

The most important ones:

```text
JVM Memory
│
├── Heap
├── Stack
├── Method Area / Metaspace
├── PC Register
└── Native Method Stack
```

For Spring Boot, **Heap, Stack, and Metaspace** are the most important.

---

## Heap

The **Heap stores objects**.

```java
User user = new User("John", 30);
```

Conceptually:

```text
Stack                 Heap
------                ----------------
user ───────────────→ User object
                       name = "John"
                       age = 30
```

Heap is shared among threads.

Garbage Collector mainly manages the Heap.

```java
User user = new User("John", 30);

user = null;
```

The `User` object can eventually be removed by **Garbage Collection** because nothing references it.

---

## Stack

Each thread has its **own stack**.

It stores things such as:

* Method call information
* Local variables
* References to objects
* Primitive local values

Example:

```java
public static void main(String[] args) {
    int age = 30;
    User user = new User("John", age);
}
```

Conceptually:

```text
Stack                  Heap
----------------       ----------------
age = 30               User object
user ────────────────→ name = "John"
                       age = 30
```

`user` is a **reference** in the stack; the actual `User` object is on the heap.

### Stack is per-thread

```text
Thread 1 → Stack 1
Thread 2 → Stack 2
Thread 3 → Stack 3

             ↓
          Shared Heap
```

This is especially important in Spring Boot because web applications handle many requests using multiple threads.

---

Note: 

**Java is multithreaded, and each thread has its own stack.**

Think of it like this:

```text
JVM Process
│
├── Heap (shared)
│
├── Metaspace (shared)
│
├── Thread 1
│    └── Stack 1
│
├── Thread 2
│    └── Stack 2
│
└── Thread 3
     └── Stack 3
```

### Example

```java
public class Main {

    static void printNumber(int n) {
        int x = n * 2;
        System.out.println(x);
    }

    public static void main(String[] args) {

        Thread t1 = new Thread(() -> printNumber(10));
        Thread t2 = new Thread(() -> printNumber(20));

        t1.start();
        t2.start();
    }
}
```

Conceptually:

```text
Thread 1 Stack              Thread 2 Stack
──────────────              ──────────────
printNumber()               printNumber()
n = 10                      n = 20
x = 20                      x = 40
```

They have **separate stacks**, so Thread 1's local variable `n` doesn't interfere with Thread 2's `n`.

But their objects are generally in the **shared Heap**:

```text
             Shared Heap
          ┌───────────────┐
          │    Objects    │
          └───────────────┘
             ↑       ↑
             │       │
        Stack 1   Stack 2
        Thread 1  Thread 2
```

### Why this matters in Spring Boot

A Spring Boot web application can process multiple requests concurrently:

```text
Request 1 → Thread 1 → Stack 1
Request 2 → Thread 2 → Stack 2
Request 3 → Thread 3 → Stack 3
```

Each request/thread gets its own method execution and local variables, while the application's shared objects can live in the Heap.

**Key rule:**

> **One JVM → potentially many threads → each thread has its own Stack → all threads share the Heap.**

---

## Metaspace

Metaspace stores **class-level metadata**.

When the ClassLoader loads:

```java
class User {
    String name;
    int age;
}
```

information about the `User` class is maintained in the JVM's class metadata area (Metaspace).

```text
.class
  ↓
ClassLoader
  ↓
Metaspace → class metadata
Heap      → User objects
```

**Important:** Metaspace uses **native memory**, not the Java Heap.

---

# Complete picture

When you run a Spring Boot application:

```text
                JVM
                 │
        ┌────────┴────────┐
        │                 │
   Class Loading       Memory
        │                 │
   .class files       ┌───┼─────────────┐
        ↓             │   │             │
   ClassLoader       Heap Stack     Metaspace
                      │     │            │
                   Objects Local      Class
                          variables    metadata
```

### Interview-ready summary

| Area                    | What it contains                          | Shared?        |
| ----------------------- | ----------------------------------------- | -------------- |
| **Heap**                | Objects                                   | Yes            |
| **Stack**               | Method calls, local variables, references | No, per thread |
| **Metaspace**           | Class metadata                            | Yes            |
| **PC Register**         | Current instruction for each thread       | No             |
| **Native Method Stack** | Native method execution                   | Per thread     |

### The 3 things you should remember

> **ClassLoader** → loads `.class` files into JVM.
> **Heap** → stores objects.
> **Stack** → stores method execution/local variables for each thread.
> **Metaspace** → stores class metadata.

For Spring Boot interviews, **Heap vs Stack + ClassLoader + Garbage Collection** are particularly important.
