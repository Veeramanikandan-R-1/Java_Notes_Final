# Comparable vs Comparator — Sorting

Both are used to **sort objects** in Java.

The main difference is **where the sorting logic is defined**.

---

## 1. Comparable

Use `Comparable` when the class itself has a **natural/default sorting order**.

You implement:

```java
Comparable<T>
```

and override:

```java
compareTo()
```

### Example: Sort Users by Age

```java
import java.util.*;

class User implements Comparable<User> {

    String name;
    int age;

    User(String name, int age) {
        this.name = name;
        this.age = age;
    }

    @Override
    public int compareTo(User other) {
        return Integer.compare(this.age, other.age);
    }

    @Override
    public String toString() {
        return name + " - " + age;
    }
}

public class Main {
    public static void main(String[] args) {

        List<User> users = new ArrayList<>();

        users.add(new User("John", 30));
        users.add(new User("Alice", 20));
        users.add(new User("Bob", 25));

        Collections.sort(users);

        System.out.println(users);
    }
}
```

Output:

```text
[Alice - 20, Bob - 25, John - 30]
```

Because:

```java
Collections.sort(users);
```

uses `User.compareTo()`.

### Remember

```text
Comparable
    ↓
compareTo()
    ↓
Defines natural/default ordering
    ↓
Class itself controls sorting
```

# 2. Comparator

Use `Comparator` when you want **different/custom sorting rules** without modifying the class.

For example, the same `User` can be sorted by:

* Age
* Name
* Salary
* etc.

### Sort by Name

```java
import java.util.*;

class User {
    String name;
    int age;

    User(String name, int age) {
        this.name = name;
        this.age = age;
    }

    @Override
    public String toString() {
        return name + " - " + age;
    }
}

public class Main {
    public static void main(String[] args) {

        List<User> users = new ArrayList<>();

        users.add(new User("John", 30));
        users.add(new User("Alice", 20));
        users.add(new User("Bob", 25));

        users.sort(Comparator.comparing(user -> user.name));

        System.out.println(users);
    }
}
```

Output:

```text
[Alice - 20, Bob - 25, John - 30]
```

### Sort by age descending

```java
users.sort(Comparator.comparingInt((User user) -> user.age).reversed());
```

Result:

```text
[John - 30, Bob - 25, Alice - 20]
```

# Comparable vs Comparator

|                              | Comparable       | Comparator      |
| ---------------------------- | ---------------- | --------------- |
| Method                       | `compareTo()`    | `compare()`     |
| Package                      | `java.lang`      | `java.util`     |
| Sorting logic                | Inside class     | Outside class   |
| Number of sorting strategies | Usually one      | Multiple        |
| Use case                     | Natural ordering | Custom ordering |

### Easy way to remember

```text
Comparable
"My class knows how it should normally be sorted."

Comparator
"I want to tell Java how to sort it this time."
```

### Interview point ⭐

For modern Java, you'll commonly see:

```java
users.sort(Comparator.comparing(User::getName));
```

or:

```java
users.sort(Comparator.comparingInt(User::getAge));
```

So understand **both `Comparable` and `Comparator`**, but pay particular attention to `Comparator` because custom/multiple sorting is extremely common.
