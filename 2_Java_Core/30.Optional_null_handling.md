# Java Optional — Null Handling

`Optional<T>` is a container that represents:

```text
A value may exist OR may be absent
```

It helps reduce **`NullPointerException`** and makes null handling explicit.

Think of it somewhat like JavaScript:

```text
Java Optional<T>  ≈  value that may be undefined/null
```

---

## 1. Problem without Optional ❌

```java
String name = getName();

System.out.println(name.length()); // ❌ NullPointerException if name is null
```

You need:

```java
if (name != null) {
    System.out.println(name.length());
}
```

---

## 2. Using Optional ✅

```java
import java.util.Optional;

public class Main {
    public static void main(String[] args) {

        Optional<String> name = Optional.of("John");

        if (name.isPresent()) {
            System.out.println(name.get());
        }
    }
}
```

Output:

```text
John
```

---

## 3. Creating Optional

### `Optional.of()`

Use when you **know the value is not null**.

```java
Optional<String> name = Optional.of("John");
```

If value is `null` → throws `NullPointerException`.

### `Optional.ofNullable()`

Use when value **may be null**.

```java
String name = null;

Optional<String> result = Optional.ofNullable(name);
```

This is the commonly used one.

### `Optional.empty()`

Represents no value:

```java
Optional<String> result = Optional.empty();
```

---

# 4. `orElse()` — Default value

```java
String name = null;

String result = Optional.ofNullable(name)
        .orElse("Unknown");

System.out.println(result);
```

Output:

```text
Unknown
```

Meaning:

```text
Value exists → use it
Value absent → use "Unknown"
```

---

# 5. `orElseGet()` ⭐

Similar to `orElse()`, but useful when creating the default value involves work.

```java
String result = Optional.ofNullable(name)
        .orElseGet(() -> getDefaultName());
```

Difference:

```text
orElse()    → default expression is evaluated immediately
orElseGet() → default is evaluated only when needed
```

---

# 6. `orElseThrow()`

Useful when absence should be treated as an error.

```java
String name = Optional.ofNullable(null)
        .orElseThrow(() -> new RuntimeException("Name not found"));
```

In Spring Boot, you'll commonly see:

```java
User user = userRepository.findById(id)
        .orElseThrow(() -> new RuntimeException("User not found"));
```

This is **very important** to understand for Spring Data JPA.

```js
// Full Example
import java.util.*;

public class Main {
    public static void main(String[] args) {
      System.out.println("Hello, World!");
      try{
        String name = Optional.<String>ofNullable(null)
        .orElseThrow(() -> new RuntimeException("Name not found"));
      }catch(RuntimeException e){
        System.out.println("e: "+e);
      }
    }
}
```

---

# 7. `map()` with Optional

You can transform the value only if it exists:

```java
Optional<String> name = Optional.of("John");

Optional<Integer> length = name
        .map(String::length);

System.out.println(length.get()); // 4
```
Here:

String::length

is a method reference.

It is equivalent to:

name.map(s -> s.length());

If `name` is empty, `map()` simply produces an empty `Optional`.

---

# Important methods to remember

```text
Optional.of(value)
       → value must not be null

Optional.ofNullable(value)
       → value can be null

Optional.empty()
       → no value

isPresent()
       → check whether value exists

orElse(value)
       → default value

orElseGet(...)
       → lazily create default

orElseThrow(...)
       → throw exception if absent

map(...)
       → transform existing value
```

### ⭐ Most important Spring Boot pattern

```java
User user = userRepository.findById(id)
        .orElseThrow(() -> new UserNotFoundException("User not found"));
```

**Key idea:** `Optional` doesn't make Java completely null-safe. It gives you a cleaner, explicit way to represent and handle a value that may be absent.
