# Java 8+ Features

## 1. Lambda Expressions ⭐⭐⭐

A **lambda** is a short way to implement a functional interface.

### Before Lambda

```java
interface Calculator {
    int add(int a, int b);
}

public class Main {
    public static void main(String[] args) {
        Calculator calculator = new Calculator() {
            @Override
            public int add(int a, int b) {
                return a + b;
            }
        };

        System.out.println(calculator.add(10, 20));
    }
}

//using implements
interface Calculator{
  public int add(int a, int b);
}

class Main implements Calculator{
   @Override
    public int add(int a, int b){
      return a+b;
    };

  public static void main(String[] args){
   
    Main mainObj = new Main();
    System.out.println(mainObj.add(1,2));
  }
}
```

### With Lambda

```java
interface Calculator {
    int add(int a, int b);
}

public class Main {
    public static void main(String[] args) {
        Calculator calculator = (a, b) -> a + b;

        System.out.println(calculator.add(10, 20));
    }
}
```

Output:

```text
30
```

### Syntax

```java
(parameters) -> expression
```

or

```java
(parameters) -> {
    // statements
}
```

Examples:

```java
() -> System.out.println("Hello");

x -> x * 2;

(a, b) -> a + b;

(x, y) -> {
    int result = x + y;
    return result;
};
```

### Important

Lambda does **not** work with every interface.

It requires a **functional interface** — an interface with exactly **one abstract method**.

# 2. Functional Interface ⭐⭐⭐

A functional interface contains exactly **one abstract method**.

```java
@FunctionalInterface
interface Calculator {
    int calculate(int a, int b);
}
```

Now Lambda can implement it:

```java
Calculator add = (a, b) -> a + b;

System.out.println(add.calculate(10, 20));
```

### `@FunctionalInterface`

This annotation tells Java:

> "This interface must contain exactly one abstract method."

If someone accidentally adds another abstract method:

```java
@FunctionalInterface
interface Calculator {
    int calculate(int a, int b);

    int multiply(int a, int b); // compilation error
}
```

This is useful because the compiler catches the mistake.

# 3. Built-in Functional Interfaces ⭐⭐⭐

Java provides commonly used functional interfaces in:

```java
java.util.function
```

The four most important ones:

| Interface       | Input | Output  | Use            |
| --------------- | ----- | ------- | -------------- |
| `Predicate<T>`  | T     | boolean | Test condition |
| `Function<T,R>` | T     | R       | Transform      |
| `Consumer<T>`   | T     | void    | Consume/use    |
| `Supplier<T>`   | none  | T       | Provide value  |

---

## Predicate

Used when you want a **true/false condition**.

```java
import java.util.function.Predicate;

Predicate<Integer> isEven = number -> number % 2 == 0;

System.out.println(isEven.test(10)); // true
System.out.println(isEven.test(7));  // false
```

Think:

```text
Input → condition → true/false
```

Commonly used with Streams.

---

## Function

Used to **convert one value into another**.

```java
Function<String, Integer> length = text -> text.length();

System.out.println(length.apply("Java")); // 4

// full code
import java.util.function.*;

class Main{

  public static void main(String[] args){
   
    Function<String, Integer> length = value -> value.length();

    System.out.println(length.apply("Sk"));
  }
}
```

Think:

```text
String → Integer
```

Another example:

```java
Function<Integer, Integer> square = x -> x * x;

System.out.println(square.apply(5)); // 25
```

---

## Consumer

Takes a value but returns nothing.

```java
Consumer<String> printer = name -> System.out.println(name);

printer.accept("Java");
```

Think:

```text
Input → action
```

## Supplier

Takes no input but produces a value.


Think:

# 4. Method Reference ⭐⭐

Method reference is a shorter form of Lambda.

Instead of:

```java
Consumer<String> printer = name -> System.out.println(name);
```

you can write:

```java
Consumer<String> printer = System.out::println;
```

Syntax:

```java
ClassName::methodName
```

### Example

```java
List<String> names = List.of("John", "Bob", "Alice");

names.forEach(name -> System.out.println(name));
```

Can become:

```java
names.forEach(System.out::println);
```

Another example:

```java
Function<String, Integer> converter = text -> Integer.parseInt(text);
```

becomes:

```java
Function<String, Integer> converter = Integer::parseInt;
```

### Simple rule

If your Lambda is simply:

```java
x -> object.method(x)
```

look for a possible method reference:

```java
object::method
```

# 5. Stream API ⭐⭐⭐⭐⭐

This is **very important for Spring Boot interviews and real-world Java code**.

Streams allow you to process collections in a declarative style.

Instead of manually:

```java
List<Integer> numbers = List.of(1, 2, 3, 4, 5);

for (Integer number : numbers) {
    if (number % 2 == 0) {
        System.out.println(number);
    }
}
```

you can write:

```java
numbers.stream()
       .filter(number -> number % 2 == 0)
       .forEach(System.out::println);
```

Output:

```text
2
4
```

### Common Stream operations

```text
stream()
   ↓
filter()
   ↓
map()
   ↓
sorted()
   ↓
collect()
```

Example:

```java
List<String> names = List.of("John", "Bob", "Alice", "David");

List<String> result = names.stream()
        .filter(name -> name.length() > 4)
        .map(String::toUpperCase)
        .sorted()
        .toList();

System.out.println(result);
```

Output:

```text
[ALICE, DAVID]
```

### Important distinction

`filter()`:

```java
.filter(x -> x > 10)
```

removes unwanted elements.

`map()`:

```java
.map(x -> x * 2)
```

transforms elements.

You'll use these heavily with database/API data in Spring Boot.

# 6. Optional ⭐⭐⭐⭐

`Optional<T>` represents:

> A value that may or may not exist.

It helps reduce accidental `NullPointerException`.

Instead of:

```java
String name = getName();

if (name != null) {
    System.out.println(name);
}
```

you can have:

```java
Optional<String> name = Optional.ofNullable(getName());

name.ifPresent(System.out::println);
```

### Common methods

```java
Optional.of(value);
Optional.ofNullable(value);
Optional.empty();

isPresent();
ifPresent();
orElse();
orElseGet();
orElseThrow();
```

Example:

```java
Optional<String> name = Optional.ofNullable(null);

String result = name.orElse("Unknown");

System.out.println(result);
```

Output:

```text
Unknown
```

### Very important in Spring Boot

You will commonly see:

```java
Optional<User> user = userRepository.findById(id);
```

Then:

```java
User result = user.orElseThrow(
    () -> new RuntimeException("User not found")
);
```

Implementation:


```java

car.start();
```


Why?

Java needed a way to add methods to existing interfaces without breaking all existing implementations.

# 14. Records — Java 16+ ⭐⭐⭐⭐

Very important for modern Java and especially useful for **DTOs**.

Instead of:

```java
class User {
    private final String name;
    private final int age;

    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() {
        return name;
    }

    public int getAge() {
        return age;
    }
}
```

You can write:

```java
record User(String name, int age) {
}
```

Usage:

```java
User user = new User("John", 25);

System.out.println(user.name());
System.out.println(user.age());
```

Records automatically provide:

* constructor
* accessors
* `equals()`
* `hashCode()`
* `toString()`

Records are **immutable data carriers** by design.


```js
// record full example

record User(int id, String name, String email) {

    // Custom method
    public String getDisplayName() {
        return name + " (" + email + ")";
    }
}

public class Main {

    public static void main(String[] args) {

        // Create record object
        User user = new User(
                101,
                "John",
                "john@gmail.com"
        );

        // Access fields
        System.out.println("ID: " + user.id());
        System.out.println("Name: " + user.name());
        System.out.println("Email: " + user.email());

        // Custom method
        System.out.println(user.getDisplayName());

        // Automatically generated toString()
        System.out.println(user);

        // Automatically generated equals()
        User user2 = new User(
                101,
                "John",
                "john@gmail.com"
        );

        System.out.println(user.equals(user2));
    }
}

```

## Record Class in Java — Short Notes

Definition: A `record` is a special kind of class introduced in Java 16 that simplifies creating data-carrier classes by automatically generating a constructor, accessors, `equals()`, `hashCode()`, and `toString()`.

### 1. Example

```
record Employee(int id, String name) {
}

public class Main {
    public static void main(String[] args) {
        Employee emp = new Employee(101, "Arun");

        System.out.println(emp.id());   // 101
        System.out.println(emp.name()); // Arun
        System.out.println(emp);        // Employee[id=101, name=Arun]
    }
}
```

Java automatically provides:

- Canonical constructor: `Employee(int id, String name)`
- Accessor methods: `id()` and `name()`
- `equals()` and `hashCode()`
- `toString()`

### 2. Important rules

- Records are implicitly `final`; they cannot be extended.
- A record can implement interfaces but cannot extend another class.
- Record components are implicitly `private final`.
- Records cannot declare additional instance fields, but can declare static fields.
- Records can have custom constructors and methods.
- A record is only shallowly immutable; mutable objects stored in its components can still change.

### 3. Record vs normal class

| Feature                   | Record                      | Normal class                |
| ------------------------- | --------------------------- | --------------------------- |
| Constructor               | Generated automatically     | Usually written manually    |
| Accessors                 | Generated automatically     | Usually written manually    |
| `equals()` / `hashCode()` | Generated from components   | Inherited unless overridden |
| Inheritance               | Cannot extend another class | Can extend a class          |
| Mutability                | Components are final        | Depends on implementation   |

### 4. Record with a custom constructor

```
record Employee(int id, String name) {
    Employee {
        if (id <= 0) {
            throw new IllegalArgumentException("ID must be positive");
        }
    }
}
```

This is a compact canonical constructor. Java assigns the component values automatically after the constructor body completes successfully.

Interview point: Records are ideal for DTOs and simple data carriers when you want concise code and value-based equality.


## Why do we need `record` in Java?

Main purpose: `record` reduces boilerplate code when creating classes whose primary purpose is to store and transfer data.

### 1. Without `record` — normal class

```
class Employee {
    private final int id;
    private final String name;

    Employee(int id, String name) {
        this.id = id;
        this.name = name;
    }

    public int getId() { return id; }
    public String getName() { return name; }

    @Override
    public String toString() {
        return "Employee[id=" + id + ", name=" + name + "]";
    }

    // equals() and hashCode() also need implementation
}
```

### 2. With `record`

```
record Employee(int id, String name) {
}
```

Java automatically generates the constructor, accessor methods, `equals()`, `hashCode()`, and `toString()`.

Usage:

```
Employee emp = new Employee(101, "Arun");

System.out.println(emp.id());   // 101
System.out.println(emp.name()); // Arun
```

### 3. Where do we use records?

- DTOs: Transfer data between frontend and backend in Spring Boot.
- API responses: Represent response data returned as JSON.
- Data carriers: Store values such as employee details, product details, or coordinates.
- Value-based objects: Compare objects based on their component values.

### Interview point

Why records instead of normal classes?

Records reduce boilerplate, provide final component fields, and automatically implement value-based `equals()`, `hashCode()`, and `toString()`.

Note: Records are shallowly immutable, and they cannot extend another class. Use a normal class when you need mutable fields or more flexible inheritance.

# 15. Sealed Classes — Java 17 ⭐⭐⭐

Sealed classes restrict which classes can extend them.

```java
sealed class Vehicle
        permits Car, Bike {
}

final class Car extends Vehicle {
}

final class Bike extends Vehicle {
}
```

Now another class cannot arbitrarily extend `Vehicle`.

Useful when you want a controlled class hierarchy.

```js
// working example
sealed class Vehicle permits Car, Bike {
    
    void start() {
        System.out.println("Vehicle started");
    }
}

final class Car extends Vehicle {
}

final class Bike extends Vehicle {
}

public class Main {
    public static void main(String[] args) {

        Vehicle car = new Car();
        Vehicle bike = new Bike();

        car.start();
        bike.start();
    }
}
```

## Sealed Class in Java — Short Notes

Definition: A `sealed` class (introduced in Java 17) restricts which classes can extend it. It provides controlled inheritance.

### Example

```
sealed class Animal permits Dog, Cat {
}

final class Dog extends Animal {
}

non-sealed class Cat extends Animal {
}

class Tiger extends Cat {
}
```

### Three permitted subclass modifiers

| Modifier     | Meaning                                               |
| ------------ | ----------------------------------------------------- |
| `final`      | Cannot be extended further                            |
| `sealed`     | Can be extended only by specified permitted classes   |
| `non-sealed` | Removes the inheritance restriction for that subclass |

### Important rules

- Use `permits` to specify allowed direct subclasses when they are not inferred automatically.
- Every direct subclass of a sealed class must be declared `final`, `sealed`, or `non-sealed`.
- A sealed class controls who can inherit, not whether objects can be created.
- Sealed classes can also implement controlled inheritance with interfaces.

### Interview point

Why use sealed classes?

To restrict inheritance, enforce a known set of subclasses, and make domain models safer and easier to maintain.

When an interface extends a sealed interface, the child interface must also be declared `sealed` or `non-sealed`.

### Example 1: Sealed interface extends sealed interface

```
sealed interface Animal permits Pet {
}

sealed interface Pet extends Animal permits Dog {
}

final class Dog implements Pet {
}
```

Here:

- `Animal` permits only `Pet`.
- `Pet` extends `Animal` and permits only `Dog`.
- `Dog` is `final`, so no class can extend it.

### Example 2: Non-sealed child interface

```
sealed interface Animal permits Pet {
}

non-sealed interface Pet extends Animal {
}

class Dog implements Pet {
}

class Cat implements Pet {
}
```

Here, `Animal` restricts its direct child to `Pet`, but `Pet` allows any eligible class to implement it.

### Important rule

| Child declaration                         | Allowed?              |
| ----------------------------------------- | --------------------- |
| `sealed interface Pet extends Animal`     | Yes                   |
| `non-sealed interface Pet extends Animal` | Yes                   |
| `interface Pet extends Animal`            | No — missing modifier |

Interview point: Every direct subtype of a sealed type must explicitly declare `final`, `sealed`, or `non-sealed`. For an interface extending another interface, `final` is not allowed because interfaces cannot be final.


An interface cannot be final because interfaces are designed to be extended or implemented, while final prevents inheritance.

Example
```java 
interface Animal {
    void sound();
}

// Invalid: interface cannot be final
// final interface Dog extends Animal { }
```


Why?
- Interface: Defines a contract that other interfaces can extend and classes can implement.
- final class: Prevents other classes from extending it.
- final interface: Would conflict with the purpose of interface inheritance.

## Constructor Reference in Java

Constructor reference is a shorthand for a lambda expression that creates an object using a constructor. It uses the `::new` syntax.

### 1. Basic example

```
import java.util.function.Supplier;

class User {
    User() {
        System.out.println("User object created");
    }
}

public class Main {
    public static void main(String[] args) {
        Supplier<User> supplier = User::new;

        User user = supplier.get();
    }
}
```

Output:

```
User object created
```

`User::new` is equivalent to `() -> new User()`.

### 2. Constructor reference with parameters

```
import java.util.function.Function;

class User {
    String name;

    User(String name) {
        this.name = name;
    }
}

public class Main {
    public static void main(String[] args) {
        Function<String, User> creator = User::new;

        User user = creator.apply("Kumar");
        System.out.println(user.name); // Kumar
    }
}
```

`User::new` is equivalent to `name -> new User(name)`.

### 3. Constructor reference with Streams

Useful when converting a list of values into objects.

```
import java.util.*;
import java.util.stream.Collectors;

class User {
    String name;

    User(String name) {
        this.name = name;
    }

    @Override
    public String toString() {
        return name;
    }
}

public class Main {
    public static void main(String[] args) {
        List<String> names = Arrays.asList("Arun", "Kumar", "Ravi");

        List<User> users = names.stream()
                .map(User::new)
                .collect(Collectors.toList());

        System.out.println(users);
    }
}
```

Output:

```
[Arun, Kumar, Ravi]
```

Here, `map(User::new)` creates a new `User` object for each name.

### Interview notes

- Syntax: `ClassName::new`
- It is a special type of method reference.
- It works with functional interfaces such as `Supplier`, `Function`, and `BiFunction`, depending on the constructor parameters.
- The compiler selects the matching constructor based on the functional interface's method signature.
- A constructor reference does not create an object immediately; the object is created when the functional interface method is invoked.
