# Java 8+ Features

## 1. Lambda Expressions ⭐⭐⭐

A **lambda** is a short way to implement a functional interface.

### Before Lambda

```java
interface Calculator {
    int add(int a, int b);
}

public class Main {
    public static void main(String[] args) {
        Calculator calculator = new Calculator() {
            @Override
            public int add(int a, int b) {
                return a + b;
            }
        };

        System.out.println(calculator.add(10, 20));
    }
}

//using implements
interface Calculator{
  public int add(int a, int b);
}

class Main implements Calculator{
   @Override
    public int add(int a, int b){
      return a+b;
    };

  public static void main(String[] args){
   
    Main mainObj = new Main();
    System.out.println(mainObj.add(1,2));
  }
}
```

### With Lambda

```java
interface Calculator {
    int add(int a, int b);
}

public class Main {
    public static void main(String[] args) {
        Calculator calculator = (a, b) -> a + b;

        System.out.println(calculator.add(10, 20));
    }
}
```

Output:

```text
30
```

### Syntax

```java
(parameters) -> expression
```

or

```java
(parameters) -> {
    // statements
}
```

Examples:

```java
() -> System.out.println("Hello");

x -> x * 2;

(a, b) -> a + b;

(x, y) -> {
    int result = x + y;
    return result;
};
```

### Important

Lambda does **not** work with every interface.

It requires a **functional interface** — an interface with exactly **one abstract method**.

# 2. Functional Interface ⭐⭐⭐

A functional interface contains exactly **one abstract method**.

```java
@FunctionalInterface
interface Calculator {
    int calculate(int a, int b);
}
```

Now Lambda can implement it:

```java
Calculator add = (a, b) -> a + b;

System.out.println(add.calculate(10, 20));
```

### `@FunctionalInterface`

This annotation tells Java:

> "This interface must contain exactly one abstract method."

If someone accidentally adds another abstract method:

```java
@FunctionalInterface
interface Calculator {
    int calculate(int a, int b);

    int multiply(int a, int b); // compilation error
}
```

This is useful because the compiler catches the mistake.

# 3. Built-in Functional Interfaces ⭐⭐⭐

Java provides commonly used functional interfaces in:

```java
java.util.function
```

The four most important ones:

| Interface       | Input | Output  | Use            |
| --------------- | ----- | ------- | -------------- |
| `Predicate<T>`  | T     | boolean | Test condition |
| `Function<T,R>` | T     | R       | Transform      |
| `Consumer<T>`   | T     | void    | Consume/use    |
| `Supplier<T>`   | none  | T       | Provide value  |

---

## Predicate

Used when you want a **true/false condition**.

```java
import java.util.function.Predicate;

Predicate<Integer> isEven = number -> number % 2 == 0;

System.out.println(isEven.test(10)); // true
System.out.println(isEven.test(7));  // false
```

Think:

```text
Input → condition → true/false
```

Commonly used with Streams.

---

## Function

Used to **convert one value into another**.

```java
Function<String, Integer> length = text -> text.length();

System.out.println(length.apply("Java")); // 4

// full code
import java.util.function.*;

class Main{

  public static void main(String[] args){
   
    Function<String, Integer> length = value -> value.length();

    System.out.println(length.apply("Sk"));
  }
}
```

Think:

```text
String → Integer
```

Another example:

```java
Function<Integer, Integer> square = x -> x * x;

System.out.println(square.apply(5)); // 25
```

---

## Consumer

Takes a value but returns nothing.

```java
Consumer<String> printer = name -> System.out.println(name);

printer.accept("Java");
```

Think:

```text
Input → action
```

---

## Supplier

Takes no input but produces a value.

```java
Supplier<String> message = () -> "Hello Java";

System.out.println(message.get());
```

Think:

```text
nothing → value
```

# 4. Method Reference ⭐⭐

Method reference is a shorter form of Lambda.

Instead of:

```java
Consumer<String> printer = name -> System.out.println(name);
```

you can write:

```java
Consumer<String> printer = System.out::println;
```

Syntax:

```java
ClassName::methodName
```

### Example

```java
List<String> names = List.of("John", "Bob", "Alice");

names.forEach(name -> System.out.println(name));
```

Can become:

```java
names.forEach(System.out::println);
```

Another example:

```java
Function<String, Integer> converter = text -> Integer.parseInt(text);
```

becomes:

```java
Function<String, Integer> converter = Integer::parseInt;
```

### Simple rule

If your Lambda is simply:

```java
x -> object.method(x)
```

look for a possible method reference:

```java
object::method
```

# 5. Stream API ⭐⭐⭐⭐⭐

This is **very important for Spring Boot interviews and real-world Java code**.

Streams allow you to process collections in a declarative style.

Instead of manually:

```java
List<Integer> numbers = List.of(1, 2, 3, 4, 5);

for (Integer number : numbers) {
    if (number % 2 == 0) {
        System.out.println(number);
    }
}
```

you can write:

```java
numbers.stream()
       .filter(number -> number % 2 == 0)
       .forEach(System.out::println);
```

Output:

```text
2
4
```

### Common Stream operations

```text
stream()
   ↓
filter()
   ↓
map()
   ↓
sorted()
   ↓
collect()
```

Example:

```java
List<String> names = List.of("John", "Bob", "Alice", "David");

List<String> result = names.stream()
        .filter(name -> name.length() > 4)
        .map(String::toUpperCase)
        .sorted()
        .toList();

System.out.println(result);
```

Output:

```text
[ALICE, DAVID]
```

### Important distinction

`filter()`:

```java
.filter(x -> x > 10)
```

removes unwanted elements.

`map()`:

```java
.map(x -> x * 2)
```

transforms elements.

You'll use these heavily with database/API data in Spring Boot.

# 6. Optional ⭐⭐⭐⭐

`Optional<T>` represents:

> A value that may or may not exist.

It helps reduce accidental `NullPointerException`.

Instead of:

```java
String name = getName();

if (name != null) {
    System.out.println(name);
}
```

you can have:

```java
Optional<String> name = Optional.ofNullable(getName());

name.ifPresent(System.out::println);
```

### Common methods

```java
Optional.of(value);
Optional.ofNullable(value);
Optional.empty();

isPresent();
ifPresent();
orElse();
orElseGet();
orElseThrow();
```

Example:

```java
Optional<String> name = Optional.ofNullable(null);

String result = name.orElse("Unknown");

System.out.println(result);
```

Output:

```text
Unknown
```

### Very important in Spring Boot

You will commonly see:

```java
Optional<User> user = userRepository.findById(id);
```

Then:

```java
User result = user.orElseThrow(
    () -> new RuntimeException("User not found")
);
```

# 7. Default and Static Methods in Interfaces

Java 8 allows interfaces to contain `default` methods.

```java
interface Vehicle {

    void drive();

    default void start() {
        System.out.println("Vehicle started");
    }
}
```

Implementation:

```java
class Car implements Vehicle {

    @Override
    public void drive() {
        System.out.println("Car driving");
    }
}
```

Now:

```java
Car car = new Car();

car.start();
car.drive();
```

Output:

```text
Vehicle started
Car driving
```

Why?

Java needed a way to add methods to existing interfaces without breaking all existing implementations.

import java.time.LocalDate;

# 11. Interface Private Methods — Java 9+

Java 9 allows private methods inside interfaces.

```java
interface Calculator {

    default void calculate() {
        log();
    }

    private void log() {
        System.out.println("Calculating...");
    }
}
```

The private method can only be used inside the interface.

# 12. `var` — Java 10+

Local variable type inference:

```java
var name = "John";
var age = 25;
var numbers = List.of(1, 2, 3);
```

Java determines:

```text
name    → String
age     → Integer
numbers → List<Integer>
```

Important:

```java
var name;
```

❌ Invalid.

You must initialize it:

```java
var name = "John";
```

Also, `var` does **not** mean dynamically typed.

Java is still statically typed.

# 13. Switch Expressions — Java 14+

Modern switch:

```java
int day = 2;

String result = switch (day) {
    case 1 -> "Monday";
    case 2 -> "Tuesday";
    default -> "Other";
};

System.out.println(result);
```

Can also use:

```java
String result = switch (day) {
    case 1, 7 -> "Weekend";
    case 2, 3, 4, 5, 6 -> "Weekday";
    default -> "Invalid";
};
```

# 14. Records — Java 16+ ⭐⭐⭐⭐

Very important for modern Java and especially useful for **DTOs**.

Instead of:

```java
class User {
    private final String name;
    private final int age;

    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() {
        return name;
    }

    public int getAge() {
        return age;
    }
}
```

You can write:

```java
record User(String name, int age) {
}
```

Usage:

```java
User user = new User("John", 25);

System.out.println(user.name());
System.out.println(user.age());
```

Records automatically provide:

* constructor
* accessors
* `equals()`
* `hashCode()`
* `toString()`

Records are **immutable data carriers** by design.


```js
// record full example

record User(int id, String name, String email) {

    // Custom method
    public String getDisplayName() {
        return name + " (" + email + ")";
    }
}

public class Main {

    public static void main(String[] args) {

        // Create record object
        User user = new User(
                101,
                "John",
                "john@gmail.com"
        );

        // Access fields
        System.out.println("ID: " + user.id());
        System.out.println("Name: " + user.name());
        System.out.println("Email: " + user.email());

        // Custom method
        System.out.println(user.getDisplayName());

        // Automatically generated toString()
        System.out.println(user);

        // Automatically generated equals()
        User user2 = new User(
                101,
                "John",
                "john@gmail.com"
        );

        System.out.println(user.equals(user2));
    }
}

```

# 15. Sealed Classes — Java 17 ⭐⭐⭐

Sealed classes restrict which classes can extend them.

```java
sealed class Vehicle
        permits Car, Bike {
}

final class Car extends Vehicle {
}

final class Bike extends Vehicle {
}
```

Now another class cannot arbitrarily extend `Vehicle`.

Useful when you want a controlled class hierarchy.

```js
// working example
sealed class Vehicle permits Car, Bike {
    
    void start() {
        System.out.println("Vehicle started");
    }
}

final class Car extends Vehicle {
}

final class Bike extends Vehicle {
}

public class Main {
    public static void main(String[] args) {

        Vehicle car = new Car();
        Vehicle bike = new Bike();

        car.start();
        bike.start();
    }
}
```

# What You Should Prioritize

Since you're coming from **React → Java → Spring Boot**, learn them in this order:

### 🔥 Must know

```text
1. Lambda Expressions
2. Functional Interfaces
3. Predicate
4. Function
5. Consumer
6. Supplier
7. Method References
8. Stream API
9. Optional
10. Date/Time API
```

### ⭐ Modern Java

```text
11. Default/Static Interface Methods
12. List.of / Set.of / Map.of
13. var
14. Switch Expressions
15. Records
16. Sealed Classes
```

### One mental model to remember

```text
Lambda
   ↓
Functional Interface
   ↓
Predicate / Function / Consumer / Supplier
   ↓
Stream API
   ↓
filter / map / reduce / collect
   ↓
Process Collections cleanly
```

For **Spring Boot**, the most important combination is:

```java
users.stream()
     .filter(user -> user.getAge() >= 18)
     .map(User::getName)
     .toList();
```

Here you're simultaneously using:

* **Lambda** → `user -> user.getAge() >= 18`
* **Predicate** → `filter(...)`
* **Method reference** → `User::getName`
* **Function** → `map(...)`
* **Stream API** → `users.stream()`
* **Collection** → resulting `List`

**This is the Java 8+ style you should become comfortable reading and writing before moving deeply into Spring Boot.**
