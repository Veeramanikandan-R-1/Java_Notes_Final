## Garbage Collection — Heap & Stack

The most important thing to understand:

> **Garbage Collector (GC) mainly manages the Heap. It does NOT clean the Stack.**

### 1. Heap

The **Heap stores objects created using `new`**.

```java
public class Main {
    public static void main(String[] args) {

        User user = new User("John");

        user = null;
    }
}

class User {
    String name;

    User(String name) {
        this.name = name;
    }
}
```

Memory conceptually:

```text
Stack                    Heap
─────────                ───────────────
user ─────────────────→ User("John")
```

After:

```java
user = null;
```

```text
Stack                    Heap
─────────                ───────────────
user = null              User("John")  ← unreachable
```

Now the `User` object is **eligible for Garbage Collection**.

GC will eventually reclaim that memory.

> **Important:** `user = null` does NOT immediately trigger GC. It only makes the object unreachable.

---

Note: When GC clears the memory?

GC runs **automatically when the JVM decides it needs to reclaim Heap memory**. There is no fixed time like “after 5 seconds.”

For example:

```java
User user = new User("John");

user = null;   // User object is now unreachable

// ...some time later...
// JVM runs GC
// → User object memory can be reclaimed
```

### When does JVM run GC?

Typically when:

* Heap memory is getting low
* JVM detects that garbage collection would be beneficial
* A GC algorithm decides it's the appropriate time

So:

```text
user = null
    ↓
Object becomes unreachable
    ↓
Object is eligible for GC
    ↓
JVM decides when to run GC
    ↓
GC finds unreachable object
    ↓
Memory is reclaimed
```

### Can we force GC?

You can request it:

```java
System.gc();
```

But **this is only a request**, not a guarantee.

```java
User user = new User("John");
user = null;

System.gc(); // JVM may run GC
```

The JVM is free to ignore the request.

### Important distinction

**Eligible for GC ≠ immediately garbage collected.**

```text
user = null
      ↓
Eligible
      ↓
(wait)
      ↓
GC runs
      ↓
Memory reclaimed
```

### One more important point

If your application has plenty of free Heap memory, the JVM may **not need to run GC immediately**.

That's why Java developers generally don't manually manage memory like:

```text
allocate → use → free
```

Instead:

> **You remove references when objects are no longer needed; the JVM's Garbage Collector eventually reclaims their memory when appropriate.**

---

## 2. Stack

Each thread has its **own Stack**.

The Stack contains method execution information, including local variables and references.

```java
public static void main(String[] args) {
    int age = 30;
    calculate(age);
}

static void calculate(int value) {
    int result = value * 2;
}
```

Conceptually:

```text
Thread Stack
┌─────────────────────┐
│ calculate()         │
│ value = 30          │
│ result = 60         │
├─────────────────────┤
│ main()              │
│ age = 30            │
└─────────────────────┘
```

When `calculate()` finishes:

```text
calculate() Stack Frame
        ↓
      removed
```

The JVM automatically removes the method's stack frame.

**No Garbage Collector is required for this.**

---

# Heap vs Stack

|            | Heap                                  | Stack                                      |
| ---------- | ------------------------------------- | ------------------------------------------ |
| Stores     | Objects                               | Method frames, local variables, references |
| Shared?    | ✅ Shared by threads                   | ❌ Each thread has its own                  |
| Managed by | Garbage Collector                     | JVM automatically                          |
| Lifetime   | Until object becomes unreachable + GC | Until method/frame finishes                |
| Example    | `new User()`                          | `int age = 30`                             |

### Very important example

```java
User user = new User("John");
```

Think:

```text
Stack                    Heap
─────────                ─────────────
user ─────────────────→ User object
                         name → "John"
```

The **reference `user`** is on the Stack, while the **User object** is on the Heap.

---

## How GC decides what to remove

GC doesn't simply remove objects that haven't been used recently.

It identifies objects that are **no longer reachable from GC roots**.

```text
GC Root
  ↓
reference
  ↓
Object A
  ↓
Object B
```

A and B are reachable → **keep them**.

If nothing can reach Object C:

```text
GC Root

Object C  ← no reference
```

Object C → **eligible for GC**.

### One-line interview answer

> **Heap stores objects and is managed by Garbage Collection; Stack is per-thread and stores method execution/local variables, with stack frames automatically removed when methods finish.**
