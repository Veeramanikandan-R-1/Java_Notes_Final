## OOP: Encapsulation

**Encapsulation = bundling data + methods together and controlling direct access to the data.**

In Java, encapsulation is mainly achieved using:

* `private` fields
* `public` getters/setters or controlled methods

### 1. Without Encapsulation ❌

```java
class BankAccount {
    public double balance;
}

class Main {
    public static void main(String[] args) {
        BankAccount account = new BankAccount();

        account.balance = -5000; // ❌ Anyone can set invalid value
    }
}
```

The `balance` can be modified directly from anywhere.

---

### 2. With Encapsulation ✅

```java
class BankAccount {
    private double balance;

    public double getBalance() {
        return balance;
    }

    public void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
        }
    }
}
```

Usage:

```java
public class Main {
    public static void main(String[] args) {

        BankAccount account = new BankAccount();

        account.deposit(5000);

        System.out.println(account.getBalance());
    }
}
```

Output:

```text
5000.0
```

Now nobody can directly do:

```java
account.balance = -5000; // ❌ Compilation error
```

They must go through the controlled method:

```java
account.deposit(5000); // ✅
```

---

### Why Encapsulation?

It provides **data protection + controlled modification**.

```text
Outside code
     │
     ▼
 public method
     │
     ▼
 private data
```

The class decides **how its internal data can be accessed or modified**.

---

### Getter vs Setter

A common pattern:

```java
class User {
    private String name;

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }
}
```

Usage:

```java
User user = new User();

user.setName("John");

System.out.println(user.getName());
```

But **don't blindly create setters for everything**. If a value shouldn't be freely changed, expose a specific business method instead.

For example:

```java
private double balance;

public void withdraw(double amount) {
    if (amount > 0 && amount <= balance) {
        balance -= amount;
    }
}
```

This is better than:

```java
setBalance(...); // ❌ allows arbitrary modification
```

### Interview Definition ⭐

> **Encapsulation is the practice of hiding an object's internal state and providing controlled access to it through methods.**

### React/JS connection

In JavaScript you can do:

```javascript
class User {
    #name;

    getName() {
        return this.#name;
    }
}
```

Java's `private` keyword provides a similar **access-control mechanism**, and Java commonly uses getters/setters or business methods to expose controlled access.
