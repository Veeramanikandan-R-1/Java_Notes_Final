## Java OOP — Inheritance

**Inheritance** allows one class to acquire the **properties (fields) and behaviors (methods)** of another class.

Think of it as an **"is-a" relationship**.

> `Dog is an Animal` → Dog can inherit from Animal.

### 1. Basic Syntax

Java uses the `extends` keyword.

```java
class Animal {
    void eat() {
        System.out.println("Eating...");
    }
}

class Dog extends Animal {
    void bark() {
        System.out.println("Barking...");
    }
}

class Main {
    public static void main(String[] args) {
        Dog dog = new Dog();

        dog.eat();   // inherited from Animal
        dog.bark();  // Dog's own method
    }
}
```

Output:

```text
Eating...
Barking...
```

Here:

```text
Animal       ← Parent / Superclass
   ↑
  Dog        ← Child / Subclass
```

---

## 2. Why use Inheritance?

Main benefits:

* **Code reuse**
* Avoid duplicate code
* Enables **method overriding**
* Foundation for **runtime polymorphism**
* Represents an **IS-A relationship**

Example:

```java
class Employee {
    String name;

    void work() {
        System.out.println("Working...");
    }
}

class Developer extends Employee {
    void writeCode() {
        System.out.println("Writing code...");
    }
}
```

`Developer` automatically gets `name` and `work()` from `Employee`.

---

## 3. Method Overriding — Very Important

A child class can provide its **own implementation** of a parent method.

```java
class Animal {
    void sound() {
        System.out.println("Some sound");
    }
}

class Dog extends Animal {
    @Override
    void sound() {
        System.out.println("Bark");
    }
}
```

Now:

```java
Dog dog = new Dog();
dog.sound();
```

Output:

```text
Bark
```

`@Override` is recommended because the compiler verifies that you're actually overriding a parent method.

---

## 4. `super` Keyword

`super` refers to the **parent class**.

### Access parent method

```java
class Animal {
    void sound() {
        System.out.println("Animal sound");
    }
}

class Dog extends Animal {
    @Override
    void sound() {
        super.sound();       // Parent method
        System.out.println("Bark");
    }
}
```

Output:

```text
Animal sound
Bark
```

### Access parent constructor

```java
class Animal {
    Animal(String name) {
        System.out.println(name);
    }
}

class Dog extends Animal {
    Dog() {
        super("Animal");  // calls parent constructor
    }
}
```

**Important:** `super(...)` must be the **first statement** in a constructor.

## 5. Types of Inheritance in Java

Java supports:

### Single

```text
A
↓
B
```

```java
class B extends A {}
```

### Multilevel

```text
A
↓
B
↓
C
```

```java
class B extends A {}
class C extends B {}
```

### Hierarchical

```text
     A
   ↙   ↘
  B     C
```

```java
class B extends A {}
class C extends A {}
```

### ❌ Multiple inheritance using classes is NOT supported

```text
   A   B
    ↘ ↙
     C
```

This is not allowed:

```java
class C extends A, B { } // ❌
```

Java avoids this ambiguity using **interfaces**.

```java
interface A{
  void methodA();
}


interface B{
  void methodB();
}

class C implements A, B {
  public void methodA(){
    System.out.println("A");
  };

  public void methodB(){
    System.out.println("B");
  };
}

class Main{
  public static void main(String[] args){
    C cObj = new C();
    cObj.methodA();
    cObj.methodB();
  }
}
```

So remember:

> **Class → extends → only one class**
> **Class → implements → multiple interfaces**

## 6. Access Modifiers and Inheritance

A child class can access:

| Parent member           | Child access   |
| ----------------------- | -------------- |
| `public`                | ✅              |
| `protected`             | ✅              |
| default/package-private | ✅ same package |
| `private`               | ❌ directly     |

Example:

```java
class Parent {
    private int a = 10;
    protected int b = 20;
}

class Child extends Parent {
    void test() {
        // System.out.println(a); // ❌ private
        System.out.println(b);    // ✅ protected
    }
}
```

**Private members are not directly accessible**, although the parent object state still exists as part of the child object.

---

## 7. Constructor Inheritance — Important

**Constructors are NOT inherited.**

But when creating a child object, the **parent constructor executes first**.

```java
class Parent {
    Parent() {
        System.out.println("Parent constructor");
    }
}

class Child extends Parent {
    Child() {
        System.out.println("Child constructor");
    }
}
```

```java
new Child();
```

Output:

```text
Parent constructor
Child constructor
```

Java implicitly puts:

```java
super();
```

as the first statement of the child constructor if you don't explicitly provide one.

## 8. Inheritance + Polymorphism

This is **very important for Spring Boot**.

```java
class Animal {
    void sound() {
        System.out.println("Animal");
    }
}

class Dog extends Animal {
    @Override
    void sound() {
        System.out.println("Dog");
    }
}

Animal animal = new Dog();

animal.sound();
```

Output:

```text
Dog
```

Although the reference is `Animal`, the actual object is `Dog`.

This is called **runtime polymorphism / dynamic method dispatch**.

You'll see this concept heavily in Java and Spring.

# Java — Why Doesn't Java Support Multiple Inheritance?

Java does not support multiple inheritance through classes mainly to avoid ambiguity and complexity, especially the Diamond Problem.

### 1. Diamond Problem

Suppose two parent classes have the same method, and a child class inherits both. Which parent's method should the child use?

```
class A {
    void display() {
        System.out.println("A");
    }
}

class B extends A { }

class C extends A { }

// Not allowed in Java:
// class D extends B, C { }
```

If both `B` and `C` override `display()`, class `D` could face ambiguity about which implementation to inherit.

### 2. How does Java handle this?

- Classes: Multiple inheritance is not supported.
- Interfaces: A class can implement multiple interfaces.

```
interface A {
    void display();
}

interface B {
    void show();
}

class C implements A, B {
    public void display() {
        System.out.println("Display");
    }

    public void show() {
        System.out.println("Show");
    }
}
```

If multiple interfaces provide conflicting default methods, Java requires the class to resolve the conflict explicitly in relevant cases.

Interview one-liner: Java avoids multiple inheritance through classes to prevent ambiguity, such as the Diamond Problem, and supports multiple inheritance of type through interfaces.

## `super()` Constructor in Java

`super()` is used to call the parent class constructor from the child class constructor.

### 1. Non-Parameterized Constructor

A constructor without parameters.

```
class Parent {
    Parent() {
        System.out.println("Parent constructor");
    }
}

class Child extends Parent {
    Child() {
        super(); // Calls Parent's non-parameterized constructor
        System.out.println("Child constructor");
    }
}

public class Main {
    public static void main(String[] args) {
        Child obj = new Child();
    }
}
```

Output:

```
Parent constructor
Child constructor
```

### 2. Parameterized Constructor

A constructor that accepts parameters.

```
class Parent {
    Parent(String name) {
        System.out.println("Name: " + name);
    }
}

class Child extends Parent {
    Child() {
        super("Java"); // Calls Parent's parameterized constructor
        System.out.println("Child constructor");
    }
}

public class Main {
    public static void main(String[] args) {
        Child obj = new Child();
    }
}
```

Output:

```
Name: Java
Child constructor
```

### Important points

- `super()` calls the parent’s non-parameterized constructor.
- `super(arguments)` calls the matching parameterized constructor.
- The `super()` call must be the first statement in the constructor.
- If you don't explicitly write `super()`, Java inserts it automatically only when the parent has an accessible no-argument constructor.
- If the parent has only a parameterized constructor, you must explicitly call it using `super(arguments)`.

---

### Is every class in Java extended from `Object`?

Yes. Every Java class directly or indirectly inherits from the `Object` class, which belongs to the `java.lang` package.

### Example

```
class A {
    void display() {
        System.out.println("Hello Java");
    }
}

// Equivalent to: class A extends Object
```

Java automatically makes `A` extend `Object` if no other parent class is specified.

so we can use super() inside the constructor of parent class as well
### Important points

- `Object` is the root class of Java's class hierarchy.
- Every class inherits methods such as `toString()`, `equals()`, and `hashCode()` from `Object`.
- If a class extends another class, it indirectly inherits from `Object` through its parent.

Remember: Java supports single inheritance for classes, and `Object` is the ultimate parent of every class (except `Object` itself).

## `this()` Inside a Constructor in Java

`this()` is used to call another constructor of the same class. It helps avoid duplicate code.

### Example

```
class Student {
    Student() {
        this("Java"); // Calls parameterized constructor
        System.out.println("Default constructor");
    }

    Student(String name) {
        System.out.println("Name: " + name);
    }
}

public class Main {
    public static void main(String[] args) {
        Student s = new Student();
    }
}
```

Output:

```
Name: Java
Default constructor
```

### Important points

- `this()` calls a non-parameterized or parameterized constructor in the same class, depending on the arguments.
- It must be the first statement inside the constructor.
- It helps reuse constructor logic and avoid code duplication.
- A constructor cannot directly or indirectly call itself recursively using `this()`.

Remember:

- `this()` → calls a constructor in the same class.
- `super()` → calls a constructor in the parent class.

## Method Overloading vs Method Overriding in Java

| Feature      | Overloading                                                     | Overriding                                  |
| ------------ | --------------------------------------------------------------- | ------------------------------------------- |
| Meaning      | Same method name, different parameters                          | Child class redefines a parent class method |
| Inheritance  | Not required                                                    | Required                                    |
| Parameters   | Must be different                                               | Must be the same                            |
| Return type  | Can differ if parameter lists differ (not by return type alone) | Same or covariant return type               |
| Polymorphism | Compile-time                                                    | Runtime                                     |
| `@Override`  | Not used                                                        | Recommended                                 |

### 1. Method Overloading

Same method name with different parameters in the same class.

```
class Calculator {
    int add(int a, int b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }
}
```

### 2. Method Overriding

A child class provides its own implementation of an inherited method.

```
class Parent {
    void display() {
        System.out.println("Parent");
    }
}

class Child extends Parent {
    @Override
    void display() {
        System.out.println("Child");
    }
}
```

Remember:

- Overloading: Same name, different parameters.
- Overriding: Same method signature, different implementation in the child class.

### How to Stop Inheritance in Java

Use the `final` keyword before a class. A `final` class cannot be extended by another class.

```
final class Parent {
    void display() {
        System.out.println("Parent class");
    }
}

// Compilation error: cannot inherit from final Parent
class Child extends Parent {
}
```

Remember:

- `final class` → Prevents inheritance.
- `final method` → Prevents method overriding.
- `final variable` → Prevents reassignment after initialization.

---

### Final Method in Java

A `final` method cannot be overridden by a child class.

```
class Parent {
    final void display() {
        System.out.println("Parent display()");
    }
}

class Child extends Parent {
    // Compilation error: cannot override final method
    // void display() {
    //     System.out.println("Child display()");
    // }
}

public class Main {
    public static void main(String[] args) {
        Child obj = new Child();
        obj.display();
    }
}
```

Output:

```
Parent display()
```

Remember: `final` method → Inherited by the child class, but cannot be overridden.
