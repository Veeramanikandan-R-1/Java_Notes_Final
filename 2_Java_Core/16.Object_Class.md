# Java `Object` Class

In Java, **every class ultimately inherits from `Object`**.

So if you create:

```java
class User {
    String name;
}
```

Java internally treats it roughly like:

```java
class User extends Object {
    String name;
}
```

That means every object gets methods like:

```java
equals()
hashCode()
toString()
clone()
```

---

## 1. `equals()` — "Are these two objects equal?"

Suppose:

```java
User u1 = new User();
u1.name = "John";

User u2 = new User();
u2.name = "John";
```

Both contain `"John"`, but they are **two different objects**.

```java
System.out.println(u1.equals(u2));
```

By default:

```text
false
```

Because `Object.equals()` checks whether they are the **same object in memory**.

### If you want to compare their data

You override `equals()`:

```java
@Override
public boolean equals(Object obj) {
    User user = (User) obj;
    return this.name.equals(user.name);
}
```

Now:

```java
u1.equals(u2)
```

returns:

```text
true
```

```js
// full example
class User {
    String name;

    @Override
    public boolean equals(Object obj) {
        User user = (User) obj;
        return this.name.equals(user.name);
    }
}

class Main {
    public static void main(String[] args) {

        User u1 = new User();
        u1.name = "mani";

        User u2 = new User();
        u2.name = "Sudharshan";

        System.out.println(u1.equals(u2)); // false
    }
}
```

### Remember

```text
==       → same object/reference?
equals() → logically same data?
```

---

# 2. `hashCode()` — "Give this object a hash number"

```java
User u1 = new User();
u1.name = "John";

System.out.println(u1.hashCode());
```

It returns an integer such as:

```text
12345678
```

You don't normally care about the exact number.

It's mainly used by collections such as:

```java
HashMap
HashSet
HashTable
```

### Most important rule

If:

```java
u1.equals(u2) == true
```

then:

```java
u1.hashCode() == u2.hashCode()
```

**must also be true.**

Therefore, when you override `equals()`, you should also override `hashCode()`.

Example:

```java
@Override
public int hashCode() {
    return name.hashCode();
}
```

### Easy way to remember

```text
equals()   → "Are these objects equal?"
hashCode() → "Which hash bucket should this object go to?"
```
---

note: when we use object hashcode basically?

Basically, you use `hashCode()` when Java needs to **quickly find/store objects in hash-based collections**.

The most common ones are:

```java
HashMap
HashSet
Hashtable
```

### Example: `HashSet`

```java
Set<User> users = new HashSet<>();

users.add(u1);
users.add(u2);
```

When adding an object to `HashSet`, Java roughly does:

```text
Object
  ↓
hashCode()
  ↓
Find bucket/location
  ↓
equals() if needed
  ↓
Store / reject duplicate
```

So `hashCode()` is mainly used for **fast lookup**.

### Simple example

```java
class User {
    String name;

    @Override
    public int hashCode() {
        return name.hashCode();
    }

    @Override
    public boolean equals(Object obj) {
        User user = (User) obj;
        return name.equals(user.name);
    }
}
```

Then:

```java
User u1 = new User();
u1.name = "mani";

User u2 = new User();
u2.name = "mani";

Set<User> set = new HashSet<>();

set.add(u1);
set.add(u2);

System.out.println(set.size());
```

Output:

```text
1
```

Because:

```text
u1.equals(u2) → true
u1.hashCode() == u2.hashCode() → true
```

### 🧠 Remember this

> **`hashCode()` = helps Java find an object quickly.**
> **`equals()` = confirms whether two objects are actually equal.**

You usually **don't call `hashCode()` manually**. Java collections call it internally.

# 3. `toString()` — "Convert object to readable text"

Suppose:

```java
User user = new User();
user.name = "John";

System.out.println(user);
```

Without overriding `toString()`, you might get:

```text
User@5acf9800
```

Not very useful.

Override it:

```java
@Override
public String toString() {
    return "User{name='" + name + "'}";
}
```

Now:

```java
System.out.println(user);
```

gives:

```text
User{name='John'}
```

### Easy way to remember

```text
toString() → object → readable String
```

Very useful for **logging and debugging**.

# 4. `clone()` — "Make a copy of this object"

Suppose:

```java
User u1 = new User();
u1.name = "John";
```

You want another object with the same data.

```java
User u2 = u1.clone();
```

Now:

```text
u1 → User("John")
u2 → User("John")
```

They are **two separate objects**.

A basic implementation:

```java
class User implements Cloneable {

    String name;

    @Override
    public User clone() throws CloneNotSupportedException {
        return (User) super.clone();
    }
}
```

Usage:

```java
User u1 = new User();
u1.name = "John";

User u2 = u1.clone();

System.out.println(u2.name); // John
```

### Important

`clone()` performs a **shallow copy** by default.

For learning Java/Spring Boot, remember:

> `clone()` is an older Java mechanism for copying objects. In real applications, constructors, copy constructors, or mapping libraries are often preferred.

```js
// clone full example

class Main {
    public static void main(String[] args) {

        User u1 = new User();
        u1.name = "mani";

        try {
            User u2 = u1.clone();

            System.out.println(u1 == u2); // false
            System.out.println(u2.name);  // mani

        } catch (CloneNotSupportedException e) {
            e.printStackTrace();
        }
    }
}

```

# 🔥 Final Cheat Sheet

| Method       | Simple meaning                     | Common use           |
| ------------ | ---------------------------------- | -------------------- |
| `equals()`   | Are these objects logically equal? | Comparing objects    |
| `hashCode()` | Generate hash number               | `HashMap`, `HashSet` |
| `toString()` | Object → readable text             | Debugging/logging    |
| `clone()`    | Create a copy                      | Object copying       |

### The most important relationship

```text
equals()
   ↓
If true
   ↓
hashCode() MUST be same
```

### One example combining all three important methods

```java
class User {

    String name;

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (!(obj instanceof User)) return false;

        User user = (User) obj;
        return name.equals(user.name);
    }

    @Override
    public int hashCode() {
        return name.hashCode();
    }

    @Override
    public String toString() {
        return "User{name='" + name + "'}";
    }
}
```

**For your Spring Boot learning, focus especially on `equals()`, `hashCode()`, and `toString()` first.** `clone()` is less important in day-to-day Spring Boot development.
