# Java Serialization

**Serialization** means converting a Java object into a **byte stream**, so it can be stored or transferred.

```text
Java Object
    ↓ Serialization
Byte Stream
    ↓ Deserialization
Java Object
```

Common uses: saving objects to files, caching, or transferring objects.

Ah, you mean **why do we need Serialization itself**.

### Why is Serialization needed?

A Java object exists in **memory (RAM)**. If you want to **save that object to a file or send it somewhere**, you need to convert it into a format that can be stored/transferred.

```text
Java Object
   ↓
Serialization
   ↓
Byte Stream
   ↓
File / Network / Cache
```

### Simple example

Suppose you have:

```java
User user = new User("John", 30);
```

This object lives in RAM:

```text
RAM
┌──────────────┐
│ User         │
│ name = John  │
│ age = 30     │
└──────────────┘
```

If you want to save it to a file:

```java
ObjectOutputStream out =
    new ObjectOutputStream(new FileOutputStream("user.ser"));

out.writeObject(user);
```

Java converts the object into bytes:

```text
User object
    ↓
[101010101010...]
    ↓
user.ser
```

Later, you can reconstruct the object:

```java
ObjectInputStream in =
    new ObjectInputStream(new FileInputStream("user.ser"));

User user = (User) in.readObject();
```

### Real-world idea

Serialization is useful when you need to:

* 💾 **Save an object** to storage
* 📡 **Transfer an object** between systems
* ⚡ **Store objects in certain caches**
* 🔄 **Reconstruct the object later**

### One important point for Spring Boot

You should know Java serialization because it is part of Java fundamentals, but **modern Spring Boot APIs usually use JSON serialization**, not Java's `Serializable`.

For example:

```java
User user = new User("John", 30);
```

becomes JSON:

```json
{
  "name": "John",
  "age": 30
}
```

This is what you'll commonly encounter with REST APIs using Jackson.

**So remember:**

> **Serialization = converting an object into a storable/transmittable representation, and deserialization = converting it back into an object.**

No. .ser is not mandatory.

The file extension is just a naming convention. Java's ObjectOutputStream doesn't care about the extension.

All of these can work:

```js
new FileOutputStream("user.ser")
new FileOutputStream("user.dat")
new FileOutputStream("user.bin")
new FileOutputStream("user.txt")   // technically works, but misleading
```

## 1. `Serializable`

`Serializable` is a **marker interface**—it has no methods.

```java
import java.io.*;

class User implements Serializable {

    String name;
    int age;

    User(String name, int age) {
        this.name = name;
        this.age = age;
    }
}

public class Main {
    public static void main(String[] args) throws Exception {

        User user = new User("John", 30);

        // Serialization
        ObjectOutputStream out =
                new ObjectOutputStream(new FileOutputStream("user.ser"));

        out.writeObject(user);
        out.close();

        // Deserialization
        ObjectInputStream in =
                new ObjectInputStream(new FileInputStream("user.ser"));

        User result = (User) in.readObject();
        in.close();

        System.out.println(result.name); // John
        System.out.println(result.age);  // 30
    }
}
```

Because `User` implements `Serializable`, Java allows:

```java
out.writeObject(user);
```

Without it → `NotSerializableException`.

# 2. `transient`

`transient` means:

> **Do not serialize this field.**

```java
class User implements Serializable {

    String name;
    transient String password;

    User(String name, String password) {
        this.name = name;
        this.password = password;
    }
}
```

When serialized:

```text
name     → "John"       ✅ saved
password → "secret123"  ❌ not saved
```

After deserialization:

```java
System.out.println(user.password);
```

Output:

```text
null
```

### Why use `transient`?

For fields you don't want persisted/transferred, such as:

```text
password
temporary data
cached data
security-sensitive fields
```

# 3. `serialVersionUID`

`serialVersionUID` is a version identifier used during **deserialization** to check whether the serialized class is compatible with the current class.

```java
class User implements Serializable {

    private static final long serialVersionUID = 1L;

    String name;
    int age;
}
```

Think of it as:

```text
Serialized object
       ↓
serialVersionUID = 1
       ↓
Current User class
       ↓
serialVersionUID = 1
       ↓
Compatible ✅
```

If versions don't match, Java can throw:

```text
InvalidClassException
```

### Why explicitly declare it?

If you don't declare one, Java can generate one automatically based on the class structure. Changing the class can then unexpectedly change the generated ID.

So commonly write:

```java
private static final long serialVersionUID = 1L;
```

# ⭐ Remember

```text
Serializable
    ↓
Allows object serialization

transient
    ↓
Skip a field during serialization

serialVersionUID
    ↓
Version/compatibility check during deserialization
```

### One complete example

```java
class User implements Serializable {

    private static final long serialVersionUID = 1L;

    String name;
    int age;
    transient String password;
}
```

**Interview answer:**

> Serialization converts an object into a byte stream. `Serializable` enables it, `transient` excludes fields from serialization, and `serialVersionUID` identifies the serialized class version for compatibility checking.

Notes:

Q. Why can't we use JSON to store objects?

Because **Java Serialization and JSON solve similar high-level problems but for different purposes**.

### Java Serialization

Converts a Java object → **binary bytes**

```text
Java Object
    ↓ Serialization
Binary data
```

It's mainly useful for **Java-to-Java** object storage/transfer.

```java
out.writeObject(user);
```

But the result isn't human-readable.

---

### JSON

Converts an object → **text format**

```text
Java Object
    ↓ JSON serialization
{
  "name": "John",
  "age": 30
}
```

JSON is mainly used for **communication between different systems/applications**.

For example:

```text
React
   ↕ JSON
Spring Boot
   ↕ JSON
Database / Other API
```

React doesn't understand Java's `Serializable` binary format, but it easily understands JSON.

### Why JSON became popular

| Java Serialization        | JSON                             |
| ------------------------- | -------------------------------- |
| Binary                    | Text                             |
| Java-specific             | Language-independent             |
| Not human-readable        | Human-readable                   |
| Mainly Java ↔ Java        | Java ↔ React, Python, Node, etc. |
| `Serializable`            | No `Serializable` needed         |
| Less common for REST APIs | **Standard for REST APIs**       |

### In your Spring Boot learning

You'll encounter **JSON much more often**.

For example:

```java
@GetMapping("/user")
public User getUser() {
    return new User("John", 30);
}
```

Spring Boot + Jackson automatically converts:

```text
Java User object
       ↓
     JSON
       ↓
React frontend
```

```json
{
  "name": "John",
  "age": 30
}
```

**Simple rule:**

> **Java Serialization → Java object ↔ binary data**
> **JSON → object/data ↔ language-independent text, especially for APIs**

So for your **Spring Boot + React** goal, focus much more on **JSON serialization/deserialization with Jackson** than Java's `Serializable`.
