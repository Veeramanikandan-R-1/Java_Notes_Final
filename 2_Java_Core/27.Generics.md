## Java Generics — Type Safety

**Generics allow you to specify what type of data a class/collection can store.**

Main benefit: **Type Safety** — Java catches incorrect types at **compile time**, instead of allowing them to cause problems at runtime.

### Without Generics ❌

```java
import java.util.ArrayList;
import java.util.List;

public class Main {
    public static void main(String[] args) {

        List names = new ArrayList();

        names.add("John");
        names.add(100);  // Allowed!

        String name = (String) names.get(1); // Runtime error
    }
}
```

This compiles, but at runtime:

```text
ClassCastException
```

Because `100` is an `Integer`, not a `String`.

---

### With Generics ✅

```java
import java.util.ArrayList;
import java.util.List;

public class Main {
    public static void main(String[] args) {

        List<String> names = new ArrayList<>();

        names.add("John");
        names.add("Alice");

        // names.add(100); // ❌ Compile-time error

        String name = names.get(0); // No casting needed

        System.out.println(name);
    }
}
```

Java knows:

```text
List<String>
     ↓
Only String objects allowed
```

So this:

```java
names.add(100);
```

is immediately rejected by the compiler.

### Why is this called Type Safety?

```text
Without Generics
List → String + Integer + ... → Runtime problem ❌

With Generics
List<String> → Only String → Compile-time checking ✅
```

### Real-world example

You'll constantly use this in Spring Boot:

```java
List<User> users = new ArrayList<>();
```

Now:

```java
users.add(new User()); // ✅
users.add("John");     // ❌ Compile-time error
```

**Remember:**

> **Generics = compile-time type safety + less casting + cleaner code.**
