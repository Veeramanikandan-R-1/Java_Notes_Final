## Java Collections — List, Set, Queue

The **Collections Framework** provides ready-made data structures to store and manipulate groups of objects.

For Spring Boot, you will use these constantly—for example, storing API results, request data, database records, etc.

### 1. Big Picture

```text
Collection
│
├── List
│   ├── ArrayList
│   └── LinkedList
│
├── Set
│   ├── HashSet
│   ├── LinkedHashSet
│   └── TreeSet
│
└── Queue
    ├── PriorityQueue
    └── LinkedList
```

> `Map` (`HashMap`, `TreeMap`, etc.) is **not** a subtype of `Collection`. Learn it separately.

---

# 1. List

**List = ordered collection that allows duplicates.**

Think of it like a JavaScript array.

```java
List<String> names = new ArrayList<>();

names.add("John");
names.add("Alice");
names.add("John");   // duplicate allowed

System.out.println(names);
System.out.println(names.get(1));
```

Output:

```text
[John, Alice, John]
Alice
```

### Important properties

| Property              | List            |
| --------------------- | --------------- |
| Maintains order       | ✅               |
| Duplicates            | ✅               |
| Index-based access    | ✅               |
| `null`                | Usually allowed |
| Common implementation | `ArrayList`     |

### ArrayList vs LinkedList

For most applications:

```java
List<String> names = new ArrayList<>();
```

Use **ArrayList by default**.

```text
ArrayList
- Fast get(index)
- Fast iteration
- Best general-purpose List

LinkedList
- Fast insertion/removal at ends
- Slow random access
- Also implements Queue/Deque
```

### Common methods

```java
List<Integer> numbers = new ArrayList<>();

numbers.add(10);
numbers.add(20);
numbers.add(30);

numbers.get(1);       // 20
numbers.set(1, 50);   // [10, 50, 30]
numbers.remove(0);    // [50, 30]
numbers.contains(30); // true
numbers.size();       // 2
numbers.isEmpty();    // false
```

Linked List example

Sure. Since you're learning Java for Spring Boot, understand **`LinkedList` in two ways**: as a `List` and as a `Queue`.

### 1. LinkedList as a List

```java
import java.util.LinkedList;
import java.util.List;

public class Main {
    public static void main(String[] args) {

        List<String> names = new LinkedList<>();

        names.add("John");
        names.add("Alice");
        names.add("Bob");

        System.out.println(names);       // [John, Alice, Bob]
        System.out.println(names.get(1)); // Alice

        names.add(1, "David");

        System.out.println(names);       // [John, David, Alice, Bob]

        names.remove(2);

        System.out.println(names);       // [John, David, Bob]
    }
}
```

### How LinkedList works internally

Conceptually:

```text
John
 ↓
David
 ↓
Bob
```

Each node stores:

```text
[ data | next ]
```

Unlike `ArrayList`, elements aren't stored in one continuous array.

### ArrayList vs LinkedList — Short

| Feature                        | ArrayList                            | LinkedList                                |
| ------------------------------ | ------------------------------------ | ----------------------------------------- |
| Data structure                 | Dynamic array                        | Doubly linked list                        |
| `get(index)`                   | **Fast O(1)**                        | Slow O(n)                                 |
| Add at end                     | **O(1)** average                     | O(1)                                      |
| Add/remove at beginning/middle | Slow O(n)                            | **Fast O(1)** once position/node is known |
| Memory                         | Less                                 | More (stores node links)                  |
| Best for                       | **Frequent reading/access by index** | **Frequent insertion/deletion**           |

### Simple rule to remember

```text
ArrayList  → Read/access frequently
LinkedList → Insert/delete frequently
```

**Example:**

```java
List<String> users = new ArrayList<>();
// users.get(5) → very fast

List<String> users = new LinkedList<>();
// adding/removing nodes → efficient
```

👉 **In most real-world Java applications, prefer `ArrayList` unless you specifically need LinkedList behavior.**

# 2. Set

**Set = collection that does NOT allow duplicate elements.**

Think of it like JavaScript `Set`.

```java
Set<String> names = new HashSet<>();

names.add("John");
names.add("Alice");
names.add("John");

System.out.println(names);
```

Output contains only:

```text
[John, Alice]
```

The second `"John"` is ignored.

### Important properties

| Property              | Set                       |
| --------------------- | ------------------------- |
| Duplicates            | ❌                         |
| Index                 | ❌                         |
| Order                 | Depends on implementation |
| Common implementation | `HashSet`                 |

### Three important implementations

#### HashSet

```java
Set<String> names = new HashSet<>();
```

* No guaranteed order
* Fast `add`, `remove`, `contains`
* Most commonly used Set

#### LinkedHashSet

```java
Set<String> names = new LinkedHashSet<>();
```

Maintains **insertion order**.

```java
names.add("C");
names.add("A");
names.add("B");

System.out.println(names);
```

```text
[C, A, B]
```

#### TreeSet

```java
Set<Integer> numbers = new TreeSet<>();

numbers.add(30);
numbers.add(10);
numbers.add(20);

System.out.println(numbers);
```

Output:

```text
[10, 20, 30]
```

`TreeSet` maintains **sorted order**.

### LinkedHashSet Example

`LinkedHashSet` is a `Set` that:

* ❌ Does not allow duplicates
* ✅ Maintains **insertion order**
* Usually provides fast `add`, `remove`, and `contains`

```java
import java.util.LinkedHashSet;
import java.util.Set;

public class Main {
    public static void main(String[] args) {

        Set<String> names = new LinkedHashSet<>();

        names.add("John");
        names.add("Alice");
        names.add("Bob");
        names.add("Alice"); // duplicate → ignored

        System.out.println(names);
    }
}
```

Output:

```text
[John, Alice, Bob]
```

Notice:

```text
John → Alice → Bob
```

The insertion order is preserved, and the second `"Alice"` is ignored.

### `HashSet` vs `LinkedHashSet` vs `TreeSet`

```text
HashSet
 → No duplicates
 → No guaranteed order

LinkedHashSet
 → No duplicates
 → Insertion order

TreeSet
 → No duplicates
 → Sorted order
```

Example:

```java
Set<Integer> numbers = new LinkedHashSet<>();

numbers.add(30);
numbers.add(10);
numbers.add(20);
numbers.add(10);

System.out.println(numbers);
```

Output:

```text
[30, 10, 20]
```

**Interview point:** If you need **unique elements + preserve the order in which they were inserted**, use `LinkedHashSet`.

# 3. Queue

**Queue = elements are generally processed in order, usually FIFO.**

FIFO:

```text
First In → First Out

10 → 20 → 30

remove() → 10
```

Very similar to a real-world queue.

```java
Queue<String> queue = new LinkedList<>();

queue.offer("A");
queue.offer("B");
queue.offer("C");

System.out.println(queue);

System.out.println(queue.poll());
System.out.println(queue.poll());
```

Output:

```text
[A, B, C]

A
B
```

### Important Queue methods

| Method      | Purpose                    |
| ----------- | -------------------------- |
| `offer()`   | Add element                |
| `poll()`    | Remove + return head       |
| `peek()`    | View head without removing |
| `remove()`  | Remove + return head       |
| `element()` | View head                  |

| Method      | Empty Queue behavior            |
| ----------- | ------------------------------- |
| `peek()`    | Returns `null`                  |
| `element()` | Throws `NoSuchElementException` |

Example:

```java
Queue<Integer> q = new LinkedList<>();

q.peek();     // null
q.element();  // NoSuchElementException
```

Both **only view the head element** — they **do not remove it**.

👉 In practice, **prefer `peek()`** because it safely handles an empty queue.


Prefer:

```java
offer()
poll()
peek()
```

because they have safer behavior when the queue is empty.

Example:

```java
Queue<Integer> queue = new LinkedList<>();

queue.offer(10);
queue.offer(20);

System.out.println(queue.peek()); // 10
System.out.println(queue.poll()); // 10
System.out.println(queue.poll()); // 20
System.out.println(queue.poll()); // null
```

# PriorityQueue

A very important Queue implementation.

Unlike a normal FIFO queue, **PriorityQueue processes elements according to priority**.

For integers, smallest comes first by default:

```java
Queue<Integer> queue = new PriorityQueue<>();

queue.offer(30);
queue.offer(10);
queue.offer(20);

System.out.println(queue.poll()); // 10
System.out.println(queue.poll()); // 20
System.out.println(queue.poll()); // 30
```

You can make it max-first:

```java
Queue<Integer> queue =
        new PriorityQueue<>(Comparator.reverseOrder());
```

This is very important for **DSA/interviews**.

If you mean **why we write `Queue<Integer>` instead of `Queue<int>`**:

Java collections can store **objects only**, not primitive types.

```java
Queue<Integer> q = new LinkedList<>(); // ✅
Queue<int> q = new LinkedList<>();     // ❌
```

`int` → primitive
`Integer` → wrapper object

Java automatically converts between them (**autoboxing/unboxing**):

```java
q.offer(10);   // int 10 → Integer 10
int x = q.poll(); // Integer → int
```

So remember:

**Collections → use wrapper classes** (`Integer`, `Double`, `Boolean`, etc.).

# List vs Set vs Queue

|                 | List         | Set         | Queue                    |
| --------------- | ------------ | ----------- | ------------------------ |
| Duplicates      | ✅            | ❌           | ✅                        |
| Maintains order | ✅            | Depends     | Usually processing order |
| Index           | ✅            | ❌           | ❌                        |
| Main purpose    | Ordered data | Unique data | Processing data          |
| Example         | Users        | Unique IDs  | Tasks                    |

### Simple decision rule

```text
Need duplicates + order?
        ↓
       List

Need unique elements?
        ↓
       Set

Need process elements one-by-one?
        ↓
      Queue
```

# Very Important: Interface vs Implementation

In real Java code, you'll commonly write:

```java
List<String> names = new ArrayList<>();

Set<String> ids = new HashSet<>();

Queue<String> tasks = new LinkedList<>();
```

**Left side = interface**
**Right side = implementation**

This is preferred because you can change the implementation easily:

```java
List<String> names = new ArrayList<>();
```

later:

```java
List<String> names = new LinkedList<>();
```

without changing most of your application code.

### What you should remember for interviews

```text
List
 → ArrayList
 → LinkedList

Set
 → HashSet       → no order
 → LinkedHashSet → insertion order
 → TreeSet       → sorted order

Queue
 → LinkedList    → FIFO
 → PriorityQueue → priority-based
```

**Next important Collections topic:** `Map` → `HashMap`, `LinkedHashMap`, `TreeMap`, and `ConcurrentHashMap`. This is especially important for Spring Boot.
