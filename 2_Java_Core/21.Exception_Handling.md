# Exception Handling — Checked vs Unchecked

Exception handling allows Java to **handle runtime problems without crashing the application unexpectedly**.

For Spring Boot, this is especially important because you'll later use things like `@ExceptionHandler`, `@ControllerAdvice`, custom exceptions, etc.

---

## 1. What is an Exception?

An exception is an object representing an abnormal situation during program execution.

Example:

```java
int result = 10 / 0;
```

This causes:

```text
ArithmeticException
```

Without handling it, the program terminates.

---

# 2. Exception Hierarchy ⭐

The important hierarchy is:

```text
Throwable
   │
   ├── Error
   │
   └── Exception
        │
        ├── Checked Exceptions
        │
        └── RuntimeException
             │
             └── Unchecked Exceptions
```

The key difference is:

> **Checked → compiler forces you to handle or declare it.**
> **Unchecked → compiler does NOT force you to handle it.**

---

# 3. Checked Exception

A checked exception is checked by the **compiler at compile time**.

Common examples:

```text
IOException
SQLException
FileNotFoundException
```

### Example

```java
import java.io.FileReader;
import java.io.IOException;

public class Main {

    public static void main(String[] args) {

        try {
            FileReader file = new FileReader("test.txt");
            file.close();
        } catch (IOException e) {
            System.out.println("File error: " + e.getMessage());
        }
    }
}
```

Here:

```java
new FileReader("test.txt");
```

can throw `FileNotFoundException`, which is a checked exception.

Therefore Java forces you to handle it:

```java
try {
    ...
} catch (IOException e) {
    ...
}
```

or declare it using `throws`.

---

## `throws` with Checked Exception

Instead of handling it:

```java
public static void readFile() throws IOException {
    FileReader file = new FileReader("test.txt");
    file.close();
}
```

Now the responsibility is passed to the caller.

```java
public static void main(String[] args) {

    try {
        readFile();
    } catch (IOException e) {
        System.out.println("File error");
    }
}
```

### Remember

```text
Checked Exception
       ↓
Compiler says:
"Handle it OR declare it"
       ↓
try-catch OR throws
```

---

# 4. Unchecked Exception

Unchecked exceptions happen mainly because of **programming/runtime mistakes**.

They extend `RuntimeException`.

Common examples:

```text
NullPointerException
ArithmeticException
ArrayIndexOutOfBoundsException
IllegalArgumentException
NumberFormatException
```

Example:

```java
public class Main {

    public static void main(String[] args) {

        int number = 10 / 0;

        System.out.println(number);
    }
}
```

Output:

```text
Exception in thread "main" java.lang.ArithmeticException: / by zero
```

Java **doesn't force** you to handle it.

You can handle it:

```java
public class Main {

    public static void main(String[] args) {

        try {
            int number = 10 / 0;
            System.out.println(number);
        } catch (ArithmeticException e) {
            System.out.println("Cannot divide by zero");
        }
    }
}
```

Output:

```text
Cannot divide by zero
```

But this is also valid from the compiler's perspective:

```java
public static void main(String[] args) {

    int number = 10 / 0;
}
```

That's why it's called **unchecked**.

---

# 5. Checked vs Unchecked ⭐

|                      | Checked                         | Unchecked                                     |
| -------------------- | ------------------------------- | --------------------------------------------- |
| Checked by compiler? | ✅ Yes                           | ❌ No                                          |
| Parent               | `Exception`                     | `RuntimeException`                            |
| Must handle/declare? | ✅ Yes                           | ❌ No                                          |
| Usually represents   | External/recoverable conditions | Programming/runtime errors                    |
| Examples             | `IOException`, `SQLException`   | `NullPointerException`, `ArithmeticException` |

---

# 6. Very Important: `throw` vs `throws`

You'll frequently encounter both.

### `throw`

Used to **actually throw an exception**.

```java
public static void checkAge(int age) {

    if (age < 18) {
        throw new IllegalArgumentException("Age must be 18+");
    }
}
```

### `throws`

Used to **declare that a method may throw an exception**.

```java
public static void readFile() throws IOException {
    // code
}
```

Think:

```text
throw  → "I'm throwing it NOW"

throws → "This method MAY throw it"
```

```js
import java.lang.ArithmeticException;

class Main{

  public static Boolean isAgeValid(int age){
    if(age<=18){
      throw new IllegalArgumentException("less than 18");
    }
    return true;
  }

  public static void main(String[] args){
    try{
      Boolean result = isAgeValid(100);
      System.out.println("result "+result);
    }catch(IllegalArgumentException e){
      System.out.println(e);
    }
  }
}
```

# 7. Custom Unchecked Exception ⭐

Very common in Spring Boot.

```java
class UserNotFoundException extends RuntimeException {

    public UserNotFoundException(String message) {
        super(message);
    }
}
```

Use it:

```java
public class Main {

    public static void findUser(int id) {

        if (id != 1) {
            throw new UserNotFoundException("User not found: " + id);
        }

        System.out.println("User found");
    }

    public static void main(String[] args) {

        try {
            findUser(10);
        } catch (UserNotFoundException e) {
            System.out.println(e.getMessage());
        }
    }
}
```

Output:

```text
User not found: 10
```

In Spring Boot, you'll commonly create custom exceptions like:

```java
UserNotFoundException
ProductNotFoundException
InvalidOrderException
```

and handle them globally using `@ControllerAdvice`.

---

## ⭐ What you should remember

```text
Exception Handling
│
├── Checked
│     ├── Compiler checks
│     ├── try-catch OR throws required
│     └── IOException, SQLException
│
└── Unchecked
      ├── RuntimeException
      ├── Compiler doesn't force handling
      └── NPE, ArithmeticException, IllegalArgumentException
```

**For Spring Boot:** focus strongly on **unchecked exceptions + custom exceptions + `throw` + `throws` + `try/catch`**, because these concepts will directly lead into Spring's global exception handling.
