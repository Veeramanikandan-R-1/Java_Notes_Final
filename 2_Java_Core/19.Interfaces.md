# Interfaces in Java

## 1. Basic Interface

An interface defines a **contract** that implementing classes must follow.

```java
interface Animal {
    void sound();   // abstract method
}
```

A class implements it using `implements`:

```java
class Dog implements Animal {

    @Override
    public void sound() {
        System.out.println("Bark");
    }
}
```

Usage:

```java
Animal animal = new Dog();
animal.sound(); // Bark
```

### Important rules

```java
interface Animal {
    void sound();
}
```

The method is automatically:

```java
public abstract void sound();
```

So this:

```java
interface Animal {
    public abstract void sound();
}
```

and this:

```java
interface Animal {
    void sound();
}
```

are equivalent.

### Interface variables

Variables in an interface are automatically:

```java
public static final
```

Example:

```java
interface Constants {
    int MAX = 100;
}
```

Equivalent to:

```java
public static final int MAX = 100;
```

You cannot modify it:

```java
Constants.MAX = 200; // ❌ Error
```

---

### Why are interface variables `public static final` in Java?

Interface variables are constants, not instance-specific data. They are implicitly `public static final`.

- `public` — Accessible from anywhere.
- `static` — Belongs to the interface itself; no object is required.
- `final` — Cannot be reassigned after initialization.

### Example

```
interface Config {
    int MAX_LIMIT = 100;
    // Equivalent to:
    // public static final int MAX_LIMIT = 100;
}

public class Main {
    public static void main(String[] args) {
        System.out.println(Config.MAX_LIMIT); // 100

        // Config.MAX_LIMIT = 200; // Compilation error
    }
}
```

Why? Interfaces define a contract. Their variables represent shared constants rather than individual object state.

Interview point: Every variable declared in an interface must be initialized and is implicitly `public static final`.

# 2. Multiple Interfaces

Java doesn't support multiple class inheritance:

```java
class C extends A, B { } // ❌
```

But a class can implement multiple interfaces:

```java
interface Flyable {
    void fly();
}

interface Swimmable {
    void swim();
}

class Duck implements Flyable, Swimmable {

    public void fly() {
        System.out.println("Flying");
    }

    public void swim() {
        System.out.println("Swimming");
    }
}
```

This is one of the major reasons interfaces are important.

# 3. Default Methods

Before Java 8, interface methods were basically abstract.

Java 8 introduced `default` methods so we can provide an implementation inside an interface.

```java
interface Vehicle {

    void start();

    default void stop() {
        System.out.println("Vehicle stopped");
    }
}
```

Now the implementing class **doesn't have to override** `stop()`.

```java
class Car implements Vehicle {

    @Override
    public void start() {
        System.out.println("Car started");
    }
}
```

```java
Car car = new Car();

car.start();
car.stop();
```

Output:

```text
Car started
Vehicle stopped
```

### Why default methods?

Imagine an interface already used by 100 classes:

```java
interface Payment {
    void pay();
}
```

If you add a new abstract method:

```java
void refund();
```

all 100 classes must implement it.

Instead:

```java
default void refund() {
    System.out.println("Default refund");
}
```

Existing classes don't break.

### Default method can be overridden

```java
class Car implements Vehicle {

    public void start() {
        System.out.println("Car started");
    }

    @Override
    public void stop() {
        System.out.println("Car stopped differently");
    }
}
```

# 4. Static Methods

Interfaces can also have `static` methods.

```java
interface MathUtil {

    static int add(int a, int b) {
        return a + b;
    }
}
```

Call it using the **interface name**:

```java
int result = MathUtil.add(10, 20);

System.out.println(result); // 30
```

❌ You cannot call it through an object:

```java
MathUtil obj = ...;

obj.add(10, 20); // ❌
```

### Why static methods?

They are generally utility/helper methods related to the interface.

```java
interface StringUtil {

    static boolean isEmpty(String value) {
        return value == null || value.isEmpty();
    }
}
```

Usage:

```java
StringUtil.isEmpty("");
```

# 5. Functional Interface ⭐

A **functional interface** is an interface containing **exactly one abstract method**.

```java
@FunctionalInterface
interface Calculator {
    int calculate(int a, int b);
}
```

The `@FunctionalInterface` annotation tells the compiler that this interface must have exactly one abstract method.

---

## Lambda + Functional Interface

Instead of creating a class:

```java
class Addition implements Calculator {

    @Override
    public int calculate(int a, int b) {
        return a + b;
    }
}
```

we can use a lambda:

```java
Calculator add = (a, b) -> a + b;

System.out.println(add.calculate(10, 20));
```

Output:

```text
30
```

---

### working example

Yes — the example itself is valid Java, but there is one common issue: **`Calculator` must be an interface, and the lambda must be assigned to its type**.

Use this complete program:

```java
@FunctionalInterface
interface Calculator {
    int calculate(int a, int b);
}

public class Main {
    public static void main(String[] args) {

        Calculator add = (a, b) -> a + b;

        int result = add.calculate(10, 20);

        System.out.println(result);
    }
}
```

Output:

```text
30
```

### Why does this work?

This:

```java
Calculator add = (a, b) -> a + b;
```

means:

> "Create an implementation of the `calculate()` method using this lambda."

Your interface has:

```java
int calculate(int a, int b);
```

and the lambda:

```java
(a, b) -> a + b
```

provides its implementation.

So conceptually:

```text
Calculator
    |
    | calculate(10, 20)
    ↓
(a, b) -> a + b
    |
    ↓
30
```

### ❌ Common mistake

This will **not** work:

```java
int add = (a, b) -> a + b; // ❌
```

because Java doesn't know what type this lambda represents.

You need the functional interface:

```java
Calculator add = (a, b) -> a + b; // ✅
```

### React/JavaScript connection

You can think of:

```java
Calculator add = (a, b) -> a + b;
```

similar to:

```javascript
const add = (a, b) => a + b;
```

But in Java, the lambda needs a **functional interface type**.

# 6. Functional Interface Can Have Default/Static Methods

This is important.

A functional interface can have:

* **1 abstract method** ✅
* Multiple `default` methods ✅
* Multiple `static` methods ✅

Example:

```java
@FunctionalInterface
interface Calculator {

    int calculate(int a, int b);  // abstract

    default void print() {
        System.out.println("Calculator");
    }

    static void info() {
        System.out.println("Math calculator");
    }
}
```

Still a functional interface because there is only **one abstract method**.

```java

```

### Supplier

```java

```

Important built-in functional interfaces

### Inheritance in Java Interfaces

An interface can extend one or more interfaces using the `extends` keyword.

Example 1: Single interface inheritance

```
interface Animal {
    void eat();
}

interface Dog extends Animal {
    void bark();
}

class Puppy implements Dog {
    public void eat() {
        System.out.println("Eating");
    }

    public void bark() {
        System.out.println("Barking");
    }
}
```

Here, `Dog` inherits `eat()` from `Animal`. Therefore, `Puppy` must implement both methods.

Example 2: Multiple interface inheritance

```
interface A {
    void methodA();
}

interface B {
    void methodB();
}

interface C extends A, B {
    void methodC();
}
```

Here, interface `C` inherits methods from both `A` and `B`.

Remember:

- Interface extends interface → `extends`
- Class implements interface → `implements`
- An interface can extend multiple interfaces.
- A class can implement multiple interfaces.

---

### Why do we need interfaces in Java?

An interface defines a contract that specifies what a class must do, without requiring a particular implementation.

Main uses:

1. Abstraction — Defines required behavior.
2. Multiple inheritance — A class can implement multiple interfaces.
3. Loose coupling — Code depends on an interface, not a specific class.
4. Polymorphism — Different classes can be used through the same interface type.

Example:

```
interface Payment {
    void pay();
}

class UpiPayment implements Payment {
    public void pay() {
        System.out.println("Paid using UPI");
    }
}

class CardPayment implements Payment {
    public void pay() {
        System.out.println("Paid using Card");
    }
}

public class Main {
    public static void main(String[] args) {
        Payment p = new UpiPayment();
        p.pay();

        p = new CardPayment();
        p.pay();
    }
}
```

Output:

```
Paid using UPI
Paid using Card
```

Real-world use case: A payment service can support UPI, cards, or net banking without changing the code that calls `pay()`.

Interview point: Interfaces help achieve abstraction, loose coupling, and multiple inheritance of type in Java.

# Additional notes

## Types of Interfaces in Java (Short Notes)

1. Normal Interface – Can contain multiple abstract methods.
   ```
   interface Animal {
       void sound();
       void eat();
   }
   ```
2. Functional Interface – Contains exactly one abstract method. Supports lambda expressions.
SAM = Single Abstract Method. It is another name for a Functional Interface.
   ```
   @FunctionalInterface
   interface Calculator {
       int add(int a, int b);
   }
   ```
3. Marker Interface – Contains no methods or fields; marks a class for special handling by Java or frameworks.
   ```
   interface MyMarker {}

   class Student implements MyMarker {}
   ```
   Examples: `Serializable`, `Cloneable`.
4. Nested Interface – An interface declared inside another class or interface.
   ```
   class Outer {
       interface Inner {
           void display();
       }
   }
   ```

Remember: Normal, functional, marker, and nested interfaces are common classifications. An interface can also extend another interface, and interfaces can have `default`, `static`, and (Java 9+) `private` methods.

---

### Why do we need a Marker Interface in Java?

A Marker Interface is used to mark a class so that Java or a framework can identify it and provide special behavior.

Example: `Serializable`

```
import java.io.Serializable;

class Student implements Serializable {
    int id = 101;
    String name = "Ravi";
}
```

Here, `Serializable` has no methods. It marks `Student` as eligible for Java serialization (converting an object into a byte stream).

Why use it?

- To identify classes for special processing.
- To enable certain Java behaviors, such as serialization or cloning.

Examples:

- `Serializable` — supports serialization.
- `Cloneable` — indicates that `Object.clone()` can create a field-by-field copy.

Interview point: Marker interfaces carry no methods; they provide type-based metadata. Annotations can also provide metadata, but marker interfaces can additionally be checked using `instanceof` and used in type declarations.

---

### Why do we need Serialization in Java?

Serialization converts a Java object into a byte stream so it can be stored or transferred. Deserialization converts the byte stream back into an object.

Why do we need it?

1. Save objects to a file for later use.
2. Transfer objects over a network.
3. Persist application state when needed.

### Example

```
import java.io.*;

class Student implements Serializable {
    int id = 101;
    String name = "Ravi";
}

public class Main {
    public static void main(String[] args) throws Exception {
        Student s = new Student();

        // Serialization: Object → File
        try (ObjectOutputStream out =
                 new ObjectOutputStream(new FileOutputStream("student.ser"))) {
            out.writeObject(s);
        }

        // Deserialization: File → Object
        try (ObjectInputStream in =
                 new ObjectInputStream(new FileInputStream("student.ser"))) {
            Student restored = (Student) in.readObject();
            System.out.println(restored.name); // Ravi
        }
    }
}
```

Remember:

- `Serializable` is a marker interface.
- `ObjectOutputStream` serializes objects.
- `ObjectInputStream` deserializes objects.
- `transient` fields are excluded from default serialization.
- Only deserialize trusted data because Java native deserialization can be unsafe.

Practical note: In Spring Boot REST APIs, JSON is more commonly used to exchange data between frontend and backend than Java native serialization.

---

### Why convert an object into a byte stream?

Because a Java object exists in memory as a runtime object, while files and network connections work with data represented as bytes.

Example:

Suppose you have this object:

```
Student s = new Student(101, "Ravi");
```

1. In memory: Java holds `s` as an object.
2. Serialization: Converts the object's data into bytes.
3. Storage/Transfer: Those bytes can be written to a file or sent over a network.
4. Deserialization: The bytes can be used to reconstruct the object later.

Real-world example: You want to save a student's data to a file and retrieve it after restarting your application. Serialization can help preserve that object's state.

Remember: Serialization doesn't mean converting the object itself into a file; it converts its serializable state into bytes that can be stored or transferred.

---

### Why do we need to store an object? (Use case)

Main reason: Data in RAM is temporary. When an application stops, its objects in memory are lost. We store data when we need it later.

Example: Student application

Suppose you create a student object:

```
Student s = new Student(101, "Ravi");
```

Use cases:

1. Save for later: Store student details in a file and retrieve them when the application restarts.
2. Transfer to another system: Send object data to another Java application over a network.
3. Save application state: Preserve certain object states between application runs.

Important distinction:

- Database: Usually the best choice for permanent business data, such as student records.
- Serialization: Useful when you specifically need to save or transfer an object's state as bytes.
- REST API: Usually uses JSON to exchange data between React and Spring Boot.

Interview point: Serialization is useful when an object's state needs to be persisted or transferred, rather than existing only temporarily in application memory.

---

Yes, serialization is still used in Java, but Java native serialization is less common in modern application development.

### Where is it used today?

| Use case                          | Common approach                                        |
| --------------------------------- | ------------------------------------------------------ |
| React ↔ Spring Boot communication | JSON                                                   |
| Permanent business data           | Database (MySQL, PostgreSQL)                           |
| Java object caching               | Redis, sometimes with serialization                    |
| Distributed systems / messaging   | JSON, Protobuf, Avro                                   |
| Java object serialization         | `Serializable` in specific use cases or legacy systems |

### Should you learn `Serializable`?

Yes, for Java interviews and fundamentals. Understand the concept, `Serializable`, `transient`, `serialVersionUID`, and serialization/deserialization.

For your React + Spring Boot full-stack goal, focus more on JSON, DTOs, REST APIs, and database persistence in practical projects.

Remember: Serialization is the general concept of converting data into a storable or transferable format. Java's `Serializable` is one specific implementation of that concept.
