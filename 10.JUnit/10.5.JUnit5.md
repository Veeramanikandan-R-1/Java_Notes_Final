## Major differences between JUnit 4 and JUnit 5

| Feature             | JUnit 4                         | JUnit 5                            |
| ------------------- | ------------------------------- | ---------------------------------- |
| Architecture        | Single framework                | Platform + Jupiter + Vintage       |
| `@Test` import      | `org.junit.Test`                | `org.junit.jupiter.api.Test`       |
| Before each test    | `@Before`                       | `@BeforeEach`                      |
| After each test     | `@After`                        | `@AfterEach`                       |
| Before all tests    | `@BeforeClass`                  | `@BeforeAll`                       |
| After all tests     | `@AfterClass`                   | `@AfterAll`                        |
| Exception testing   | `@Test(expected=...)`           | `assertThrows()`                   |
| Disable a test      | `@Ignore`                       | `@Disabled`                        |
| Parameterized tests | `@RunWith(Parameterized.class)` | `@ParameterizedTest`               |
| Nested test classes | Limited support                 | `@Nested`                          |
| Repeated tests      | Not built in                    | `@RepeatedTest`                    |
| Assertions          | `org.junit.Assert`              | `org.junit.jupiter.api.Assertions` |

## Example: JUnit 4 vs JUnit 5

JUnit 4:

```
import org.junit.Test;
import org.junit.Before;

@Test
public void testAdd() {
    assertEquals(3, app.add(1, 2));
}
```

JUnit 5:

```
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.BeforeEach;

@Test
void testAdd() {
    assertEquals(3, app.add(1, 2));
}
```

## Important JUnit 5 features

- JUnit Platform: Launches testing frameworks and test engines.
- JUnit Jupiter: Provides JUnit 5 annotations, assertions, and programming model.
- JUnit Vintage: Supports running older JUnit 3 and JUnit 4 tests on the JUnit Platform.
- Extension model: Uses `@ExtendWith` instead of JUnit 4's `@RunWith` for many extension use cases.

Interview takeaway: JUnit 5 provides a more modular architecture, improved lifecycle annotations, parameterized and nested tests, and a flexible extension model.
