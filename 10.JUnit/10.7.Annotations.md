## Important JUnit 5 annotations

| Annotation           | Purpose                                 | Example use                          |
| -------------------- | --------------------------------------- | ------------------------------------ |
| `@Test`              | Marks a method as a test                | Test addition                        |
| `@BeforeEach`        | Runs before every test method           | Initialize test objects              |
| `@AfterEach`         | Runs after every test method            | Clean up test data                   |
| `@BeforeAll`         | Runs once before all tests              | Initialize shared resources          |
| `@AfterAll`          | Runs once after all tests               | Close shared resources               |
| `@Disabled`          | Skips a test or test class              | Temporarily disable a test           |
| `@DisplayName`       | Provides a readable test name           | `"Test user creation"`               |
| `@Nested`            | Groups related tests in an inner class  | Group user-service tests             |
| `@RepeatedTest`      | Runs a test multiple times              | Repeat a test 5 times                |
| `@ParameterizedTest` | Runs a test with multiple input values  | Test addition with different numbers |
| `@Tag`               | Categorizes tests                       | `"slow"` or `"integration"`          |
| `@Timeout`           | Fails if execution exceeds a time limit | Ensure a method finishes quickly     |
| `@ExtendWith`        | Registers a JUnit extension             | Integrate Mockito extensions         |

## Example: Lifecycle annotations

```

import org.junit.jupiter.api.*;

class AppTest {

    @BeforeAll
    static void setupAll() {
        System.out.println("Runs once before all tests");
    }

    @BeforeEach
    void setup() {
        System.out.println("Runs before each test");
    }

    @Test
    void testAddition() {
        Assertions.assertEquals(3, 1 + 2);
    }

    @Test
    void testSubtraction() {
        Assertions.assertEquals(2, 5 - 3);
    }

    @AfterEach
    void cleanup() {
        System.out.println("Runs after each test");
    }

    @AfterAll
    static void cleanupAll() {
        System.out.println("Runs once after all tests");
    }
}

```

Execution order:

1. `@BeforeAll` — once
2. `@BeforeEach` → `@Test` → `@AfterEach` — for each test
3. `@AfterAll` — once

By default, `@BeforeAll` and `@AfterAll` methods must be `static` unless you configure JUnit with `@TestInstance(TestInstance.Lifecycle.PER_CLASS)`.

## Parameterized test example

Use `@ParameterizedTest` with `@ValueSource` to test multiple inputs without duplicating test methods.

```

import org.junit.jupiter.params.ParameterizedTest;
import org.junit.jupiter.params.provider.ValueSource;
import static org.junit.jupiter.api.Assertions.assertTrue;

class NumberTest {

    @ParameterizedTest
    @ValueSource(ints = {2, 4, 6, 8})
    void testEvenNumbers(int number) {
        assertTrue(number % 2 == 0);
    }
}

```

The `junit-jupiter-params` dependency is needed for parameterized tests. If you already have the `junit-jupiter` aggregate dependency in your `pom.xml`, it includes this module.

Interview priority: Learn `@Test`, `@BeforeEach`, `@AfterEach`, `@BeforeAll`, `@AfterAll`, `@ParameterizedTest`, `@Disabled`, and `@ExtendWith` first.

## `@TestInstance` in JUnit 5

`@TestInstance` controls how JUnit creates instances of a test class.

There are two lifecycle options:

### 1. `PER_METHOD` (default)

JUnit creates a new test class object for each test method.

```
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.TestInstance;

@TestInstance(TestInstance.Lifecycle.PER_METHOD)
class AppTest {

    int count = 0;

    @Test
    void test1() {
        count++;
        System.out.println(count); // 1
    }

    @Test
    void test2() {
        count++;
        System.out.println(count); // 1
    }
}
```

Each test gets a fresh instance, so `count` starts at `0` each time.

### 2. `PER_CLASS`

JUnit creates one test class object for all test methods.

```
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.TestInstance;

@TestInstance(TestInstance.Lifecycle.PER_CLASS)
class AppTest {

    int count = 0;

    @Test
    void test1() {
        count++;
        System.out.println(count); // 1
    }

    @Test
    void test2() {
        count++;
        System.out.println(count); // 2
    }
}
```

The same instance is reused, so `count` retains its value between tests. The order of test execution is not guaranteed by default.

### Major differences

| Feature                    | `PER_METHOD`              | `PER_CLASS`         |
| -------------------------- | ------------------------- | ------------------- |
| Instance creation          | One per test method       | One per test class  |
| Default?                   | Yes                       | No                  |
| Instance variables         | Reset for each test       | Shared across tests |
| `@BeforeAll` / `@AfterAll` | Must normally be `static` | Can be non-static   |

When to use `PER_CLASS`? When you want non-static `@BeforeAll` and `@AfterAll` methods or intentionally need shared test-instance state.

Interview tip: `PER_METHOD` provides better test isolation by default. With `PER_CLASS`, be careful that one test does not affect another through shared mutable state.
