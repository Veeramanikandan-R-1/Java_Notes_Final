## Java Application Build and Unit Testing — Corrected Notes

Your diagram represents the Java build process, but a few steps need correction.

### 1. Correct execution and build flow

Step 1: Source code

- Write Java code in `.java` files.
- Example: `Calculator.java`

Step 2: Compile

- The Java compiler (`javac`) converts `.java` files into `.class` bytecode files.
- Compilation does not automatically run unit tests.

Step 3: Write and run unit tests

- Write test cases using JUnit 5.
- Test the compiled application code by checking expected and actual results.
- In a Maven project, run tests using `mvn test`.

Step 4: Build the application

- Maven or Gradle compiles the source code, compiles test code, runs tests, and packages the application.
- Tests must pass for the build to succeed when the build is configured to fail on test errors.

Step 5: Package the application

- JAR (`.jar`): Commonly used for Java libraries and executable Spring Boot applications.
- WAR (`.war`): Commonly used for deployment to a compatible application server.

### 2. Important correction

Unit testing is not a conversion step between bytecode and the application package. It is a separate verification step performed during the build process.

For a Maven project, use:

```
mvn test
```

To build and package the application after running tests:

```
mvn package
```

Maven typically creates the resulting JAR or WAR inside the `target/` directory.

Remember: `.java` → `.class` → unit tests verify behavior → build and package → `.jar` or `.war`.

## JAR vs WAR in Java

1\. JAR (Java Archive)

- Packages compiled Java classes, libraries, and resources into a single `.jar` file.
- Used for Java applications and libraries.
- Spring Boot applications commonly use executable JAR files with an embedded server such as Tomcat.
- Run using: `java -jar app.jar`

2\. WAR (Web Application Archive)

- Packages a Java web application into a `.war` file.
- Commonly deployed to an external servlet container or application server, such as Tomcat.
- Often used when the server manages the application deployment.

### Difference

| Feature    | JAR                                 | WAR                                     |
| ---------- | ----------------------------------- | --------------------------------------- |
| Full form  | Java Archive                        | Web Application Archive                 |
| Extension  | `.jar`                              | `.war`                                  |
| Common use | Java apps and libraries             | Java web applications                   |
| Deployment | Can run independently if executable | Commonly deployed to an external server |

Remember: Spring Boot supports both JAR and WAR, but JAR is the default and commonly preferred choice for new Spring Boot applications.
