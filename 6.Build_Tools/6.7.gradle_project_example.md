## 1. Install the required VS Code extension

In VS Code → Extensions, install:

**Extension Pack for Java** by Microsoft.

You should also have Gradle available. But for a project, we'll use the **Gradle Wrapper**, so you don't need to depend on a globally installed Gradle version.

That's okay. **`gradle command not found` means Gradle is not installed globally or its `bin` folder isn't in Windows PATH.**

Since you're learning Gradle, let's fix it properly.

### Option 1 — Recommended: Install Gradle globally

1. Download Gradle from the official [Gradle installation page](https://gradle.org/install/?utm_source=chatgpt.com).

2. Download the **Binary-only ZIP**.

3. Extract it somewhere permanent, for example:

```text
C:\Gradle\gradle-9.x
```

You should have:

```text
C:\Gradle\gradle-9.x\
├── bin
├── init.d
├── lib
└── ...
```

4. Open Windows **Environment Variables**:

```text
Start
 → Search "Environment Variables"
 → Edit the system environment variables
 → Environment Variables
```

5. Under **System variables**, create:

```text
GRADLE_HOME
```

Value:

```text
C:\Gradle\gradle-9.x
```

6. Edit **Path** → Add:

```text
%GRADLE_HOME%\bin
```

7. Close VS Code completely and reopen it.

8. Open a new terminal and run:

```cmd
gradle -version
```

You should see:

```text
Gradle 9.x
Gradle home: C:\Gradle\gradle-9.x
JVM: 21...
```

### Important: You don't actually need global Gradle after project creation

Once you create a Gradle project, you'll normally have:

```text
gradlew
gradlew.bat
```

Then use:

```cmd
.\gradlew build
```

instead of:

```cmd
gradle build
```

On Windows:

```cmd
.\gradlew.bat build
```

And to run your application:

```cmd
.\gradlew.bat :app:run
```

### But there's one catch

You need **Gradle once** to run:

```cmd
gradle init
```

So for your current situation, install Gradle globally, run `gradle init`, and afterward you can use the **Gradle Wrapper** (`gradlew.bat`) for your projects.

Also verify Java first:

```cmd
java -version
```

and:

```cmd
javac -version
```

If those work, you're ready to configure Gradle.

# 8. Understand the important files

### `settings.gradle`

```groovy
rootProject.name = 'gradle-demo'

include('app')
```

It defines the Gradle project and modules.

---

### `app/build.gradle`

This is the important build script:

```groovy
plugins {
    id 'application'
}

repositories {
    mavenCentral()
}

dependencies {
    testImplementation 'org.junit.jupiter:junit-jupiter:5.10.0'
}

application {
    mainClass = 'com.example.App'
}

tasks.named('test') {
    useJUnitPlatform()
}
```

Think of this similarly to your Maven `pom.xml`.

```text
Maven                     Gradle

pom.xml          →        build.gradle
<dependency>     →        dependencies { }
<plugin>         →        plugins { }
```

# 9. Add a dependency

For example, suppose you want Google's Gson library.

Add:

```groovy
dependencies {
    implementation 'com.google.code.gson:gson:2.13.1'

    testImplementation 'org.junit.jupiter:junit-jupiter:5.10.0'
}
```

Then:

```cmd
.\gradlew build
```

Gradle automatically downloads Gson.

You can then use it:

```java
import com.google.gson.Gson;
```

This is one of the main jobs of a build tool.

## The mental model I want you to remember

Coming from React:

```text
React
│
├── package.json
├── node_modules
└── npm run build


Java + Gradle
│
├── build.gradle
├── Gradle dependency cache
└── gradlew build
```

And for your eventual Spring Boot project:

```text
Spring Boot
     ↓
build.gradle
     ↓
Spring dependencies
     ↓
Gradle
     ↓
compile → test → package → run
```

**One recommendation:** since you're currently learning Maven too, don't spend too much time on Gradle internals. Learn enough to understand `build.gradle`, dependencies, plugins, tasks, wrapper, `build`, `test`, and `bootRun`; then move on to **Spring Boot**.
