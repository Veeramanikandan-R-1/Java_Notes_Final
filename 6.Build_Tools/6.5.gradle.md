## Gradle — Build Scripts & Gradle Project

Since you already know **React/npm**, think of Gradle like this:

| React           | Java/Gradle                         |
| --------------- | ----------------------------------- |
| `package.json`  | `build.gradle` / `build.gradle.kts` |
| `npm install`   | `gradle build`                      |
| `node_modules`  | Gradle dependency cache             |
| npm dependency  | Maven/Gradle dependency             |
| `npm run build` | `gradle build`                      |
| npm scripts     | Gradle tasks                        |

**Gradle** is a build automation tool. It handles **dependencies, compilation, testing, packaging, and running build tasks**.

---

# 1. What is a Gradle Project?

A basic Java Gradle project:

```text
my-app/
│
├── build.gradle
├── settings.gradle
├── gradlew
├── gradlew.bat
│
└── src/
    ├── main/
    │   └── java/
    │       └── com/example/Main.java
    │
    └── test/
        └── java/
```

For Spring Boot, it will look roughly like:

```text
spring-app/
├── build.gradle
├── settings.gradle
├── gradlew
├── gradlew.bat
└── src/
    ├── main/
    │   ├── java/
    │   └── resources/
    │       └── application.properties
    └── test/
        └── java/
```

---

# 2. `settings.gradle`

This mainly defines the **Gradle project name** and, for multi-module projects, the modules.

```groovy
rootProject.name = 'my-app'
```

Think:

```text
settings.gradle
      ↓
Project configuration
```

For now, remember:

> `settings.gradle` → **Which Gradle project/modules exist?**

---

# 3. Build Script — `build.gradle`

This is the most important file.

It tells Gradle:

* What plugins to use
* What dependencies are required
* How to compile/build the project
* What tasks/configuration are needed

Example:

```groovy
plugins {
    id 'java'
}

group = 'com.example'
version = '1.0.0'

repositories {
    mavenCentral()
}

dependencies {
    testImplementation 'org.junit.jupiter:junit-jupiter:5.10.0'
}

test {
    useJUnitPlatform()
}
```

### Understand each section

### `plugins`

```groovy
plugins {
    id 'java'
}
```

Adds Java-related Gradle functionality.

For Spring Boot:

```groovy
plugins {
    id 'java'
    id 'org.springframework.boot' version '3.5.5'
    id 'io.spring.dependency-management' version '1.1.7'
}
```

---

### `group` and `version`

```groovy
group = 'com.example'
version = '1.0.0'
```

Used to identify your application/library.

Similar concept to Maven:

```xml
<groupId>com.example</groupId>
<version>1.0.0</version>
```

---

### `repositories`

```groovy
repositories {
    mavenCentral()
}
```

Tells Gradle where to download dependencies from.

Most common:

```text
Maven Central
```

---

# 4. Dependencies

Suppose your application needs JUnit.

```groovy
dependencies {
    testImplementation 'org.junit.jupiter:junit-jupiter:5.10.0'
}
```

The format is:

```text
group:name:version
```

For example:

```text
org.junit.jupiter:junit-jupiter:5.10.0
```

This is conceptually similar to Maven's:

```xml
<dependency>
    <groupId>org.junit.jupiter</groupId>
    <artifactId>junit-jupiter</artifactId>
    <version>5.10.0</version>
</dependency>
```

---

# 5. Dependency Configurations

This is important for interviews.

Common ones:

```groovy
implementation '...'
testImplementation '...'
runtimeOnly '...'
compileOnly '...'
```

### `implementation`

Dependency required by your application:

```groovy
implementation 'some-library'
```

### `testImplementation`

Only required for tests:

```groovy
testImplementation 'org.junit.jupiter:junit-jupiter:5.10.0'
```

### `runtimeOnly`

Required only at runtime.

Example:

```groovy
runtimeOnly 'org.postgresql:postgresql'
```

### `compileOnly`

Required during compilation but not runtime.

# 6. Gradle Tasks

Gradle works heavily around **tasks**.

For example:

```bash
gradle build
```

`build` is a task.

Other common tasks:

```bash
gradle clean
gradle test
gradle build
```

### What happens?

```text
gradle build
     ↓
compile
     ↓
test
     ↓
package
     ↓
BUILD SUCCESSFUL
```

You can see available tasks:

```bash
gradle tasks
```

---

# 7. Create Your Own Task

You can define a task in `build.gradle`:

```groovy
tasks.register('hello') {
    doLast {
        println 'Hello from Gradle!'
    }
}
```

Run:

```bash
gradle hello
```

Output:

```text
Hello from Gradle!
```

This is one of the important differences from Maven:

> Gradle build scripts are programmable using **Groovy or Kotlin DSL**.

# 8. Complete Working Java Gradle Project

### `settings.gradle`

```groovy
rootProject.name = 'gradle-demo'
```

### `build.gradle`

```groovy
plugins {
    id 'java'
}

group = 'com.example'
version = '1.0.0'

repositories {
    mavenCentral()
}

dependencies {
    testImplementation 'org.junit.jupiter:junit-jupiter:5.10.0'
}

tasks.register('hello') {
    doLast {
        println 'Hello from Gradle!'
    }
}

test {
    useJUnitPlatform()
}
```

### `src/main/java/com/example/Main.java`

```java
package com.example;

public class Main {

    public static void main(String[] args) {
        System.out.println("Hello Gradle!");
    }
}
```

Run:

```bash
gradle build
```

Then:

```bash
gradle hello
```

You should get:

```text
Hello from Gradle!
```

# 9. Gradle Wrapper — Very Important

A Gradle project normally contains:

```text
gradlew
gradlew.bat
gradle/
```

On Windows:

```cmd
gradlew.bat build
```

or simply:

```cmd
gradlew build
```

The **Gradle Wrapper** ensures everyone uses the project's configured Gradle version.

So generally prefer:

```cmd
gradlew build
```

instead of:

```cmd
gradle build
```

This is similar to:

```text
npm install
```

versus using a globally installed tool, but the Gradle Wrapper specifically pins the Gradle version for the project.

# 10. Gradle + Spring Boot

A typical Spring Boot `build.gradle` looks like:

```groovy
plugins {
    id 'java'
    id 'org.springframework.boot' version '3.5.5'
    id 'io.spring.dependency-management' version '1.1.7'
}

group = 'com.example'
version = '0.0.1-SNAPSHOT'

java {
    toolchain {
        languageVersion = JavaLanguageVersion.of(21)
    }
}

repositories {
    mavenCentral()
}

dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-web'

    testImplementation 'org.springframework.boot:spring-boot-starter-test'
}

tasks.named('test') {
    useJUnitPlatform()
}
```

Then:

```cmd
gradlew build
```

and:

```cmd
gradlew bootRun
```

## What you should remember for interviews

```text
Gradle
 │
 ├── settings.gradle
 │      └── project/modules
 │
 ├── build.gradle
 │      ├── plugins
 │      ├── repositories
 │      ├── dependencies
 │      └── tasks
 │
 ├── Gradle Wrapper
 │      ├── gradlew
 │      └── gradlew.bat
 │
 └── src/
        ├── main/
        └── test/
```

### Most important commands

```bash
gradle tasks
gradle clean
gradle test
gradle build
gradle bootRun
```

On Windows, preferably:

```cmd
gradlew build
gradlew bootRun
```

### Maven → Gradle mental mapping

```text
pom.xml                 → build.gradle
Maven Central           → mavenCentral()
<dependency>            → implementation / testImplementation
mvn clean               → gradle clean
mvn test                → gradle test
mvn package             → gradle build
Maven Wrapper            → Gradle Wrapper
mvnw.cmd                 → gradlew.bat
```

**For your Spring Boot goal:** you don't need to master every Gradle feature. Focus first on **`build.gradle` → plugins → repositories → dependencies → tasks → Gradle Wrapper → Spring Boot `bootRun`/`build`**.
