# Build Tools — Maven

## 1. What is Maven?

**Maven** is a Java **build and dependency management tool**.

It mainly helps you:

* Manage external libraries/dependencies
* Compile Java code
* Run tests
* Package the application (`.jar` / `.war`)
* Maintain a standard project structure
* Manage dependency versions
* Run build plugins

### React comparison

| React / Node        | Java / Maven                           |
| ------------------- | -------------------------------------- |
| `package.json`      | `pom.xml`                              |
| npm                 | Maven                                  |
| `npm install`       | `mvn install`                          |
| `node_modules`      | Local Maven repository                 |
| npm package         | Maven dependency                       |
| `npm run build`     | `mvn package`                          |
| `package-lock.json` | Dependency resolution/version metadata |

# 2. Maven Project Structure

A typical Maven project:

```text
my-app/
│
├── pom.xml
│
└── src/
    ├── main/
    │   ├── java/
    │   │   └── com/example/App.java
    │   │
    │   └── resources/
    │
    └── test/
        └── java/
            └── com/example/AppTest.java
```

### Important directories

```text
src/main/java
```

Your application Java code.

```text
src/main/resources
```

Configuration/resources.

For Spring Boot, you'll commonly see:

```text
application.properties
application.yml
```

```text
src/test/java
```

Unit/integration tests.

# 3. POM — Project Object Model

`pom.xml` is the **heart of a Maven project**.

POM tells Maven:

> "What is my project, what libraries do I need, and how should this project be built?"

Basic POM:

```xml
<?xml version="1.0" encoding="UTF-8"?>

<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
         https://maven.apache.org/xsd/maven-4.0.0.xsd">

    <modelVersion>4.0.0</modelVersion>

    <groupId>com.example</groupId>
    <artifactId>my-app</artifactId>
    <version>1.0.0</version>

</project>
```

The most important identifiers:

---

This is the **standard XML header + Maven POM declaration**. You don't need to memorize it.

```xml
<?xml version="1.0" encoding="UTF-8"?>
```

### 1. XML declaration

* `version="1.0"` → XML specification version.
* `encoding="UTF-8"` → Characters are encoded using UTF-8.

---

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0"
```

### 2. `<project>`

This is the **root element** of `pom.xml`.

`xmlns` = XML Namespace.

It tells XML:

> "The elements inside this document follow the Maven POM rules."

---

```xml
xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
```

### 3. `xsi`

Defines the XML Schema Instance namespace.

It's used for XML schema-related features.

You normally **don't need to interact with this directly**.

---

```xml
xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
https://maven.apache.org/xsd/maven-4.0.0.xsd">
```

### 4. `schemaLocation`

Tells XML tools:

> "Here is the schema that describes what a valid Maven POM looks like."

It helps IntelliJ/VS Code provide things like:

* Autocomplete
* Validation
* Error detection

### In simple terms

Think of the whole thing as:

```text
XML declaration
      ↓
"This is an XML file using UTF-8"

<project>
      ↓
"This is a Maven POM"

xmlns / schemaLocation
      ↓
"Use Maven's POM rules/schema"
```

**For Spring Boot development:** you can mostly treat these lines as **boilerplate** generated automatically by Maven/IDE.

---

### `groupId`

Usually represents the organization/company/package namespace.

```xml
<groupId>com.example</groupId>
```

### `artifactId`

Your application/library name.

```xml
<artifactId>my-app</artifactId>
```

### `version`

Version of your project.

```xml
<version>1.0.0</version>
```

Together:

```text
com.example : my-app : 1.0.0
```

This uniquely identifies your Maven artifact.

# 4. Dependencies

Suppose your Java application needs a JSON library.

Without Maven, you would have to manually download the `.jar` and add it to your project.

With Maven:

```xml
<dependencies>

    <dependency>
        <groupId>com.fasterxml.jackson.core</groupId>
        <artifactId>jackson-databind</artifactId>
        <version>2.20.0</version>
    </dependency>

</dependencies>
```

Maven downloads the required JAR and makes it available to your application.

### React equivalent

You do:

```bash
npm install axios
```

and package.json contains something like:

```json
{
  "dependencies": {
    "axios": "..."
  }
}
```

Maven:

```xml
<dependency>
    <groupId>...</groupId>
    <artifactId>...</artifactId>
    <version>...</version>
</dependency>
```

# 5. Where does Maven download dependencies from?

Normally from **Maven Central Repository**.

Flow:

```text
pom.xml
   ↓
Maven
   ↓
Maven Central
   ↓
Download dependency
   ↓
Local Maven Repository
   ↓
Your project
```

Local repository is typically:

```text
~/.m2/repository
```

On Windows:

```text
C:\Users\<username>\.m2\repository
```

So Maven doesn't necessarily download the same dependency every time.

If it already exists locally, Maven can reuse it.

# 7. Full Working Maven Example

### Project

```text
maven-demo/
│
├── pom.xml
│
└── src/
    └── main/
        └── java/
            └── com/example/App.java
```

### `pom.xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>

<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
         https://maven.apache.org/xsd/maven-4.0.0.xsd">

    <modelVersion>4.0.0</modelVersion>

    <groupId>com.example</groupId>
    <artifactId>maven-demo</artifactId>
    <version>1.0.0</version>

    <properties>
        <maven.compiler.source>21</maven.compiler.source>
        <maven.compiler.target>21</maven.compiler.target>
    </properties>

</project>
```

### `App.java`

```java
package com.example;

public class App {

    public static void main(String[] args) {
        System.out.println("Hello Maven!");
    }
}
```

Run:

```bash
mvn compile
```

Then:

```bash
mvn package
```

Maven compiles and packages your application.

# 8. Maven Lifecycle

You should know these commands for interviews and Spring Boot development:

```bash
mvn clean
```

Deletes previous build output (`target`).

```bash
mvn compile
```

Compiles source code.

```bash
mvn test
```

Runs tests.

```bash
mvn package
```

Creates a JAR/WAR.

```bash
mvn install
```

Builds and puts your artifact into your local `.m2` repository.

Common flow:

```text
clean
  ↓
compile
  ↓
test
  ↓
package
  ↓
install
```

You can execute:

```bash
mvn clean install
```

# 9. What is `target/`?

After:

```bash
mvn package
```

Maven creates:

```text
target/
├── classes/
├── test-classes/
└── maven-demo-1.0.0.jar
```

`target` contains generated build output.

Usually you **don't commit `target/` to Git**.

# 10. Maven + Spring Boot

This is where Maven becomes very important for your goal.

A Spring Boot project might have:

```xml
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>...</version>
</parent>

<dependencies>

    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>

</dependencies>
```

Notice something important:

You may **not specify the version** for:

```xml
spring-boot-starter-web
```

because Spring Boot's dependency management can manage compatible versions for you.

This prevents dependency-version conflicts.

# 11. Transitive Dependencies ⭐

This is an important Maven concept.

Suppose:

```text
Your Application
      ↓
Library A
      ↓
Library B
```

You directly add:

```xml
Library A
```

but Library A itself requires:

```text
Library B
```

Maven automatically brings Library B.

This is called a **transitive dependency**.

You don't need to manually add every dependency required by your dependencies.

# 12. Dependency Scope

You will commonly see:

```xml
<scope>test</scope>
```

Example:

```xml
<dependency>
    <groupId>org.junit.jupiter</groupId>
    <artifactId>junit-jupiter</artifactId>
    <version>...</version>
    <scope>test</scope>
</dependency>
```

Common scopes:

| Scope      | Meaning                               |
| ---------- | ------------------------------------- |
| `compile`  | Available everywhere; default         |
| `test`     | Only for testing                      |
| `provided` | Provided by runtime/container         |
| `runtime`  | Needed at runtime but not compilation |

For now, remember:

**`compile` = normal dependency**

**`test` = test-only dependency**

# 13. Maven Plugins

Maven itself doesn't perform every build operation directly.

Plugins perform tasks.

For example:

```text
Maven
 ↓
Compiler Plugin → compiles Java
Surefire Plugin → runs tests
Spring Boot Plugin → packages/runs Spring Boot application
```

This becomes particularly relevant in Spring Boot projects.

# 14. What you should remember for interviews

### Maven

> Maven is a Java build automation and dependency management tool.

### POM

> `pom.xml` is the configuration file that defines project metadata, dependencies, plugins, and build configuration.

### Dependency

> A dependency is an external library required by your project.

### Maven Central

> Public repository from which Maven can download dependencies.

### `.m2`

> Local Maven repository where downloaded dependencies and installed artifacts are stored.

### Transitive dependency

> A dependency required by another dependency and automatically resolved by Maven.

### `mvn clean install`

> Cleans the previous build, compiles/tests/packages the project, and installs the artifact into the local Maven repository.
