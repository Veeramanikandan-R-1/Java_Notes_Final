## REST API – Introduction

REST (Representational State Transfer) is an architectural style used to build web services that allow different applications to communicate over HTTP.

A REST API allows a client (browser, React application, mobile app) to communicate with a server and exchange data, commonly in JSON format.

### 1. Why do we need REST API?

- Enables communication between frontend and backend.
- Allows different technologies to communicate (React ↔ Java).
- Supports CRUD operations.
- Provides a standard way to access server resources.
- Separates frontend and backend development.

### 2. HTTP methods used in REST API

| HTTP Method | Operation              | Example              |
| ----------- | ---------------------- | -------------------- |
| GET         | Read data              | Get all students     |
| POST        | Create data            | Add a student        |
| PUT         | Update entire resource | Update student       |
| PATCH       | Partially update       | Update student email |
| DELETE      | Delete data            | Delete a student     |

### 3. REST API example

Consider a Student Management API.

Base URL:

```
http://localhost:8080/api/students
```

| Method | Endpoint          | Purpose           |
| ------ | ----------------- | ----------------- |
| GET    | `/api/students`   | Get all students  |
| GET    | `/api/students/1` | Get student by ID |
| POST   | `/api/students`   | Create student    |
| PUT    | `/api/students/1` | Update student    |
| DELETE | `/api/students/1` | Delete student    |

### 4. Example request and response

POST request

URL:

```
POST /api/students
```

Request Body (JSON):

```
{
    "name": "Arun",
    "email": "arun@gmail.com",
    "course": "Java"
}
```

Response:

```
{
    "id": 1,
    "name": "Arun",
    "email": "arun@gmail.com",
    "course": "Java"
}
```

### 5. Important REST principles

1. Client-Server: Frontend and backend are independent.
2. Stateless: Each request contains the information needed to process it; the server doesn't rely on previous request state.
3. Cacheable: Responses can be cached when permitted.
4. Uniform Interface: Consistent resource-based URLs and HTTP methods.
5. Resource-Based: Everything is represented as a resource (Student, Employee, Product).

### 6. REST API vs Traditional Servlet/JSP

| Servlet/JSP           | REST API                           |
| --------------------- | ---------------------------------- |
| Usually returns HTML  | Usually returns JSON               |
| Server renders UI     | Client renders UI                  |
| JSP is used for views | React or other clients consume API |
| Browser-oriented      | Supports multiple clients          |

Remember: REST is an architectural style, HTTP is the communication protocol, and JSON is a commonly used data format.

In Spring Boot: We typically use `@RestController`, `@GetMapping`, `@PostMapping`, `@PutMapping` and `@DeleteMapping` to build REST APIs.

## Jersey vs Spring Boot for REST API Development

Both Jersey and Spring Boot can be used to develop REST APIs in Java, but they differ in their approach and ecosystem.

### 1. What are they?

- Jersey: An implementation of JAX-RS (now Jakarta REST), the standard Java API for building RESTful web services.
- Spring Boot: A framework built on the Spring ecosystem that simplifies building standalone applications, REST APIs and microservices.

### 2. Key differences

| Feature              | Jersey                                     | Spring Boot                                      |
| -------------------- | ------------------------------------------ | ------------------------------------------------ |
| Type                 | JAX-RS implementation                      | Application framework                            |
| Standard             | Jakarta REST                               | Spring MVC / Spring Web                          |
| REST annotations     | `@Path`, `@GET`, `@POST`                   | `@RestController`, `@GetMapping`, `@PostMapping` |
| Dependency Injection | Can use CDI/HK2                            | Spring IoC container                             |
| Configuration        | JAX-RS configuration                       | Auto-configuration                               |
| Database             | JDBC/JPA integration configured separately | Spring Data JPA, JDBC support                    |
| Security             | Requires integration                       | Spring Security                                  |
| Microservices        | Possible                                   | Extensive ecosystem                              |
| Learning curve       | Relatively lightweight for REST            | Broader concepts to learn                        |

### 3. Simple coding comparison

Jersey:

```
@Path("/students")
public class StudentResource {

    @GET
    @Produces(MediaType.APPLICATION_JSON)
    public String getStudents() {
        return "Student List";
    }
}
```

Spring Boot:

```
@RestController
@RequestMapping("/students")
public class StudentController {

    @GetMapping
    public String getStudents() {
        return "Student List";
    }
}
```

Both expose a GET endpoint to retrieve students.

### 4. When to use what?

| Jersey                                      | Spring Boot                                          |
| ------------------------------------------- | ---------------------------------------------------- |
| When you specifically need JAX-RS standards | When building enterprise applications                |
| Lightweight REST services                   | REST APIs with database, security and business logic |
| Existing JAX-RS applications                | Modern microservices and backend applications        |

### 5. My recommendation

Since your goal is to become a Full Stack Java Developer (React + Spring Boot), focus on Spring Boot.

Recommended learning sequence:

1. Java fundamentals
2. Servlets and JSP
3. REST API fundamentals
4. Spring Core (IoC and DI)
5. Spring MVC
6. Spring Boot REST API
7. Spring Data JPA + MySQL
8. Spring Security

Interview takeaway: Jersey implements the Jakarta REST specification, whereas Spring Boot is a broader application framework that provides REST development through Spring MVC and many other capabilities.
