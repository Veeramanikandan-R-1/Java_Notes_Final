## Create a REST API using Jersey in VS Code (Linux)

Let's create a simple Student REST API using Jersey (Jakarta REST) and Maven.

We'll implement one GET endpoint to understand how Jersey works.

### 1. Prerequisites

- Java 21
- Maven
- VS Code
- REST Client extension or Postman for testing

### 2. Create a Maven project

```
mkdir jersey-demo
cd jersey-demo
code .
```

Create a Maven project with this structure:

mvn archetype:generate \
  -DgroupId=com.example \
  -DartifactId=jersey-demo \
  -DarchetypeArtifactId=maven-archetype-webapp \
  -DinteractiveMode=false
  
```
jersey-demo/
├── pom.xml
└── src/
    └── main/
        ├── java/
        │   └── com/example/
        │       ├── StudentResource.java
        │       └── ApplicationConfig.java
        └── webapp/
            └── WEB-INF/
                └── web.xml
```

We'll deploy it as a WAR to Tomcat 10.1.

### 3. Configure pom.xml

```
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
         https://maven.apache.org/xsd/maven-4.0.0.xsd">

    <modelVersion>4.0.0</modelVersion>

    <groupId>com.example</groupId>
    <artifactId>jersey-demo</artifactId>
    <version>1.0</version>
    <packaging>war</packaging>

    <properties>
        <maven.compiler.release>21</maven.compiler.release>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    </properties>

    <dependencies>
        <dependency>
            <groupId>org.glassfish.jersey.containers</groupId>
            <artifactId>jersey-container-servlet</artifactId>
            <version>3.1.11</version>
        </dependency>

        <dependency>
            <groupId>org.glassfish.jersey.inject</groupId>
            <artifactId>jersey-hk2</artifactId>
            <version>3.1.11</version>
        </dependency>

        <dependency>
            <groupId>org.glassfish.jersey.media</groupId>
            <artifactId>jersey-media-json-jackson</artifactId>
            <version>3.1.11</version>
        </dependency>
    </dependencies>

    <build>
        <finalName>jersey-demo</finalName>
    </build>

</project>
```

### 4. Create ApplicationConfig.java

This class configures Jersey and scans for REST resource classes.

```
package com.example;

import jakarta.ws.rs.ApplicationPath;
import org.glassfish.jersey.server.ResourceConfig;
import org.glassfish.jersey.jackson.JacksonFeature;

@ApplicationPath("/api")
public class ApplicationConfig extends ResourceConfig {

    public ApplicationConfig() {
        packages("com.example");
        register(JacksonFeature.class);
    }
}
```

### 5. Create StudentResource.java

This is the REST resource class. It handles HTTP requests.

```
package com.example;

import jakarta.ws.rs.*;
import jakarta.ws.rs.core.MediaType;
import java.util.List;

@Path("/students")
public class StudentResource {

    @GET
    @Produces(MediaType.APPLICATION_JSON)
    public List<Student> getStudents() {

        return List.of(
            new Student(1, "Arun", "Java"),
            new Student(2, "Mani", "Spring Boot")
        );
    }
}
```

### 6. Create Student.java

```
package com.example;

public record Student(
    int id,
    String name,
    String course
) {}
```

We use a Java record to represent student data.

### 7. Build the application

```
mvn clean package
```

This generates:

```
target/jersey-demo.war
```

### 8. Deploy in Tomcat 10.1

```
sudo cp target/jersey-demo.war \
/var/lib/tomcat10/webapps/

sudo systemctl restart tomcat10
```

### 9. Test the REST API

Open browser or Postman:

```
GET http://localhost:8080/jersey-demo/api/students
```

Expected JSON response:

```
[
    {
        "id": 1,
        "name": "Arun",
        "course": "Java"
    },
    {
        "id": 2,
        "name": "Mani",
        "course": "Spring Boot"
    }
]
```

## 10. Understand the important Jersey annotations

| Annotation         | Purpose                         |
| ------------------ | ------------------------------- |
| `@Path`            | Defines API URL                 |
| `@GET`             | Handles GET request             |
| `@POST`            | Handles POST request            |
| `@PUT`             | Handles PUT request             |
| `@DELETE`          | Handles DELETE request          |
| `@Produces`        | Defines response format         |
| `@Consumes`        | Defines accepted request format |
| `@ApplicationPath` | Defines base API path           |

Understand the request mapping:

```
@ApplicationPath("/api")
        +
@Path("/students")
        =
/api/students
```

Remember: Jersey uses JAX-RS annotations to map HTTP requests to Java methods. Unlike Spring Boot's `@RestController`, Jersey uses `@Path` and HTTP method annotations such as `@GET` and `@POST`.
