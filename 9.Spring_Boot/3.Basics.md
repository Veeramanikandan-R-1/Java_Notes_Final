## Spring Boot Auto-Configuration

Since you already know React, think of **Auto-Configuration** as Spring Boot doing the setup/configuration work that you would otherwise have to write manually.

### 1. What is Auto-Configuration?

**Spring Boot automatically configures Spring beans based on:**

1. Dependencies present in your project
2. Configuration properties
3. What beans you have already defined

Example:

If you add:

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

Spring Boot detects that you're building a web application and automatically configures things such as:

* Embedded Tomcat
* Spring MVC
* DispatcherServlet
* JSON support
* HTTP request handling

So you don't need to configure these manually.

Why each one?

Embedded Tomcat → Runs your application as a web server. You don't need to install/configure Tomcat separately.

Spring MVC → Framework for building REST APIs and web applications.

DispatcherServlet → The central entry point that receives HTTP requests and sends them to the correct Controller.

JSON support (Jackson) → Converts Java objects ↔ JSON, so React can easily communicate with your API.

HTTP request handling → Handles GET, POST, PUT, DELETE, headers, parameters, request/response, etc.

## 2. The key annotation

Your main class normally looks like:

```java
package com.example.demo;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class DemoApplication {

    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
```

The important annotation is:

```java
@SpringBootApplication
```

It combines three annotations:

```java
@SpringBootConfiguration
@EnableAutoConfiguration
@ComponentScan
```

### Most important one for this topic:

```java
@EnableAutoConfiguration
```

It tells Spring Boot:

> "Look at the dependencies and application configuration, and automatically configure the application."

# 3. How Auto-Configuration works

Suppose your `pom.xml` contains:

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

Spring Boot sees the web-related dependencies.

Conceptually:

```text
spring-boot-starter-web
        ↓
Spring MVC + Tomcat + Jackson
        ↓
@EnableAutoConfiguration
        ↓
Spring Boot detects web dependencies
        ↓
Automatically creates/configures required beans
```

You don't explicitly write:

```java
@Bean
public DispatcherServlet dispatcherServlet() {
    ...
}
```

Spring Boot handles it.

# 4. Very simple working example

### Project structure

```text
demo/
├── src/
│   └── main/
│       ├── java/
│       │   └── com/example/demo/
│       │       └── DemoApplication.java
│       └── resources/
│           └── application.properties
└── pom.xml
```

### `pom.xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0">

    <modelVersion>4.0.0</modelVersion>

    <parent>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-parent</artifactId>
        <version>4.0.1</version>
        <relativePath/>
    </parent>

    <groupId>com.example</groupId>
    <artifactId>demo</artifactId>
    <version>0.0.1-SNAPSHOT</version>

    <properties>
        <java.version>21</java.version>
    </properties>

    <dependencies>

        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-web</artifactId>
        </dependency>

    </dependencies>

    <build>
        <plugins>
            <plugin>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-maven-plugin</artifactId>
            </plugin>
        </plugins>
    </build>

</project>
```

### `DemoApplication.java`

```java
package com.example.demo;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class DemoApplication {

    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
```

That's enough to start a web application.

Run:

```bash
mvn spring-boot:run
```

Spring Boot automatically configures the embedded web server.

# 5. Auto-Configuration can back off

This is an **important interview concept**.

Spring Boot doesn't blindly configure everything.

Suppose Spring Boot would normally create a particular bean, but **you provide your own bean**.

Spring Boot generally says:

> "The developer already configured it, so I won't create the default one."

Example concept:

```java
@Configuration
public class AppConfig {

    @Bean
    public MyService myService() {
        return new MyService();
    }
}
```

Spring Boot's auto-configuration can **back off** when an appropriate user-defined configuration already exists.

This is why Spring Boot is:

**Convention + sensible defaults + developer override**

# 6. `@EnableAutoConfiguration` vs `@SpringBootApplication`

You normally use:

```java
@SpringBootApplication
```

instead of:

```java
@EnableAutoConfiguration
```

because `@SpringBootApplication` already includes it.

Think:

```text
@SpringBootApplication
        |
        +-- @SpringBootConfiguration
        +-- @EnableAutoConfiguration  ← Auto Configuration
        +-- @ComponentScan
```

# 7. How to remember it

### Traditional Spring

You configure many things yourself:

```text
Dependencies
   ↓
Manual configuration
   ↓
Beans
   ↓
Application
```

### Spring Boot

```text
Dependencies
      ↓
Spring Boot detects them
      ↓
Auto-Configuration
      ↓
Required Beans / Server / MVC etc.
      ↓
Application
```

### Interview answer

> **Spring Boot Auto-Configuration automatically configures the application based on the dependencies available in the classpath and the application's configuration. It is enabled by `@EnableAutoConfiguration`, which is included inside `@SpringBootApplication`. If we provide our own configuration, Spring Boot can back off from its default configuration.**

**One important distinction:** Auto-Configuration is **not magic** and it does not configure every possible thing. It applies predefined auto-configuration classes when their conditions match the application's environment.
