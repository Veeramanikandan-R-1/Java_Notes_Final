# Spring Boot – Exception Handling

## Sub Topic: Global Exception Handler Implementation

## 1. What is a Global Exception Handler?

A **Global Exception Handler** handles exceptions from multiple controllers in one centralized class instead of writing `try-catch` blocks in every controller.

Spring Boot provides:

* `@RestControllerAdvice` – handles exceptions globally and returns response bodies.
* `@ExceptionHandler` – defines which exception a method handles.
* `ResponseEntity` – controls the HTTP status code and response body.

**React comparison:** Similar in purpose to centralized API error handling using an Axios interceptor, but this handles exceptions on the backend.

## 2. Implementation – Complete Working Example

**Prerequisite:** A Spring Boot project with `spring-boot-starter-web`.

### Project Structure

```text
src/main/java/com/example/demo/
├── DemoApplication.java
├── controller/
│   └── UserController.java
├── exception/
│   ├── UserNotFoundException.java
│   └── GlobalExceptionHandler.java
└── service/
    └── UserService.java
```

### Step 1: Create a Custom Exception

**File:** `exception/UserNotFoundException.java`

```java
package com.example.demo.exception;

public class UserNotFoundException extends RuntimeException {

    public UserNotFoundException(String message) {
        super(message);
    }
}
```

**Explanation:**

* Extends `RuntimeException`, making it an unchecked exception.
* `super(message)` passes the error message to the parent exception class.

### Step 2: Create the Service

**File:** `service/UserService.java`

```java
package com.example.demo.service;

import com.example.demo.exception.UserNotFoundException;
import org.springframework.stereotype.Service;

@Service
public class UserService {

    public String getUserById(Long id) {
        if (id != 1L) {
            throw new UserNotFoundException(
                "User not found with id: " + id
            );
        }

        return "John";
    }
}
```

**Explanation:**

* `@Service` registers the class as a Spring-managed bean.
* If the requested ID is not `1`, the service throws a custom exception.
* Otherwise, it returns the user's name.

### Step 3: Create the Controller

**File:** `controller/UserController.java`

```java
package com.example.demo.controller;

import com.example.demo.service.UserService;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/api/users")
public class UserController {

    private final UserService userService;

    public UserController(UserService userService) {
        this.userService = userService;
    }

    @GetMapping("/{id}")
    public String getUser(@PathVariable Long id) {
        return userService.getUserById(id);
    }
}
```

**Explanation:**

* `@RestController` exposes REST endpoints.
* `@RequestMapping` defines the common URL prefix.
* `@GetMapping` handles HTTP GET requests.
* Constructor injection provides the service dependency.
* No `try-catch` is required in the controller.

### Step 4: Implement the Global Exception Handler

**File:** `exception/GlobalExceptionHandler.java`

```java
package com.example.demo.exception;

import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

import java.time.LocalDateTime;
import java.util.Map;

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(UserNotFoundException.class)
    public ResponseEntity<Map<String, Object>> handleUserNotFound(
            UserNotFoundException ex) {

        Map<String, Object> body = Map.of(
            "timestamp", LocalDateTime.now().toString(),
            "status", 404,
            "error", "Not Found",
            "message", ex.getMessage()
        );

        return ResponseEntity
                .status(HttpStatus.NOT_FOUND)
                .body(body);
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<Map<String, Object>> handleGenericException(
            Exception ex) {

        Map<String, Object> body = Map.of(
            "timestamp", LocalDateTime.now().toString(),
            "status", 500,
            "error", "Internal Server Error",
            "message", "An unexpected error occurred"
        );

        return ResponseEntity
                .status(HttpStatus.INTERNAL_SERVER_ERROR)
                .body(body);
    }
}
```

**Explanation:**

* `@RestControllerAdvice` centralizes exception handling across REST controllers.
* `@ExceptionHandler(UserNotFoundException.class)` handles user-not-found exceptions.
* `@ExceptionHandler(Exception.class)` provides a fallback for other unhandled exceptions covered by this advice.
* `ResponseEntity` sets the appropriate HTTP status and response body.
* Unexpected internal exception details are not exposed to the client.

### Step 5: Main Application Class

**File:** `DemoApplication.java`

```java
package com.example.demo;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class DemoApplication {

    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
```

**Important:** Keep all classes under the `com.example.demo` package hierarchy so Spring Boot can discover the controller, service and exception handler through component scanning.

## 4. Important Annotations and Classes

| Annotation / Class      | Purpose                                                            |
| ----------------------- | ------------------------------------------------------------------ |
| `@RestControllerAdvice` | Centralized exception handling for REST controllers                |
| `@ControllerAdvice`     | Global controller advice; can also support view-based applications |
| `@ExceptionHandler`     | Maps an exception type to a handler method                         |
| `ResponseEntity`        | Controls HTTP status, headers and response body                    |
| `RuntimeException`      | Base class for custom unchecked exceptions                         |

### Important Points

1. Specific exception handlers take precedence over a generic handler when both match.
2. Add separate handlers for validation errors, invalid parameters and other expected API errors as needed.
3. Avoid repeating `try-catch` blocks in every controller when the exception can be handled centrally.
4. For production applications, prefer a consistent error-response DTO over repeated `Map<String, Object>` structures.
5. Never expose stack traces, SQL details, credentials or sensitive internal exception messages in API responses.

```text
          |
          v

          |
          v
Service throws an exception
          |
          v
@RestControllerAdvice catches the exception
          |
          v
@ExceptionHandler processes the exception
          |
          v
ResponseEntity returns HTTP status and JSON
          |
          v

```

## 6. Interview Questions

### Q1. What is a Global Exception Handler?

It centralizes exception handling across controllers, avoiding duplicated error-handling logic and providing consistent API error responses.

### Q2. What is the difference between `@ControllerAdvice` and `@RestControllerAdvice`?

`@RestControllerAdvice` combines `@ControllerAdvice` and `@ResponseBody`. Its handler return values are written directly to the response body, usually as JSON.

`@ControllerAdvice` is more general and can also support view-based applications.

### Q3. What is the purpose of `@ExceptionHandler`?

It identifies the method responsible for handling a particular exception type.

### Q4. Why use `ResponseEntity`?

It allows us to specify the HTTP status code, headers and response body.

### Q5. Can a Global Exception Handler handle custom exceptions?

Yes. Create a custom exception class and register a corresponding `@ExceptionHandler` method.

### Q6. Why should we avoid exposing exception messages in production?

Exception messages may reveal implementation details, database information or other sensitive data. Return a safe, meaningful error message instead.

## 7. Quick Revision

* `@RestControllerAdvice` → Global exception handling.
* `@ExceptionHandler` → Handles a specific exception.
* `ResponseEntity` → Controls the HTTP response.
* Custom exception → Represents an application-specific error.
* `404 Not Found` → Requested resource does not exist.
* `500 Internal Server Error` → Unexpected server-side failure.

**Remember:** Keep exception-handling logic centralized, return meaningful HTTP status codes, and never expose sensitive internal details.
