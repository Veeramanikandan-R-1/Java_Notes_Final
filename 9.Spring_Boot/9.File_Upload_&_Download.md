# Spring Boot – File Upload & Download

## Subtopic: `MultipartFile` Implementation

Since you already know React, think of `MultipartFile` as the Spring Boot side of handling a file selected through an HTML `<input type="file">`.

## 1. Key concepts

- `MultipartFile`: Represents a file uploaded in an HTTP multipart request.
- `multipart/form-data`: The content type used to send files through HTTP.
- `@RequestParam("file")`: Binds the uploaded file to a controller parameter.
- `transferTo()`: Saves an uploaded file to disk.
- `ResponseEntity<Resource>`: Can return a file to the client for downloading.

The standard Spring Boot Web starter already provides the required support; you normally don't need an additional upload dependency.

## 2. Complete working example

This implementation supports:

- Uploading a file
- Downloading a previously uploaded file
- Basic file validation
- Saving files in an `uploads` directory outside your source code

### Step 1: Configure file upload limits

File: `src/main/resources/application.properties`

```
spring.servlet.multipart.max-file-size=10MB
spring.servlet.multipart.max-request-size=10MB
```

This limits an individual file and the overall multipart request to 10 MB.

### Step 2: Create the controller

File: `src/main/java/com/springapp/demo/controller/FileController.java`

```
package com.springapp.demo.controller;

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.Paths;
import java.util.UUID;

import org.springframework.core.io.Resource;
import org.springframework.core.io.UrlResource;
import org.springframework.http.ContentDisposition;
import org.springframework.http.HttpHeaders;
import org.springframework.http.MediaType;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;
import org.springframework.web.multipart.MultipartFile;
import org.springframework.web.server.ResponseStatusException;
import org.springframework.http.HttpStatus;

@RestController
@RequestMapping("/api/files")
public class FileController {

    private final Path uploadDir = Paths.get("uploads")
            .toAbsolutePath().normalize();

    public FileController() throws IOException {
        Files.createDirectories(uploadDir);
    }

    @PostMapping("/upload")
    public ResponseEntity<String> uploadFile(
            @RequestParam("file") MultipartFile file) throws IOException {

        if (file.isEmpty()) {
            throw new ResponseStatusException(
                    HttpStatus.BAD_REQUEST, "File is empty");
        }

        String originalName = file.getOriginalFilename();

        if (originalName == null || originalName.isBlank()) {
            throw new ResponseStatusException(
                    HttpStatus.BAD_REQUEST, "Invalid filename");
        }

        // Prevent user-supplied path components from being stored.
        String safeName = Paths.get(
                originalName.replace('\\', '/'))
                .getFileName().toString();

        String extension = "";
        int dot = safeName.lastIndexOf('.');
        if (dot > 0) {
            extension = safeName.substring(dot);
        }

        // Generate a unique storage name to avoid collisions.
        String storedName = UUID.randomUUID() + extension;
        Path destination = uploadDir.resolve(storedName).normalize();

        if (!destination.startsWith(uploadDir)) {
            throw new ResponseStatusException(
                    HttpStatus.BAD_REQUEST, "Invalid filename");
        }

        file.transferTo(destination);

        return ResponseEntity.ok(
                "File uploaded successfully. Stored name: " + storedName);
    }

    @GetMapping("/download/{filename}")
    public ResponseEntity<Resource> downloadFile(
            @PathVariable String filename) throws IOException {

        // Only accept generated UUID-based storage names.
        if (!filename.matches(
                "[0-9a-fA-F-]{36}(\\.[a-zA-Z0-9]{1,10})?")) {
            throw new ResponseStatusException(
                    HttpStatus.BAD_REQUEST, "Invalid filename");
        }

        Path path = uploadDir.resolve(filename).normalize();

        if (!path.startsWith(uploadDir) || !Files.isRegularFile(path)) {
            throw new ResponseStatusException(
                    HttpStatus.NOT_FOUND, "File not found");
        }

        Resource resource = new UrlResource(path.toUri());

        return ResponseEntity.ok()
                .contentType(MediaType.APPLICATION_OCTET_STREAM)
                .header(HttpHeaders.CONTENT_DISPOSITION,
                        ContentDisposition.attachment()
                                .filename(filename).build().toString())
                .body(resource);
    }
}
```

The controller package must be under `com.springapp.demo` so that your existing `@SpringBootApplication` class discovers it.

How it works:

- `file.isEmpty()` rejects empty uploads.
- `file.transferTo(destination)` saves the file.
- A UUID creates a unique storage name, reducing accidental overwrites.
- `UrlResource` lets Spring return the saved file.
- `Content-Disposition: attachment` tells the browser to download it.

Note: This is a learning example. For production, also validate allowed file types and content, consider malware scanning, and enforce authorization for downloads. A filename extension alone does not prove a file's type.

## 3. Important interview questions

Q1. What is `MultipartFile`?

An interface provided by Spring that represents a file received through a multipart HTTP request.

Q2. Why use `multipart/form-data`?

It allows a request to contain file data and other form fields together.

Q3. What is the difference between `getOriginalFilename()` and `transferTo()`?

- `getOriginalFilename()` retrieves the filename supplied by the client.
- `transferTo()` writes the uploaded file to the specified destination.

Q4. Should we store uploaded files directly in a database?

Usually, store the file in filesystem or object storage and save its metadata and storage reference in the database. Database BLOB storage is also possible when appropriate.

Q5. What validations are important?

- File size
- Allowed file types and actual content
- Empty files
- Safe filenames and storage paths
- Authentication and authorization
- Malware scanning where appropriate
