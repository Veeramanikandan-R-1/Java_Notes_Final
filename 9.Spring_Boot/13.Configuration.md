# Spring Boot – Configuration: Profiles (Dev and Prod Setup)

## 1. What are Spring Profiles?

Spring Profiles allow you to use different configurations for different environments, such as:

- Dev — local development, test database, debug logging.
- Prod — production database, restricted logging, production settings.

For example, React developers may use `.env.development` and `.env.production`. Spring Boot profiles provide a similar way to separate environment-specific configuration.

## 2. Project structure

src/main/resources/

`application.properties`

Common configuration

`application-dev.properties`

Development settings

`application-prod.properties`

Production settings

## 3. Configure each profile

`application.properties` — shared settings

```
spring.application.name=demo
server.port=8080
```

`application-dev.properties` — development settings

```
spring.datasource.url=jdbc:mysql://localhost:3306/dev_db
spring.datasource.username=${DEV_DB_USERNAME:root}
spring.datasource.password=${DEV_DB_PASSWORD}

logging.level.com.springapp.demo=DEBUG
```

`application-prod.properties` — production settings

```
spring.datasource.url=${PROD_DB_URL}
spring.datasource.username=${PROD_DB_USERNAME}
spring.datasource.password=${PROD_DB_PASSWORD}

logging.level.com.springapp.demo=INFO
```

These database properties apply when the project uses Spring Boot's JDBC/JPA database configuration. Configure the appropriate database driver and dependencies as well.

Important: Environment variables keep credentials out of configuration files. Set them in your operating environment or deployment platform; do not commit secrets to Git.

## 4. Activate a profile

You can activate a profile in three ways.

Option 1: Run with a command-line argument

Development:

```
mvn spring-boot:run -Dspring-boot.run.profiles=dev
```

Production:

```
java -jar target/demo-0.0.1-SNAPSHOT.jar --spring.profiles.active=prod
```

Option 2: Use an environment variable

Windows PowerShell:

```
$env:SPRING_PROFILES_ACTIVE="dev"
mvn spring-boot:run
```

For production, set `SPRING_PROFILES_ACTIVE=prod` in your deployment environment.

Option 3: Set it in `application.properties`

```
spring.profiles.active=dev
```

This is convenient for local development, but avoid hardcoding `dev` if the same configuration is packaged for production. Prefer selecting the profile at runtime.

## 5. Use `@Profile` in Java code

Sometimes you need different implementations for different environments, not just different property values.

For example, create this interface:

`service/NotificationService.java`

```
package com.springapp.demo.service;

public interface NotificationService {
    String sendNotification();
}
```

Development implementation:

`service/DevNotificationService.java`

```
package com.springapp.demo.service;

import org.springframework.context.annotation.Profile;
import org.springframework.stereotype.Service;

@Service
@Profile("dev")
public class DevNotificationService
        implements NotificationService {

    @Override
    public String sendNotification() {
        return "Dev notification: simulated";
    }
}
```

Production implementation:

`service/ProdNotificationService.java`

```
package com.springapp.demo.service;

import org.springframework.context.annotation.Profile;
import org.springframework.stereotype.Service;

@Service
@Profile("prod")
public class ProdNotificationService
        implements NotificationService {

    @Override
    public String sendNotification() {
        return "Production notification sent";
    }
}
```

Use the service in a controller:

`controller/NotificationController.java`

```
package com.springapp.demo.controller;

import com.springapp.demo.service.NotificationService;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/api/notifications")
public class NotificationController {

    private final NotificationService notificationService;

    public NotificationController(
            NotificationService notificationService) {
        this.notificationService = notificationService;
    }

    @GetMapping
    public String notifyUser() {
        return notificationService.sendNotification();
    }
}
```

When the `dev` profile is active, Spring registers `DevNotificationService`. When `prod` is active, it registers `ProdNotificationService`.

Test using:

```
GET http://localhost:8080/api/notifications
```

The production implementation above is only a placeholder; replace it with a real notification integration before deploying.

Important: If neither `dev` nor `prod` is active, Spring won't register either implementation, and dependency injection will fail. Choose a profile explicitly or provide a default implementation.

## 6. Key interview points

| Question                                  | Answer                                                                      |
| ----------------------------------------- | --------------------------------------------------------------------------- |
| What is a profile?                        | A mechanism for environment-specific configuration and beans.               |
| What is `application-dev.properties`?     | A configuration file loaded when the `dev` profile is active.               |
| What does `@Profile("prod")` do?          | Registers a bean only when the `prod` profile is active.                    |
| Can multiple profiles be active?          | Yes. For example, `dev,local`.                                              |
| What happens to common properties?        | Properties in `application.properties` remain available unless overridden.  |
| How should production secrets be managed? | Use environment variables or a secrets manager, not committed source files. |

Remember: `application-{profile}.properties` controls environment-specific configuration; `@Profile` controls which Spring beans are created. Use runtime profile activation to ensure the correct environment is selected.
