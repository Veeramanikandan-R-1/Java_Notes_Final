# Spring Boot – Bean Validation (Validation Layer)

## 1. What is Bean Validation?

Bean Validation validates incoming data against predefined rules before your application processes it.

For example, when a user submits a registration form:

* Name must not be blank.

* Email must be valid.

* Age must be at least 18.

In React, you might validate form data before submitting it. In Spring Boot, server-side validation protects your API even when requests bypass the React frontend.

Typical request flow:

React / Postman — HTTP request

Controller — `@Valid`

Bean Validation — check constraints

Valid

Service → Database

Invalid

400 Bad Request

## 2. Add the dependency

If you're using Spring Boot with Maven, add this inside `<dependencies>` in `pom.xml`. Spring Boot manages the compatible version.

XML

```
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>
```

## 3. Common validation annotations

Import these from `jakarta.validation.constraints.*`.

| Annotation               | Purpose                                               |
| ------------------------ | ----------------------------------------------------- |
| `@NotNull`               | Value cannot be `null`                                |
| `@NotBlank`              | String cannot be null, empty, or whitespace-only      |
| `@NotEmpty`              | String or collection cannot be null or empty          |
| `@Size(min=, max=)`      | Restricts string, collection, or supported value size |
| `@Min(18)` / `@Max(100)` | Restricts numeric values                              |
| `@Email`                 | Checks email format                                   |
| `@Positive`              | Number must be greater than zero                      |
| `@Pattern(regexp=...)`   | Validates against a regular expression                |
| `@Past` / `@Future`      | Validates dates or times relative to now              |

Important: `@NotNull` alone does not reject an empty string. Choose the annotation that matches the requirement.

## 4. Complete working example

We'll create a user registration API that validates the request before saving or processing it.

### Project structure

```
src/main/java/com/example/demo/
├── DemoApplication.java
├── UserController.java
├── UserService.java
├── UserRequest.java
└── GlobalExceptionHandler.java
```

### Step 1: Create the DTO with validation rules

`UserRequest.java`

Java

```
package com.example.demo;

import jakarta.validation.constraints.Email;
import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Size;

public class UserRequest {

    @NotBlank(message = "Name is required")
    @Size(min = 3, max = 50,
          message = "Name must contain 3 to 50 characters")
    private String name;

    @NotBlank(message = "Email is required")
    @Email(message = "Enter a valid email address")
    private String email;

    @Min(value = 18, message = "Age must be at least 18")
    private int age;

    public UserRequest() {}

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public String getEmail() {
        return email;
    }

    public void setEmail(String email) {
        this.email = email;
    }

    public int getAge() {
        return age;
    }

    public void setAge(int age) {
        this.age = age;
    }
}
```

Key concept: A DTO (Data Transfer Object) carries request data. Validation annotations define the rules directly on its fields.

### Step 2: Create the service layer

`UserService.java`

Java

```
package com.example.demo;

import org.springframework.stereotype.Service;

@Service
public class UserService {

    public String register(UserRequest request) {
        // Business logic goes here.
        // For example, save the user through a repository.
        return "User registered successfully: " + request.getName();
    }
}
```

### Step 3: Validate the request in the controller

`UserController.java`

Java

```
package com.example.demo;

import jakarta.validation.Valid;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/api/users")
public class UserController {

    private final UserService userService;

    public UserController(UserService userService) {
        this.userService = userService;
    }

    @PostMapping
    public ResponseEntity<String> register(
            @Valid @RequestBody UserRequest request) {

        String result = userService.register(request);
        return ResponseEntity.ok(result);
    }
}
```

The most important part is:

Java

```
@Valid @RequestBody UserRequest request
```

* `@RequestBody` converts incoming JSON into a `UserRequest` object.

* `@Valid` triggers Bean Validation on that object.

* If validation fails, Spring normally throws `MethodArgumentNotValidException` and does not invoke the controller method body.

* If validation succeeds, the service executes.

### Step 4: Return readable validation errors

`GlobalExceptionHandler.java`

Java

```
package com.example.demo;

import java.util.Map;
import java.util.LinkedHashMap;

import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.*;

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<Map<String, String>> handleValidation(
            MethodArgumentNotValidException ex) {

        Map<String, String> errors = new LinkedHashMap<>();

        ex.getBindingResult().getFieldErrors().forEach(error ->
            errors.putIfAbsent(
                error.getField(),
                error.getDefaultMessage()
            )
        );

        return ResponseEntity
                .status(HttpStatus.BAD_REQUEST)
                .body(errors);
    }
}
```

`@RestControllerAdvice` centralizes exception handling across controllers, so you don't have to repeat error-handling logic in every endpoint.

## 6. Where does the validation layer belong?

| Layer                    | Responsibility                                                   |
| ------------------------ | ---------------------------------------------------------------- |
| DTO                      | Validate incoming fields using annotations                       |
| Controller               | Trigger validation using `@Valid`                                |
| Service                  | Validate business rules, such as whether a user is eligible      |
| Repository               | Persist data; database constraints provide additional protection |
| Global exception handler | Convert validation failures into consistent API responses        |

Important distinction: Bean Validation checks constraints on data. Business rules may require service-layer checks, database queries, or custom validators.

### Bonus: `@Valid` vs `@Validated`

* `@Valid` — commonly used to validate request DTOs and nested objects.

* `@Validated` — Spring-specific annotation that also supports validation groups and method-level validation when configured appropriately.

For nested DTOs, use `@Valid` on the nested field as well. For service method parameter or return-value validation, use `@Validated` on the Spring bean.

## 7. Interview-ready summary

* What is Bean Validation? A standard Java mechanism for enforcing constraints on object data.

* Why use `@Valid`? It triggers validation before the controller processes the request.

* What happens when validation fails? Spring typically returns `400 Bad Request` for invalid `@RequestBody` data; a global handler can customize the response.

* Why validate on the backend if React already validates? Backend validation cannot be bypassed simply by skipping the frontend.

* What dependency is required? `spring-boot-starter-validation`.

Remember the core flow: `DTO annotations → @Valid → validation errors → exception handler → HTTP 400`.
