# Spring Boot – Scheduling

## 1. What is scheduling?

Scheduling allows Spring Boot to execute a method automatically at a specific time or repeatedly at fixed intervals, without an API request.

Common use cases:

- Send daily reminder emails.
- Generate daily reports.
- Clean up expired records.
- Run periodic data synchronization.

Spring provides `@Scheduled` for this purpose.

## 2. Enable scheduling

Add `@EnableScheduling` to your main application class.

`DemoApplication.java`

```
package com.springapp.demo;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.scheduling.annotation.EnableScheduling;

@SpringBootApplication
@EnableScheduling
public class DemoApplication {

    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
```

`@EnableScheduling` tells Spring to detect and execute scheduled methods.

## 3. Complete scheduler demo

Create `ScheduledTasks.java` under `com.springapp.demo.service`.

```
package com.springapp.demo.service;

import java.time.LocalDateTime;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.scheduling.annotation.Scheduled;
import org.springframework.stereotype.Component;

@Component
public class ScheduledTasks {

    private static final Logger logger =
            LoggerFactory.getLogger(ScheduledTasks.class);

    // Executes every 5 seconds
    @Scheduled(fixedRate = 5000)
    public void reportStatus() {
        logger.info("Fixed rate task: {}", LocalDateTime.now());
    }

    // Executes 5 seconds after the previous execution finishes
    @Scheduled(fixedDelay = 5000)
    public void syncData() {
        logger.info("Fixed delay task: {}", LocalDateTime.now());
    }

    // Executes every day at 9:00 AM
    @Scheduled(
        cron = "0 0 9 * * *",
        zone = "Asia/Kolkata"
    )
    public void dailyReport() {
        logger.info("Generating daily report");
    }
}
```

No additional scheduling dependency is normally required when using Spring Boot's standard starters.

## 4. Understand the scheduling options

| Option                 | Meaning                                                                  |
| ---------------------- | ------------------------------------------------------------------------ |
| `fixedRate = 5000`     | Starts executions every 5 seconds, measured from the previous start time |
| `fixedDelay = 5000`    | Waits 5 seconds after the previous execution finishes                    |
| `initialDelay = 10000` | Waits 10 seconds before the first execution                              |
| `cron = "..."`         | Runs according to a calendar-based schedule                              |

Example combining initial delay and fixed delay:

```
@Scheduled(initialDelay = 10000, fixedDelay = 5000)
public void processJob() {
    logger.info("Processing job");
}
```

This waits 10 seconds after scheduling begins, executes the method, and then waits 5 seconds after each completion before running it again.

Important: By default, Spring's scheduler uses a single scheduling thread in the standard configuration. A long-running task can delay other scheduled tasks. Configure a scheduler thread pool if your application needs concurrent scheduled jobs.

## 5. Cron expressions

Spring cron expressions use six fields, unlike the common five-field Unix cron format.

Cron field order

Second

0–59

Minute

0–59

Hour

0–23

Day of month

1–31

Month

1–12

Day of week

0–7

The day-of-week field supports 0 or 7 for Sunday.

| Cron expression       | Meaning                                  |
| --------------------- | ---------------------------------------- |
| `0 * * * * *`         | Every minute, at second 0                |
| `0 */5 * * * *`       | Every 5 minutes                          |
| `0 0 9 * * *`         | Every day at 9:00 AM                     |
| `0 30 18 * * MON-FRI` | Weekdays at 6:30 PM                      |
| `0 0 0 1 * *`         | Midnight on the first day of every month |

Use `zone = "Asia/Kolkata"` when the schedule must follow Indian Standard Time, regardless of the server's configured time zone.

## 6. Common mistakes

- Forgetting `@EnableScheduling`.
- Forgetting `@Component` or another Spring bean annotation on the scheduled class.
- Using a five-field cron expression instead of Spring's six-field format.
- Expecting scheduled methods to execute immediately at startup.
- Assuming `@Scheduled` automatically distributes jobs across multiple application instances.

For multi-instance deployments, each application instance may run the same scheduled job. Use a distributed locking mechanism or an external scheduler when a job must execute only once across instances.

## 7. Interview quick revision

Q: `fixedRate` vs `fixedDelay`?

`fixedRate` measures time between execution starts; `fixedDelay` measures time from completion to the next start.

Q: Can `@Scheduled` methods accept parameters?

Usually, no. Scheduled methods must have no arguments.

Q: Does `@Scheduled` need an API call?

No. Spring triggers it automatically while the application is running.

Q: Does scheduling survive an application restart?

The schedule is registered again when the application starts. Jobs missed while the application is stopped are not automatically replayed.

Remember: `@EnableScheduling` enables scheduling, `@Scheduled` defines when a method runs, and cron expressions define calendar-based execution times.
