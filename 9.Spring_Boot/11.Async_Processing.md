# Spring Boot – Async Processing

## Subtopic: `@Async`, `TaskExecutor` Implementation

## 1. What is asynchronous processing?

Asynchronous processing allows a method to execute on a separate thread so the calling thread does not need to wait for that method to finish.

For example, when a user registers, your Spring Boot API can save the user and trigger an email task asynchronously.

Think of it from a React perspective: instead of making the caller wait for a long-running operation to finish, the application can schedule that work separately.

Key concepts

- `@EnableAsync` — enables Spring's asynchronous method execution.
- `@Async` — runs a method asynchronously through a Spring-managed executor.
- `TaskExecutor` — manages the threads that execute asynchronous tasks.
- `CompletableFuture` — lets you return a result from an asynchronous operation.

## 2. Complete working example

### Step 1: Enable asynchronous processing

Update `DemoApplication.java`.

```
package com.springapp.demo;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.scheduling.annotation.EnableAsync;

@SpringBootApplication
@EnableAsync
public class DemoApplication {

    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
```

Without `@EnableAsync`, Spring does not apply its normal `@Async` processing.

### Step 2: Configure a `TaskExecutor`

Create `AsyncConfig.java` under `com.springapp.demo.config`.

```
package com.springapp.demo.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.scheduling.concurrent.ThreadPoolTaskExecutor;

import java.util.concurrent.Executor;

@Configuration
public class AsyncConfig {

    @Bean(name = "taskExecutor")
    public Executor taskExecutor() {
        ThreadPoolTaskExecutor executor =
                new ThreadPoolTaskExecutor();

        executor.setCorePoolSize(2);
        executor.setMaxPoolSize(5);
        executor.setQueueCapacity(100);
        executor.setThreadNamePrefix("async-");

        executor.initialize();
        return executor;
    }
}
```

What these settings mean:

| Setting               | Meaning                                                      |
| --------------------- | ------------------------------------------------------------ |
| `corePoolSize = 2`    | Maintains 2 core worker threads                              |
| `maxPoolSize = 5`     | Allows up to 5 worker threads under load                     |
| `queueCapacity = 100` | Queues up to 100 tasks before expanding beyond the core pool |
| `threadNamePrefix`    | Makes async threads easy to identify in logs                 |

If the queue and thread pool are both full, task submission may be rejected. Choose limits based on your workload.

### Step 3: Create an asynchronous service

Create `AsyncService.java` under `com.springapp.demo.service`.

```
package com.springapp.demo.service;

import java.util.concurrent.CompletableFuture;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.scheduling.annotation.Async;
import org.springframework.stereotype.Service;

@Service
public class AsyncService {

    private static final Logger logger =
            LoggerFactory.getLogger(AsyncService.class);

    @Async("taskExecutor")
    public CompletableFuture<String> processTask() {

        logger.info("Task started on thread: {}",
                Thread.currentThread().getName());

        try {
            Thread.sleep(3000); // Simulate a slow operation
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();

            return CompletableFuture.failedFuture(e);
        }

        logger.info("Task completed");

        return CompletableFuture.completedFuture(
                "Async task completed successfully");
    }
}
```

Important: `@Async("taskExecutor")` tells Spring to execute this method using the executor bean created in Step 2.

`CompletableFuture` represents a result that becomes available later.

### Step 4: Create a REST controller

Create `AsyncController.java` under `com.springapp.demo.controller`.

```
package com.springapp.demo.controller;

import java.util.concurrent.CompletableFuture;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

import com.springapp.demo.service.AsyncService;

@RestController
public class AsyncController {

    private final AsyncService asyncService;

    public AsyncController(AsyncService asyncService) {
        this.asyncService = asyncService;
    }

    @GetMapping("/async")
    public CompletableFuture<String> runAsyncTask() {
        return asyncService.processTask();
    }
}
```

This uses constructor injection, which is the recommended approach for required dependencies.

### Step 5: Run and test

Start the application and call:

`GET http://localhost:8080/async`

The service takes approximately 3 seconds to complete. Spring MVC can handle the returned `CompletableFuture` asynchronously, so the servlet request thread does not need to remain blocked for the whole operation.

Your logs should show a thread name similar to:

```
INFO ... async-1 ... Task started on thread: async-1
INFO ... async-1 ... Task completed
```

The exact thread number may vary.

## 3. Important concepts you must know

### A. Why use `TaskExecutor` instead of creating threads manually?

Spring manages the thread pool, allowing you to configure concurrency, queue capacity, and thread names centrally.

Avoid creating a new `Thread` for every request in a production application.

### B. Important `@Async` limitation: self-invocation

Spring normally implements `@Async` through a proxy. Therefore, calling an `@Async` method from another method within the same class bypasses the proxy, and the call may execute synchronously.

Use a separate Spring-managed service, as shown in this example.

### C. How are exceptions handled?

For methods returning `CompletableFuture`, exceptions can be represented by a failed future and handled by the caller. For `void` methods, exceptions cannot be returned to the caller; configure an `AsyncUncaughtExceptionHandler` when needed.

### D. When should you use `@Async`?

- Sending notification emails.
- Processing independent background tasks.
- Calling multiple independent external services.
- Performing work that does not need to finish before returning an API response.

Do not use it as a substitute for durable job processing. Tasks running only in memory can be lost if the application shuts down unexpectedly.

## 4. Interview quick revision

| Question                                  | Short answer                                                                                    |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------- |
| What does `@Async` do?                    | Executes a method asynchronously through a Spring-managed executor.                             |
| Why `@EnableAsync`?                       | Enables Spring's async method processing.                                                       |
| What is `TaskExecutor`?                   | An abstraction for executing tasks, commonly using a thread pool.                               |
| Why `CompletableFuture`?                  | Represents a result available in the future and supports asynchronous composition.              |
| Does `@Async` always create a new thread? | No. It normally uses a thread from the configured executor.                                     |
| Is `@Async` suitable for every slow task? | No. Consider timeouts, resource limits, failure handling, and durable queues for critical work. |

Remember: `@EnableAsync` enables the feature, `@Async` marks the method, `TaskExecutor` manages worker threads, and `CompletableFuture` carries the asynchronous result.
