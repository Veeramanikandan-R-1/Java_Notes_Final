Since you already have **5 years of React experience**, think of a Spring Boot project structure as similar to how you organize a React application: each folder has a specific responsibility.

# Spring Boot — Project Structure

A typical Maven Spring Boot project looks like this:

```text
my-spring-app/
│
├── pom.xml
│
└── src/
    ├── main/
    │   ├── java/
    │   │   └── com/example/demo/
    │   │       └── DemoApplication.java
    │   │
    │   └── resources/
    │       ├── application.properties
    │       ├── application.yml
    │       ├── static/
    │       └── templates/
    │
    └── test/
        └── java/
            └── com/example/demo/
                └── DemoApplicationTests.java
```

## 1. `src/main`

This contains the **actual application code**.

```text
src/main/
├── java/
└── resources/
```

Think:

```text
src/main = production application
```

Whereas:

```text
src/test = test code
```

---

# 2. `src/main/java`

This contains your **Java source code**.

Example:

```text
src/main/java/com/example/demo/
│
├── DemoApplication.java
├── controller/
│   └── UserController.java
├── service/
│   └── UserService.java
├── repository/
│   └── UserRepository.java
└── model/
    └── User.java
```

A common layered structure is:

```text
Controller
    ↓
Service
    ↓
Repository
    ↓
Database
```

### Controller

Handles HTTP requests.

```java
@RestController
@RequestMapping("/users")
public class UserController {

    @GetMapping
    public String getUsers() {
        return "Users";
    }
}
```

### Service

Contains business logic.

```java
@Service
public class UserService {

    public String getUsers() {
        return "Users";
    }
}
```

### Repository

Handles database access.

```java
@Repository
public interface UserRepository extends JpaRepository<User, Long> {
}
```

This separation is one of the most important concepts in a real Spring Boot application.

---

# 3. Main Application Class

Example:

```java
package com.example.demo;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class DemoApplication {

    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
```

`@SpringBootApplication` is essentially a combination of:

```java
@Configuration
@EnableAutoConfiguration
@ComponentScan
```

The `main()` method starts the Spring Boot application.

---

# 4. `src/main/resources`

This contains **non-Java application resources/configuration**.

```text
src/main/resources/
│
├── application.properties
├── application.yml
├── static/
└── templates/
```

Most importantly:

```text
application.properties
application.yml
```

are used for application configuration.

Examples:

* Server port
* Database configuration
* Logging
* Spring configuration
* Custom application properties

---

# 5. `application.properties`

Configuration is written as:

```properties
server.port=8081

spring.application.name=my-spring-app

spring.datasource.url=jdbc:mysql://localhost:3306/mydb
spring.datasource.username=root
spring.datasource.password=password
```

For example:

```properties
server.port=8081
```

means your application runs at:

```text
http://localhost:8081
```

Instead of the default:

```text
http://localhost:8080
```

### Important

You don't normally need both:

```text
application.properties
application.yml
```

Use **one configuration style**.

---

# 6. `application.yml`

The same configuration can be written using YAML.

```yaml
server:
  port: 8081

spring:
  application:
    name: my-spring-app

  datasource:
    url: jdbc:mysql://localhost:3306/mydb
    username: root
    password: password
```

### Properties vs YAML

### `application.properties`

```properties
server.port=8081
spring.application.name=my-app
```

### `application.yml`

```yaml
server:
  port: 8081

spring:
  application:
    name: my-app
```

YAML is often easier to read when configuration becomes large/nested.

---

# 7. `static/`

Used for static web resources:

```text
resources/
└── static/
    ├── css/
    ├── js/
    └── images/
```

For example:

```text
static/logo.png
```

Spring Boot can serve static resources.

For a typical **React + Spring Boot** application, however, React will usually be a separate frontend project, so you won't commonly put your React source code here.

---

# 8. `templates/`

Used for server-side HTML template engines such as:

* Thymeleaf
* FreeMarker

Example:

```text
resources/
└── templates/
    └── home.html
```

If you're building:

```text
React → Spring Boot REST API → Database
```

you generally won't need `templates/`.

---

# 9. `src/test`

Contains automated tests.

```text
src/test/java/
└── com/example/demo/
    └── DemoApplicationTests.java
```

Example:

```java
@SpringBootTest
class DemoApplicationTests {

    @Test
    void contextLoads() {
    }
}
```

---

# 10. Recommended structure for your React → Spring Boot transition

Since your goal is **React + Spring Boot full-stack**, a realistic project structure would be:

```text
backend/
│
├── pom.xml
│
└── src/
    ├── main/
    │   ├── java/com/example/app/
    │   │   │
    │   │   ├── AppApplication.java
    │   │   │
    │   │   ├── controller/
    │   │   │   └── UserController.java
    │   │   │
    │   │   ├── service/
    │   │   │   └── UserService.java
    │   │   │
    │   │   ├── repository/
    │   │   │   └── UserRepository.java
    │   │   │
    │   │   ├── entity/
    │   │   │   └── User.java
    │   │   │
    │   │   ├── dto/
    │   │   │   └── UserDTO.java
    │   │   │
    │   │   └── exception/
    │   │       └── GlobalExceptionHandler.java
    │   │
    │   └── resources/
    │       ├── application.properties
    │       └── static/
    │
    └── test/
        └── java/
```

The request flow becomes:

```text
React
  │
  │ HTTP request
  ▼
Controller
  │
  ▼
Service
  │
  ▼
Repository
  │
  ▼
Database
```

### Remember this

| Folder/File              | Purpose                                |
| ------------------------ | -------------------------------------- |
| `src/main/java`          | Java application code                  |
| `src/main/resources`     | Configuration/resources                |
| `application.properties` | Application configuration              |
| `application.yml`        | YAML-based configuration               |
| `static/`                | Static files                           |
| `templates/`             | Server-side HTML templates             |
| `src/test`               | Test code                              |
| `pom.xml`                | Maven dependencies/build configuration |

**Most important for you:** don't treat `resources` as where your Java code goes. Your Java classes belong under `src/main/java`; configuration such as database settings and server port belongs under `src/main/resources`.

Next, the most useful topic after this is **Spring Boot `application.properties` in depth — profiles (`dev`, `test`, `prod`), environment variables, and database configuration**, because you'll use these constantly in real projects.
