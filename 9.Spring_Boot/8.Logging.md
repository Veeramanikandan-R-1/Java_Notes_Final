# Spring Boot – Logging Setup: SLF4J & Logback

## 1. What are SLF4J and Logback?

Logging helps you track application execution, debug errors, and monitor production applications.

| Concept                  | Purpose                                           |
| ------------------------ | ------------------------------------------------- |
| SLF4J                    | Logging API (the interface your code uses)        |
| Logback                  | Logging implementation (actually writes the logs) |
| Logger                   | Object used to write log messages                 |
| `application.properties` | Configure logging levels and output               |

Think of it like React: SLF4J is the contract; Logback is the implementation.

Spring Boot uses SLF4J with Logback by default when you use the standard Spring Boot starter.

## 2. Logging levels

From lowest to highest severity:

| Level   | Usage                               |
| ------- | ----------------------------------- |
| `TRACE` | Very detailed execution information |
| `DEBUG` | Debugging during development        |
| `INFO`  | Important application events        |
| `WARN`  | Potential problems                  |
| `ERROR` | Failures and exceptions             |

If the level is `INFO`, `INFO`, `WARN`, and `ERROR` messages appear, but `DEBUG` and `TRACE` do not.

## 3. Complete working example

Assume you already have a Spring Boot project with `spring-boot-starter-web`.

### Step 1: Create a controller

File: `src/main/java/com/springapp/demo/controller/LoggingController.java`

```java
package com.springapp.demo.controller;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class LoggingController {

    private static final Logger logger =
            LoggerFactory.getLogger(LoggingController.class);

    @GetMapping("/logs")
    public String getLogs() {

        logger.trace("Trace log");
        logger.debug("Debug log");
        logger.info("Logs endpoint called");
        logger.warn("This is a warning");
        logger.error("This is an error");

        return "Check application logs";
    }
}
```

Important concepts:

- `LoggerFactory.getLogger(...)` creates a logger for the class.
- `logger.info(...)` records an informational message.
- Logging does not replace exception handling; it helps you understand what happened.
- Use parameterized logging for dynamic values:

```
String username = "Karthik";

logger.info("User {} logged in", username);
```

This is preferable to string concatenation such as `"User " + username + " logged in"`.

### Step 2: Configure logging

File: `src/main/resources/application.properties`

```
# Set the root logging level
logging.level.root=INFO

# Enable DEBUG logs for your application
logging.level.com.springapp.demo=DEBUG

# Write logs to a file
logging.file.name=logs/application.log
```

What these settings do:

- `logging.level.root=INFO`: hides `DEBUG` and `TRACE` logs by default.
- `logging.level.com.springapp.demo=DEBUG`: enables `DEBUG` logs for your application's package.
- `logging.file.name=logs/application.log`: writes logs to this file, relative to the application's working directory.

### Step 3: Run and test

Start the application and open:

`http://localhost:8080/logs`

You should see messages similar to:

```
DEBUG ... LoggingController : Debug log
INFO  ... LoggingController : Logs endpoint called
WARN  ... LoggingController : This is a warning
ERROR ... LoggingController : This is an error
```

The same logs will also be written to `logs/application.log`. The exact output format may vary.

## 4. Configure Logback using XML

For more advanced control, create:

`src/main/resources/logback-spring.xml`

```
<?xml version="1.0" encoding="UTF-8"?>
<configuration>

    <property name="LOG_DIR" value="logs"/>

    <appender name="CONSOLE"
              class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>
                %d{yyyy-MM-dd HH:mm:ss} %-5level [%thread] %logger{36} - %msg%n
            </pattern>
        </encoder>
    </appender>

    <appender name="FILE"
              class="ch.qos.logback.core.FileAppender">
        <file>${LOG_DIR}/application.log</file>
        <append>true</append>
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss} %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>

    <logger name="com.springapp.demo" level="DEBUG"/>

    <root level="INFO">
        <appender-ref ref="CONSOLE"/>
        <appender-ref ref="FILE"/>
    </root>

</configuration>
```

This configuration writes logs to both the console and a file. Ensure the `logs` directory exists or that your Logback configuration can create it.

Important: When using XML configuration, avoid duplicating conflicting settings in `application.properties`. For production, consider a rolling file appender to prevent log files from growing indefinitely. Spring Boot's `logging.file.name` setting is simpler when you only need basic file logging.

## 5. Best practices for real projects

- Use `INFO` for important business events and `DEBUG` for diagnostic details.
- Log exceptions with their stack traces when appropriate:

```
try {
    // Perform an operation
} catch (Exception e) {
    logger.error("Failed to process request", e);
    throw e;
}
```

- Never log passwords, access tokens, or sensitive personal data.
- Avoid logging the same exception repeatedly at every application layer.
- Prefer configuration over changing log levels in source code.

## 6. Interview quick revision

Q1. What is the difference between SLF4J and Logback?

SLF4J provides the logging API, while Logback implements that API and outputs log messages.

Q2. Does Spring Boot require a separate logging dependency?

Usually not. The standard Spring Boot starter includes the default logging setup through `spring-boot-starter-logging`.

Q3. What is the difference between `logger.error("Failed", e)` and `logger.error("Failed")`?

The first includes the exception and its stack trace; the second logs only the message.

Q4. What is the difference between `application.properties` and `logback-spring.xml`?

Properties are convenient for common settings such as log levels and file names. XML provides detailed control over appenders, formats, and logging destinations.

Remember: Use SLF4J in your Java classes and let Logback handle the output. Start with `application.properties`; use `logback-spring.xml` when you need advanced logging configuration.
